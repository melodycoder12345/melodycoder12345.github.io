全文检索

全文检索的核心是倒排索引：将文档分词后，建立 term → posting list 的映射。写入时词项按字典序排列，posting list 追加新 doc_id。查询 "distributed AND system" 时，两条 posting list 用双指针归并取交集，BM25 对结果排名打分。核心是"不扫表，做集合运算"。

倒排索引构建

  • 分词（Tokenizer）：将文档文本拆分为 token，中文用分词器（jieba/HanLP），英文按空格+标点
  • 规范化：小写转换、去停用词（the/is/的/了）、词干提取（running→run）
  • 排序：词项在字典中按字典序排列，支持前缀搜索和范围查询
  • Posting List 追加：新文档入库时，将 doc_id 追加到对应词项的 posting list 末尾
  • 段合并（Segment Merge）：多个小段定期合并为大段，减少检索时需要扫描的段数

多词查询处理

  • AND 查询：双指针归并多个 posting list 取交集，总时间 O(∑n_i)，从最短列表开始
  • OR 查询：归并合并（merge）多个 posting list，去重后排序
  • 短语查询："distributed system" 需要位置信息，doc_id 相同且位置相邻
  • 跳表加速：Posting List 建立稀疏跳表，AND 查询时可以跳过大段不相交的区域
  • NOT 查询：先 AND 再过滤，不能单独做 NOT（否则需要全部文档集合）

相关性打分（BM25）

  • BM25 = Σ IDF(t) × (TF × (k1+1)) / (TF + k1 × (1 - b + b × dl/avgdl))
  • TF（词频）：词在文档中出现次数，越多越相关（有饱和上限 k1）
  • IDF（逆文档频率）：log((N - df + 0.5) / (df + 0.5))，越罕见的词区分度越高
  • 文档长度归一化（b）：短文档中出现同等词频，相关性应更高
  • k1=1.2, b=0.75：ES 默认参数，可调整到领域特点

Elasticsearch 架构

  • 基于 Lucene：Lucene 提供 segment、倒排索引、BM25 等核心；ES 提供分布式、API、DSL
  • 分片（Primary Shard）：每个索引分为 N 个主分片，数据哈希路由到对应分片
  • 副本（Replica）：每个主分片有 M 个副本，读请求可分散到副本
  • 近实时（NRT）：写入后约 1s 可检索（segment refresh 间隔）
  • 向量检索：ES 8.x 支持 kNN 向量搜索（HNSW 索引），用于 AI 语义检索
