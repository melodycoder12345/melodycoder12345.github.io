向量索引

向量索引用近似最近邻搜索替代全量距离计算，是语义检索和 RAG 的基础。

EmbeddingANNRAG
掌握 HNSW 图结构 + IVF/PQ 量化方案足以覆盖绝大多数向量检索面试问题。
核心术语
ANNApproximate Nearest Neighbor，用近似算法在亚线性时间内找到足够近的结果。
HNSWHierarchical Navigable Small World，多层图索引，高召回低延迟。
IVF / PQ倒排聚类缩小搜索范围 + 积量化压缩存储，适合十亿级向量。

背景

朴素高维向量精确 KNN（K-Nearest Neighbors）需要计算约 O(n·d) 的距离；其延迟取决于硬件、批处理、数据布局和过滤条件，规模增大时通常难以满足低延迟在线检索需求。

近似最近邻（ANN）是解决此问题的标准方案，核心权衡：召回率 vs 延迟 vs 内存。

  • 维度灾难：高维空间中数据点间距离趋于均匀，精确 KNN 退化为全扫描
  • ANN 思路：牺牲少量召回率（如 95% → 99%）换取 10-1000x 加速
  • 主流方案：基于图（HNSW）、基于聚类（IVF）、基于量化（PQ/SQ）、基于哈希（LSH）
  • 距离度量选择：L2（欧氏）、Cosine（余弦）、IP（内积，带 norm 模型用）
  • 应用场景：RAG 语义检索、相似商品推荐、图像去重、用户行为聚类

运行机制

  • HNSW：多层跳表式图。顶层稀疏（长距离跳转定位区域），底层稠密（精确搜索）。插入时随机分配层数（指数分布），每层贪心搜索最近邻后双向连边。查询从顶层向下 greedy search + 候选队列
  • HNSW 参数：M（每层最大连接数，影响召回和内存）、efConstruction（建图搜索宽度）、efSearch（查询搜索宽度，越大越慢但召回越高）
  • IVF (Inverted File Index)：K-Means 将向量分成 nlist 个聚类。查询时只搜最近 nprobe 个桶内的向量。nprobe 越大召回越高但越慢
  • PQ (Product Quantization)：d 维向量切分为 m 个子空间，每个子空间用 256 中心编码（1 byte）。原始向量压缩为 m bytes，距离用查表（ADC）替代浮点运算
  • IVF-PQ 组合：IVF 缩小搜索范围 + PQ 压缩内存。十亿级向量可单机检索（如 Faiss）
  • 构建 vs 查询权衡：HNSW 构建慢、内存大但查询快；IVF-PQ 构建快、内存小但精度略低
  • Scalar Quantization (SQ)：将 float32 量化为 int8/uint8，内存降 4x，精度损失 <1%。适合对内存敏感但不想损失太多精度的场景
  • DiskANN：将图索引存储在 SSD 上，用 PQ 在内存中做粗搜，SSD 做精确 rerank。十亿级向量单机可行

代码示例

Go 伪代码：HNSW 搜索 + 插入核心逻辑：

type HNSWNode struct {
    ID      int
    Vector  []float32
    Friends [][]int // friends[layer] = neighbor IDs at that layer
}

type HNSW struct {
    Nodes    []*HNSWNode
    MaxLayer int
    EntryID  int  // top layer entry point
    M        int  // max connections per layer
    EfSearch int  // search beam width
}

// Search: 从顶层贪心下降，底层 beam search 扩展候选集
func (h *HNSW) Search(query []float32, topK int) []int {
    curr := h.EntryID
    // Phase 1: greedy descent from top layer to layer 1
    for layer := h.MaxLayer; layer > 0; layer-- {
        curr = h.greedyClosest(query, curr, layer)
    }
    // Phase 2: beam search at layer 0
    candidates := h.beamSearch(query, curr, 0, h.EfSearch)
    // Return top-K by distance
    sort.Slice(candidates, func(i, j int) bool {
        return dist(query, h.Nodes[candidates[i]].Vector) <
               dist(query, h.Nodes[candidates[j]].Vector)
    })
    if len(candidates) > topK {
        candidates = candidates[:topK]
    }
    return candidates
}

// Insert: 随机层数 + 逐层连边
func (h *HNSW) Insert(node *HNSWNode) {
    // 层数服从指数分布: -ln(rand) * mL
    nodeLayer := int(-math.Log(rand.Float64()) * (1.0 / math.Log(float64(h.M))))
    if nodeLayer > h.MaxLayer {
        h.MaxLayer = nodeLayer
        h.EntryID = node.ID
    }
    for layer := min(nodeLayer, h.MaxLayer); layer >= 0; layer-- {
        neighbors := h.beamSearch(node.Vector, h.EntryID, layer, h.EfSearch)
        selected := selectNeighbors(neighbors, h.M) // heuristic pruning
        node.Friends[layer] = selected
        for _, nid := range selected {
            h.Nodes[nid].Friends[layer] = append(
                h.Nodes[nid].Friends[layer], node.ID)
            // Prune if exceeds maxM
            if len(h.Nodes[nid].Friends[layer]) > h.M*2 {
                h.Nodes[nid].Friends[layer] = pruneNeighbors(
                    h.Nodes[nid], layer, h.M*2)
            }
        }
    }
}

metric_type = "COSINE"  # 文本embedding（已归一化）

面试问答

HNSW 为什么比单层图搜索更快？▶
单层图搜索需要大量跳步从随机位置走到目标区域（平均路径长度 O(n^(1/d))）。HNSW 的多层结构类似跳表：顶层节点稀疏、连接距离远，能在 O(log(n)) 步内定位到目标区域；底层节点密集、连接距离近，做精细搜索。总复杂度约 O(log(n) * ef)，远优于单层的搜索路径。类比：顶层是"高速公路"，底层是"街区小路"。
IVF 的 nprobe 参数如何选择？▶
nprobe 决定搜索几个聚类桶。nprobe=1 时速度最快但召回率低（约 40-60%），nprobe=nlist 等于全扫描。经验法则：nprobe = sqrt(nlist) 通常能达到 90%+ 召回。实际应选定一组测试查询，绘制 recall-latency 曲线，找到业务可接受延迟下的最高召回点。典型配置：百万级数据 nlist=1024, nprobe=32-64；十亿级数据 nlist=65536, nprobe=128-256。
向量索引需要重建吗？什么时候触发？▶
IVF 的聚类中心基于训练数据分布，分布漂移可能降低召回率；HNSW 的删除和重建能力取决于具体实现。是否重训或重建应由离线真值集上的 recall@k、延迟、内存和删除比例等指标触发，不存在通用的 30%-50% 阈值。
Cosine 距离和 L2 距离有什么区别？怎么选？▶
L2 (欧氏距离) 对向量模长敏感，适合模长有意义的场景（如图像特征、物理坐标）。Cosine 只看方向不看模长，适合文本 embedding（句子长短不同但语义相近）。数学关系：若向量已 L2 normalize，则 cos_dist = 1 - dot_product, 且 L2^2 = 2 - 2*dot_product，两者排序完全等价。选择依据：使用模型训练时采用的度量。OpenAI/Cohere 等文本模型输出已归一化，用 cosine 或 IP 均可。

常见陷阱

误解：向量距离近 = 业务相关
// 只用向量相似度做最终结果
results := index.Search(queryVec, topK=10)
return results // 直接返回给用户

// 问题场景：
// "苹果手机" 和 "苹果水果" 向量可能相近
// 用户搜手机却返回了水果
// 过期内容、无权限内容也可能被召回
// 重复内容占满 top-K 位置

问题：embedding 空间的距离不等于业务相关性，缺少过滤和重排会产出无效结果。

// 正确：向量召回 + 过滤 + 重排
// Step 1: 大召回（向量检索）
candidates := index.Search(query, topK=100)

// Step 2: metadata 过滤
filtered := filter(candidates, func(doc) bool {
    return doc.Category == userIntent &&
           doc.ExpireAt.After(now) &&
           doc.HasPermission(userID)
})

// Step 3: 精排（cross-encoder rerank）
ranked := reranker.Score(queryText, filtered)

// Step 4: 业务规则
return diversify(ranked[:10]) // 去重+多样性

正确：向量检索是召回阶段，必须配合过滤、精排和业务规则才能产出有效结果。

误解：维度越高效果越好
// 选了最高维度模型 (3072-dim)
// 成本计算：
// 100M vectors * 3072 * 4B = 1.2TB 内存
// HNSW 索引额外 0.5TB
// 构建时间：7 天
// 查询延迟：80ms

// 对比 768-dim：
// 100M * 768 * 4B = 307GB
// 查询延迟：15ms
// 召回率差异 < 2%

问题：高维向量带来巨大内存和计算成本，但边际收益递减（维度灾难使距离区分度下降）。

// 正确的维度选择方法
// 1. 在业务测试集上对比不同维度模型的 recall@K
// 2. 使用 PQ/SQ 量化降低存储：
//    768-dim * PQ(m=96) = 96 bytes/vector
//    100M * 96B = 9.6GB (vs 307GB raw)

// 3. Matryoshka embedding 支持截断：
//    模型输出 1536-dim
//    截断到 256-dim 仍保持 ~95% recall

// 4. 决策优先级：
//    模型质量 > 检索策略 > 维度 > 索引参数

// 5. 最终验证：end-to-end evaluation
//    包括 rerank 后的最终 precision/recall

正确：维度应根据 recall/cost tradeoff 评估，配合量化方案可大幅降低存储而不显著损失效果。
