Linux 网络协议栈

Linux 网络栈从用户态 socket 到网卡 DMA 经过多个内核子系统。理解数据包的完整收发路径，是分析高性能网络、调优 TCP 参数和排查网络问题的基础。

核心术语
  • sk_buff内核中表示网络数据包的核心数据结构，贯穿从网卡到应用层的完整路径，通过指针调整减少数据复制
  • Netfilter/iptables内核网络钩子框架，可在包处理的各节点插入过滤/NAT/连接跟踪规则
  • NAPI（New API）现代网卡驱动的中断+轮询混合模型，高流量时切换到轮询模式，减少中断开销

零拷贝优化

  • sendfile()：数据从文件直接到 socket buffer，绕过用户空间，减少 2 次 CPU 复制（nginx 静态文件默认使用）
  • mmap + write：mmap 将文件映射到用户空间，write 时 page cache 直接传给网卡
  • splice()：内核内管道拼接，零复制传输，适合代理场景
  • sk_buff 通过 headroom/tailroom 指针避免数据移动，协议层只修改指针偏移

TCP 内核参数调优

  • tcp_rmem/tcp_wmem：receive/send buffer 动态范围，影响吞吐上限
  • tcp_congestion_control：bbr 适合弱网；cubic 适合数据中心
  • net.core.somaxconn：listen backlog 上限，影响突发连接接受能力
  • tcp_fastopen：TFO 在 SYN 包携带数据，减少 1 RTT 建连延迟

DPDK / XDP Bypass 内核

高性能场景下，内核网络栈本身成为瓶颈（中断处理、内存拷贝、锁竞争）：

  • DPDK：用户态轮询驱动，绕过内核网络栈，延迟 <1µs，适合 NFV/5G
  • eBPF XDP：在网卡驱动层（最早 hook 点）运行 eBPF 程序，丢包/转发决定在 DMA 后立即做，不进入内核栈
  • io_uring：异步 I/O 接口，减少系统调用次数，适合高并发 socket

工程场景与排查

  • 查 TCP receive buffer 是否满：ss -tmip 查看 rcv_space 和 rcv_buf
  • Netfilter 规则影响性能：nft list ruleset 检查规则数量
  • 高软中断：cat /proc/softirqs 查看 NET_RX 软中断分布
  • 网卡 RX 队列积压：ethtool -S eth0 查看 rx_missed_errors
