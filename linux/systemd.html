Linux / Systemd

Systemd

Systemd 是现代 Linux 的 PID 1 和服务管理器，替代了 SysVinit 和 Upstart。它并行启动服务、管理依赖、集成日志（journald）、管理 cgroup、处理挂载/网络，并提供统一的 systemctl 接口。理解 systemd 的 Unit 文件结构、依赖系统、socket activation 和资源限制是运维和后端开发的基础技能。

systemctlunitjournaldsocket activationcgrouptarget
核心术语
  • Unit 文件INI 格式配置，描述服务/挂载/设备/定时器等。
  • 依赖与排序Requires/Wants 控制依赖，After/Before 控制顺序。
  • Cgroup 集成每个服务有独立 cgroup，管理资源限制和进程生命周期。
  • socket activationsocket 预创建，服务按需启动，支持零停机重启。

Unit 文件结构

# /etc/systemd/system/myapp.service [Unit] Description=My Application Documentation=https://example.com After=network.target postgresql.service Wants=postgresql.service [Service] Type=simple User=appuser Group=appgroup WorkingDirectory=/opt/myapp ExecStart=/opt/myapp/bin/server --port 8080 ExecReload=/bin/kill -HUP $MAINPID Restart=on-failure RestartSec=5s StandardOutput=journal StandardError=journal # 资源限制 CPUQuota=200% MemoryMax=512M LimitNOFILE=65536 [Install] WantedBy=multi-user.target

常用 systemctl 命令

# 服务管理 systemctl start|stop|restart|reload myapp systemctl enable|disable myapp # 开机启动 systemctl status myapp # 当前状态 systemctl is-active myapp # 脚本判断 # 查看日志 journalctl -u myapp -f # 实时日志 journalctl -u myapp --since "1h ago" journalctl -u myapp -n 100 -p err # 最近100条错误 # 系统分析 systemd-analyze blame # 各服务启动耗时 systemd-analyze critical-chain # 关键路径 systemd-analyze dot | dot -Tpdf > deps.pdf

Service Type 类型

  • simple（默认）：ExecStart 的进程是主进程，systemd 认为启动后服务即就绪
  • forking：服务会 fork 后台进程，需指定 PIDFile，systemd 以子进程为主进程
  • notify：服务调用 sd_notify("READY=1") 通知 systemd 已就绪，推荐
  • exec：类似 simple，但只有 exec 成功才认为启动成功
  • oneshot：执行一次就退出，常用于 ExecStartPre 初始化脚本
  • idle：等所有任务完成后才启动（如 getty 登录提示）

依赖关系详解

  • Requires=：强依赖，若目标停止或失败，本服务也跟着停止
  • Wants=：弱依赖，目标失败本服务不受影响，推荐用于可选依赖
  • BindsTo=：比 Requires 更强，目标不活跃时立即停止自身
  • PartOf=：声明属于某个组，停止/重启父 unit 时一起操作
  • After=/Before=：只控制启动顺序，不建立依赖，两者独立
  • Conflicts=：与指定 unit 互斥，启动时自动停止对方
  • 网络依赖：After=network-online.target（网络完全就绪）vs After=network.target（网络接口启动）

Socket Activation

  • systemd 预创建 socket，监听端口，服务进程按需拉起
  • 服务通过 SD_LISTEN_FDS 环境变量获取 socket fd（从 fd=3 开始）
  • 重启服务期间 socket 仍在监听，不会拒绝连接（零停机重启）
# myapp.socket [Socket] ListenStream=0.0.0.0:8080 Accept=no [Install] WantedBy=sockets.target # 服务只需 .socket 激活，不需要 After=network.target # Go 代码使用：listener, _ := activation.Listeners()

Timer 定时任务

# backup.timer - 替代 cron [Unit] Description=Daily Backup [Timer] OnCalendar=*-*-* 02:30:00 Persistent=true # 错过执行时追补 RandomizedDelaySec=10min # 避免惊群 [Install] WantedBy=timers.target # backup.service 对应服务文件 # 查看定时器状态 systemctl list-timers --all
  • OnCalendar：日历表达式，如 weekly / Mon 09:00
  • OnBootSec：启动后多久执行
  • Persistent=true：系统关机期间错过的执行，开机后补跑
