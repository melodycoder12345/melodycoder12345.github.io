顺序写 / Page Cache

顺序写和 Page Cache 让 WAL、Kafka 日志和 LSM 文件获得高吞吐。

Page CachefsyncWAL
B 类型页面重点是把背景、术语、机制、误区和工程场景讲清楚；本页不强行加入动画。
核心术语
Page Cache内核维护的文件页缓存。
Dirty Page已修改但尚未落盘的缓存页。
fsync要求内核把数据和必要元数据刷到稳定存储。

背景

随机 I/O 需要频繁寻址和元数据更新。顺序追加把写入变成连续日志，Page Cache 则吸收短时间内的读写波动。

运行机制

  • 应用 write 先进入 Page Cache，系统异步回写。
  • 顺序追加让磁盘和 SSD 更容易合并请求。
  • fsync 或刷盘策略决定崩溃窗口。

常见误区

  • 写入返回不等于已经持久化。
  • Page Cache 命中高不代表应用内存小，容器内还要关注 cgroup 统计。

工程场景

  • Kafka segment、数据库 WAL、LSM SSTable 和日志系统都依赖顺序 I/O。

边界判断

判断这个概念是否适用时，先看它解决的核心约束，再看代价是否落在业务可接受范围内。不要只记名字，要能说清楚它牺牲了什么、保留了什么。
