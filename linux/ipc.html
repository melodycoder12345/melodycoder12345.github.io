进程间通信（IPC）

Linux 提供管道、消息队列、共享内存、信号量等多种 IPC 机制，各自在通信语义、性能和适用场景上不同。选择合适的 IPC 方式直接影响系统性能和架构复杂度。

管道共享内存消息队列信号量
核心术语
  • Pipe（管道）单向字节流，内核缓冲区，父子进程最简通信方式，支持匿名和命名管道（FIFO）
  • Shared Memory（共享内存）多进程映射同一物理内存区域，最快的 IPC 方式，零数据复制，需配合同步原语
  • Message Queue（消息队列）内核管理的消息链表，带 mtype 类型字段，支持按类型选择接收，发送方接收方解耦

IPC 性能对比

机制延迟吞吐适用场景
共享内存~100ns极高大量数据、数据库 buffer pool
匿名管道~1µs高父子进程单向数据流
命名管道(FIFO)~2µs中无血缘进程、日志管道
消息队列~5µs中解耦异步消息、带类型路由
Unix Domain Socket~3µs高本地 RPC、支持 fd 传递

Socket vs 本地 IPC

网络 Socket（TCP/UDP）可跨主机，但在本地通信时有额外的网络栈开销。Unix Domain Socket（AF_UNIX）绕过网络层，支持传递文件描述符，适合本地进程间 RPC。

  • nginx 使用 Unix Domain Socket 与 upstream worker 通信
  • Docker daemon 使用 /var/run/docker.sock 接受客户端连接
  • systemd 使用 Socket activation，传递 fd 给服务进程

工程场景

  • nginx worker 通过共享内存共享连接计数和限速状态（ngx_shm_zone_t）
  • PostgreSQL 进程间通过共享内存共享 buffer pool，信号量保护页面锁
  • Redis fork() 子进程做 RDB 快照，利用 Copy-on-Write 避免全量复制
  • Chrome 多进程架构：渲染进程与主进程通过 Mojo IPC 通信

边界与误区

  • 共享内存不是"免费的"：缓存行竞争（false sharing）在多核下依然有损耗
  • 管道容量 64KB，写满后 write() 阻塞，两端互等可能导致死锁
  • System V IPC（shmget/msgget）资源不随进程退出自动释放，需手动 ipcrm
  • POSIX 信号量（sem_open）有名称，进程退出不影响信号量计数值
