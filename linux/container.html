容器原理

容器不是虚拟机，而是 Linux Namespace + Cgroup + OverlayFS 的组合。Namespace 提供进程/网络/文件系统的隔离视图，Cgroup 限制 CPU/内存资源上限，OverlayFS 实现只读镜像层加可写容器层的联合文件系统。动画展示容器启动时三层机制依次激活，以及 kill 容器后可写层消失、只读镜像层不变的过程。

核心术语
  • Linux Namespace将 PID/网络/文件系统虚拟化为独立命名空间，进程只见自己的世界。
  • Cgroup限制进程组的 CPU/内存/IO 资源上限，不提供隔离。
  • OverlayFS只读镜像层 + 可写容器层，写时 CoW，删除用 whiteout。
  • 容器 vs VM共享宿主内核（轻量快速）vs 独立内核（强隔离）。

Namespace 类型

  • PID Namespace：容器内 PID=1 是 init，宿主机看到另一个 PID（如 8420）
  • Network Namespace：独立 eth0、IP 地址、路由表、iptables；通过 veth pair 连接宿主机
  • Mount Namespace：独立挂载点视图，容器看不到宿主机的挂载
  • UTS Namespace：独立主机名和域名，容器可有独立 hostname
  • User Namespace：容器内 root（UID=0）映射到宿主机的普通用户，提升安全性
  • IPC Namespace：独立 System V IPC 和 POSIX 消息队列

OverlayFS 写时复制

  • 镜像层（lower dir）：只读，由多个 FROM/RUN/COPY 层叠加，多容器共享
  • 容器层（upper dir）：可写，每个容器独立，仅存储修改
  • 合并视图（merged）：容器进程看到的完整文件系统
  • 读：从 upper 到 lower 逐层查找，找到即返回
  • 写：将 lower 中的文件复制到 upper 后修改（Copy-on-Write）
  • 删除：在 upper 创建 .wh.filename（whiteout 文件）遮蔽 lower 中的文件
  • 停止容器：upper dir 删除，镜像层不变；docker commit 将 upper 固化为新镜像层

Cgroup v2 资源控制

  • CPU：cpu.max = "100000 200000"（每 200ms 最多用 100ms = 50%）
  • 内存：memory.max 硬限制，超出触发 OOM killer 杀死进程
  • IO：io.max 限制设备读写带宽和 IOPS
  • Cgroup 树：层级结构，子 cgroup 继承父 cgroup 限制，不能超出父级
  • 统计功能：记录进程组的资源使用量，用于计费和监控

容器运行时架构

  • Docker：CLI + dockerd（高层运行时）+ containerd（中层）+ runc（低层 OCI 运行时）
  • runc：调用 Linux 内核创建 Namespace、设置 Cgroup、挂载 OverlayFS，执行容器进程
  • OCI 标准：容器镜像格式（Image Spec）和运行时接口（Runtime Spec），保证可移植性
  • Kubernetes：通过 CRI 接口调用 containerd/CRI-O，管理 Pod 生命周期
  • gVisor/Kata：增强隔离的沙盒运行时，牺牲性能换取更强隔离
