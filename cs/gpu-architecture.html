GPU 架构

GPU 不是一个大 CPU，而是数千个轻量级核心组成的大规模并行处理器。理解 SM、Warp 调度、HBM 带宽层次和 PCIe 传输开销，是优化 AI 推理、图形渲染和通用计算（GPGPU）的基础。

核心观察
SIMT 隐藏延迟一个 Warp 等待内存时，调度器切换另一个 Warp 执行，HBM 延迟被计算掩盖。充足 Warp 数（Occupancy）是关键。
Divergence 代价if/else 分叉让 32 个线程分两批执行，吞吐减半。避免在 kernel 热路径出现分支。
LLM Decode 是 Memory Bound每步只做小矩阵乘，但要反复读 KV Cache，HBM 带宽是瓶颈，加算力无效。

GPU 推理服务配置指南

      
    
        
  • 显存估算：至少考虑模型权重、KV Cache、运行时工作区和框架开销；“参数量 × 精度字节”只估算未压缩权重。
    • 
        
  • Batch size 影响利用率：增大 batch 往往提高权重复用和算术强度，但 MFU 取决于模型、阶段、内核、GPU 与统计口径，不存在通用百分比。
    • 
        
  • Tensor Parallelism：可通过 NVLink、PCIe 或其他互联切分权重矩阵，降低单卡内存压力，代价是 collective 通信；带宽取决于具体拓扑和代际。
    • 
        
  • Flash Attention：将 Attention 计算分块在 L1/Shared Memory 完成，减少 HBM 读写次数，大幅提升 Memory Bound 效率。
    • 
      

    

    

      
LLM 显存占用计算

      
    
        
  • 模型权重：参数量 × dtype。7B FP16 = 14GB；INT8 量化减半，INT4 再减半。
    • 
        
  • KV Cache：基础估算为 2 × 层数 × KV 头数 × 头维度 × 已缓存 token 数 × batch × 每元素字节；GQA/MQA 要使用 KV 头数，分页、量化和运行时元数据会改变实际占用。
    • 
        
  • 为什么 batch 影响 MFU：算术强度 = FLOP / HBM 字节。batch 越大 → 每次读权重服务更多 token → 算术强度越高 → 越接近 Compute Bound。
    • 
        
  • 量化与 Decode：降低权重位宽可减少带宽和容量压力，但实际加速受量化元数据、反量化、内核支持和其他瓶颈影响，不能由位宽比例直接推出吞吐倍数。
