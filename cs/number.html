面试题

int8 的范围为什么是 -128~127 而不是 -127~127？▶
补码中 8 位能表示 256 个值。正数范围 0~127（含 0），负数范围 -1~-128，共 128 个负数。10000000（-128）没有对应的正数形式，所以范围是非对称的。原码有 +0（00000000）和 -0（10000000）两种表示，浪费了一个编码位置；补码消除了 -0，将其复用为 -128，让范围多了一个。
为什么 0.1 + 0.2 ≠ 0.3？如何在代码中处理浮点比较？▶
0.1 和 0.2 的二进制表示是无限循环小数，IEEE 754 只能截断存储，存在舍入误差。两个误差相加后结果为 0.30000000000000004。
处理方式：
1. 使用容差比较：math.Abs(a-b) < 1e-9
2. 金融场景用整数（分而非元）
3. 使用 math/big.Float 或 shopspring/decimal 库
NaN、+Inf、-Inf 在 IEEE 754 中如何编码？▶
IEEE 754 用特殊指数字段编码：
• 指数全 1（E=255）+ 尾数非零 → NaN（Not a Number），如 0/0、sqrt(-1)
• 指数全 1 + 尾数全 0 + 符号位 0 → +Inf
• 指数全 1 + 尾数全 0 + 符号位 1 → -Inf
• 指数全 0 + 尾数非零 → 非规格化数（接近 0 的极小值）
NaN 是唯一不等于自身的值：NaN != NaN 为 true。
Go 中 int 的大小是固定的吗？int32 和 int 的区别？▶
int 的大小由平台决定：64 位系统上是 64 位，32 位系统上是 32 位。int32 是固定 32 位，不随平台变化。
实践建议：
• 数组索引、循环计数用 int（与平台 native 大小匹配，性能最优）
• 需要确定精确位宽时用 int32/int64（如协议字段、序列化）
• 不要混用 int 和 int64 做比较，需要显式转换。

易错点

❌ 整数溢出：Go 不会 panic
var x int8 = 127
x++
// x 变为 -128，不会报错
// 01111111 + 1 = 10000000

// 检测溢出需手动判断
if x == 127 {
    // 将要溢出，处理...
}
import "math/bits"

// 安全加法：检测溢出
func safeAdd(a, b uint64) (uint64, bool) {
    sum, carry := bits.Add64(a, b, 0)
    return sum, carry == 0
}

// 或使用 math.MaxInt8 做边界检查
if x > math.MaxInt8-1 {
    return errors.New("overflow")
}

原则：Go 的整数溢出是静默的，关键业务逻辑中必须手动检查边界。

❌ 浮点数直接用 == 比较
a := 0.1 + 0.2
b := 0.3
if a == b {
    // 永远不会进入！
    // a = 0.30000000000000004
    // b = 0.3
}

// 同样错误
var sum float64
for i := 0; i < 10; i++ {
    sum += 0.1
}
fmt.Println(sum == 1.0) // false
import "math"

// 正确：使用容差比较
const eps = 1e-9
if math.Abs(a-b) < eps {
    // 认为相等
}

// 金融场景：使用整数
// 存储分而非元，避免浮点
cents := 10 + 20  // 30 分，精确

// 或使用 big.Float
x := new(big.Float).SetFloat64(0.1)
y := new(big.Float).SetFloat64(0.2)
z := new(big.Float).Add(x, y)

原则：永远不要用 == 比较浮点数（特殊情况：检查 NaN、Inf 除外）。
