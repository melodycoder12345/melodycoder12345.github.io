面试题

流水线的五个阶段各自的职责？▶
IF（取指）：从 PC 地址取出指令；ID（译码）：解析指令操作码，读寄存器；EX（执行）：ALU 运算或计算内存地址；MEM（访存）：读写数据缓存；WB（写回）：将结果写回寄存器文件。每个阶段占用一个时钟周期，五级流水线理想情况下每周期出一条指令（吞吐率 1 IPC）。
数据冒险、结构冒险、控制冒险的区别？▶
数据冒险（RAW/WAR/WAW）：指令间存在数据依赖，后续指令需要前指令尚未写回的结果。解决方案：forwarding（数据前递）+ stall。
结构冒险：多条指令同时需要同一硬件资源（如单端口内存）。解决方案：资源复制（分离 I-Cache/D-Cache）。
控制冒险：分支/跳转指令导致 PC 不确定。解决方案：分支预测 + flush。
分支预测失败的代价有多大？现代 CPU 准确率多少？▶
五级流水线中预测失败会 flush 已进入流水线的 3 条指令，损失约 3 个时钟周期。现代超标量 CPU（如 Intel Skylake）流水线深度达 14-19 级，错误预测代价高达 15-20 个周期。现代 CPU 分支预测准确率通常在 95%~99% 之间，使用 TAGE（带标签的几何历史长度预测器）等复杂算法。
乱序执行为什么不会破坏程序语义？ROB 的作用？▶
乱序执行（Out-of-Order Execution）允许指令按数据准备情况乱序进入执行单元，但 ROB（重排序缓冲区，Re-Order Buffer） 保证按原程序顺序提交（retire）结果。ROB 是一个循环队列，追踪所有在途指令的状态；只有队首指令完成且无异常，才提交结果到体系结构状态（寄存器文件/内存）。这保证了精确例外（precise exception）语义。

易错点

❌ 误区：流水线 = 多核并行
// 流水线（单核）
// 同一时刻多条指令处于
// 不同阶段，但仍是一条
// 逻辑执行流，没有真正
// 的并行计算

// 时钟周期 3：
// I1: EX  阶段
// I2: ID  阶段
// I3: IF  阶段
// 三条指令同时在硬件上
// 活跃，但属于同一 core

流水线是指令级流水（ILP），提升吞吐，不是多核并行。

// 多核并行（真正并行）
// Core 0 和 Core 1 各自
// 独立执行不同线程

// Core 0: 执行线程 A
// Core 1: 执行线程 B
// 同一时刻真正执行两条
// 不同指令流

// 需要 OS 调度 + 显式
// 并发编程（goroutine 等）

多核才是真正的并行，需要程序员显式使用并发原语。

❌ Forwarding 不能解决所有数据冒险
; LOAD-USE hazard：
; forwarding 无法消除
LW  R1, [R2]   ; MEM阶段才有数据
ADD R3, R1, R4 ; 需要R1，但LW
               ; EX结束时数据不在

; 即使加 forwarding，
; LW 的结果在 MEM 阶段
; 末尾才可用，ADD 的 EX
; 阶段已经过了 → 仍需
; 1 个 stall 周期

LOAD-USE hazard：Load 后紧跟使用该寄存器的指令，必须插入 1 个 stall。

; 编译器优化：指令调度
; 将无关指令插入 LOAD 后

LW  R1, [R2]   ; 取数
ADD R5, R6, R7 ; 无关指令填 stall
ADD R3, R1, R4 ; 现在 R1 已就绪

; 运行时：硬件插 bubble
LW  R1, [R2]
NOP            ; 硬件 stall 1 周期
ADD R3, R1, R4 ; forwarding 传值

编译器通过指令调度消除 LOAD-USE stall；硬件检测到时自动插 bubble。
