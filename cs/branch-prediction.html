分支预测

CPU 流水线不等分支结果，预测一条路径继续取指（投机执行，虚线框）。预测正确时虚线框变实；预测错误时虚线框变红并 flush，重新从正确路径取指。2-bit 饱和计数器记录历史：连续预测错误两次才改变预测方向，避免一次误判就翻转。动画展示流水线停顿和 flush 的真实代价。

分支预测器的演化

  • 静态预测：总是预测不跳（simplest），命中率约 50–65%
  • 1-bit 预测器：记录上次结果，命中率约 85%，但循环末尾（taken→not taken）每次循环都误判
  • 2-bit 饱和计数器：需要连续两次错误才改变方向，解决了 1-bit 在循环边界的问题
  • 局部历史预测器（PHT）：每个分支独立记录 k 位历史，查表预测，命中率 90%+
  • TAGE 预测器（现代）：结合多长度全局历史，Intel/AMD 旗舰 CPU 使用，准确率 97–99%

流水线冲突类型

  • 数据冲突（Data Hazard）：指令需要前一指令的结果，用 Forwarding 或插入 NOP 解决
  • 控制冲突（Control Hazard）：分支指令，用分支预测解决，误判时 flush
  • 结构冲突（Structural Hazard）：两条指令同时需要同一硬件单元，用流水线停顿
  • 乱序执行（OoO）：重排指令顺序，避开数据依赖等待；ROB（Reorder Buffer）维持程序顺序提交

对程序性能的影响

  • 分支密集代码：大量 if/else 或 switch，每次误判浪费约 15 周期
  • 排序循环：随机数组的比较分支预测命中率低（约 50%），有序数组几乎 100%
  • 避免分支的技巧：条件移动（CMOV）、查表、无分支算法（bit tricks）
  • profile-guided optimization（PGO）：编译器根据实际运行 profile 优化分支布局，使热路径更可预测
  • __builtin_expect：告知编译器分支概率，影响指令顺序和 CPU 预测器

Spectre/Meltdown 漏洞

  • 投机执行期间访问了无权访问的内存（投机路径上的越界访问）
  • 投机失败后虽然结果被丢弃，但 CPU 缓存状态被修改（侧信道）
  • 攻击者通过测量缓存访问时间（cache timing）推断出被保护的数据
  • 修复：Retpoline（防止间接分支推测）、KPTI（内核页表隔离）、微码更新
  • 代价：KPTI 对系统调用密集的应用性能损失 5–30%
