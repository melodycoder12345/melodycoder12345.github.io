# 知识数据维护说明

`knowledge/` 是节点、页面画像和语义关系的唯一人工维护源。

- `modules.json`：模块名称与颜色。
- `nodes/<module>.json`：模块节点及页面节点；页面节点同时包含页面画像。
- `relations.json`：经过明确整理、会进入正式图谱的语义关系。
- `relation-candidates.json`：由历史规则生成的待审核候选，不进入前端图谱。
- `schema/`：节点和关系的 JSON Schema 文档。

`cs/topic.html` 与 `golang/topic.html` 是交互式模块聚合页，不作为独立知识节点登记；具体知识点仍由各详情页节点承载。

修改数据后运行：

```bash
npm run knowledge:check
```

该命令依次校验数据、生成根目录 `knowledge-data.js`，并运行测试。不要直接编辑生成文件。

校验错误会阻止构建，包括重复 ID、悬空关系、失效页面、把模块分类当作关系，以及前置依赖环。没有已审核关系的节点是允许存在的，只作为治理提示；不应为了消除“孤立”而制造弱关系。

模块归属只由节点的 `module` 字段表达。无论是否属于同一模块，只有能够明确说明“为什么有关”的两个页面知识点才能建立语义关系。
