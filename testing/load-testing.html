⚡ 负载与压力测试

通过模拟真实并发流量发现系统容量极限。负载测试确认正常流量下的性能基线；压力测试把系统推向极限，观察何处先断裂；浸泡测试验证系统在持续负载下的稳定性。

测试类型区别

负载测试（Load Test）

在预期正常流量下运行，验证系统达到性能目标（P99 < 200ms，错误率 < 0.1%）。确立基线，证明系统在日常场景下表现良好。

压力测试（Stress Test）

持续增加负载直至系统降级，找到断裂点（breaking point）。关注问题：哪里先崩溃？是 CPU、内存、连接池还是数据库？

浸泡测试（Soak Test）

在中等负载下运行数小时到数天，发现缓慢内存泄漏、连接泄漏、日志文件积累等随时间累积的问题。

峰值测试（Spike Test）

模拟突然爆发的流量洪峰（秒杀、热点事件），验证系统能否快速扩容、降级和恢复，而不是崩溃。

延迟百分位（Percentiles）

为什么不用平均延迟？

平均值会被少量极端慢请求稀释。假设 99 个请求 10ms，1 个请求 10000ms，平均值是 110ms，但 99% 的用户体验是 10ms，1% 的用户感知到 10s。

P99 的含义

P99 = 第 99 百分位延迟：100 个请求中最慢的那 1 个的耗时。P99 < 500ms 意味着 99% 的请求都在 500ms 内完成。SLO 通常用 P99 而非平均值定义。

长尾延迟（Long Tail）

在微服务调用链中，多个服务的 P99 会累乘：10 个服务各有 1% 慢请求，串行调用时约有 10% 的请求会遇到至少一个慢服务，使得整体 P99 恶化。

k6 测试脚本
// k6 负载测试脚本示例
import http from 'k6/http';
import { sleep, check } from 'k6';
import { Rate } from 'k6/metrics';

const errorRate = new Rate('errors');

// 负载阶段：ramp up → 稳定 → ramp down
export const options = {
  stages: [
    { duration: '2m', target: 100 },   // 爬坡到 100 VU
    { duration: '5m', target: 100 },   // 稳定 5 分钟
    { duration: '1m', target: 0   },   // 缩减到 0
  ],
  thresholds: {
    http_req_duration: ['p(99)<500'],   // P99 必须 < 500ms
    errors:            ['rate<0.01'],    // 错误率 < 1%
  },
};

export default function() {
  const res = http.get('https://api.example.com/users');
  check(res, {
    'status 200': (r) => r.status === 200,
    'latency ok': (r) => r.timings.duration < 500,
  }) || errorRate.add(1);
  sleep(1);  // 模拟真实用户思考时间
}
