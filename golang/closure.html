闭包基础

函数值 + 捕获的变量引用

核心

闭包是一个函数值，它捕获并引用了其定义时所在作用域中的变量。被捕获的是变量的引用，不是值的拷贝。

func makeCounter() func() int {
    count := 0
    return func() int {
        count++     // 捕获并修改 count
        return count
    }
}

c1 := makeCounter()
c2 := makeCounter()
fmt.Println(c1(), c1(), c1())  // 1 2 3
fmt.Println(c2(), c2())        // 1 2（c2 独立的 count）

每次调用 makeCounter 都创建一个新的 count 变量，每个返回的闭包引用各自的 count。count 因为被闭包引用，会从栈逃逸到堆，其生命周期延长到所有引用它的闭包都消亡为止。

循环变量捕获

经典陷阱与 Go 1.22 语义变更1.22

核心

Go 1.21 及之前：for 循环变量在整个循环中只有一个实例，所有闭包共享同一个变量。

Go 1.22+：每次迭代创建独立的循环变量，不再有这个陷阱。

// Go 1.21 及之前的陷阱
funcs := make([]func(), 3)
for i := 0; i < 3; i++ {
    funcs[i] = func() {
        fmt.Println(i)  // 捕获的是 i 的引用
    }
}
for _, f := range funcs {
    f()  // 打印 3 3 3，而不是 0 1 2
}

// 解决方案1：引入局部变量（Go 1.21 适用）
for i := 0; i < 3; i++ {
    i := i  // 遮蔽外层 i，创建新变量
    funcs[i] = func() { fmt.Println(i) }
}

// 解决方案2：传参
for i := 0; i < 3; i++ {
    funcs[i] = func(n int) func() {
        return func() { fmt.Println(n) }
    }(i)  // 立即调用，值传递
}

// Go 1.22+：每次迭代 i 是独立变量，自动正确

goroutine 中的循环变量捕获是同样的陷阱，常见于 go func() { ... }() 场景。

函数作为值

高阶函数与函数式选项模式

进阶

Go 函数是一等公民，可以赋值给变量、作为参数传递、作为返回值。函数类型是 func(参数类型) 返回类型。

// 函数类型别名
type Handler func(w http.ResponseWriter, r *http.Request)

// 高阶函数：接受函数参数
func filter(nums []int, pred func(int) bool) []int {
    var result []int
    for _, n := range nums {
        if pred(n) {
            result = append(result, n)
        }
    }
    return result
}

// 函数式选项模式（Functional Options Pattern）
type Server struct {
    addr    string
    timeout time.Duration
}

type Option func(*Server)

func WithAddr(addr string) Option {
    return func(s *Server) { s.addr = addr }
}

func NewServer(opts ...Option) *Server {
    s := &Server{addr: ":8080", timeout: 30 * time.Second}
    for _, opt := range opts {
        opt(s)
    }
    return s
}

srv := NewServer(WithAddr(":9090"))

闭包内存影响

被捕获变量逃逸到堆

进阶

当变量被闭包捕获时，Go 编译器的逃逸分析会将该变量分配到堆上（而非栈上），以确保闭包在外层函数返回后仍能访问该变量。

func makeAdder(x int) func(int) int {
    // x 被返回的闭包捕获，逃逸到堆
    return func(y int) int {
        return x + y
    }
}

// 验证逃逸：go build -gcflags="-m" main.go
// 输出：x escapes to heap

// 闭包捕获大对象时注意内存占用
func processLargeData() func() {
    data := make([]byte, 1<<20)  // 1MB
    process(data)
    // ❌ 返回的闭包持有 data 引用，1MB 无法释放
    return func() {
        fmt.Println(data[0])  // 只用一个字节，却持有 1MB
    }
}

性能建议：如果闭包只需要大对象的一部分，提前提取需要的字段，避免整个大对象被闭包持有。

面试题

闭包捕获的是值还是引用？▶
闭包捕获的是变量的引用（准确说是指向变量的指针），不是值的拷贝。这意味着：
• 闭包读取变量时，读到的是变量的当前值（可能已被外部修改）
• 闭包修改变量时，外部也能看到这个修改
• 如果需要捕获值的快照，要显式拷贝：x := x（遮蔽变量创建新的局部变量）

注意区别：函数参数是值传递（拷贝），而闭包捕获的外部变量是引用捕获。
循环变量陷阱的本质原因和解决方案？▶
本质：Go 1.21 及之前，for 循环变量（如 i）在整个循环生命周期内只有一个内存地址，每次迭代只是修改该地址存储的值。闭包捕获的是这个地址的引用，所以执行时看到的是循环结束时的最终值。

解决方案（Go 1.21）：
1. 遮蔽变量：i := i（在循环体内重新声明），每次迭代创建新变量
2. 传参：go func(i int) { ... }(i)，通过参数值传递

Go 1.22+ 已经修复：每次迭代自动创建独立变量，无需手动处理。
函数式选项模式（Functional Options）有什么优势？▶
优势：
1. 可选参数：与 Go 不支持默认参数/重载不同，functional options 优雅地表达可选配置
2. 向后兼容：新增选项不影响已有调用代码（无需修改函数签名）
3. 自文档化：WithTimeout(5s) 比位置参数更清晰
4. 可测试：可以在测试中传入不同选项

缺点：比简单结构体配置多一些间接性，小对象初始化场景可能过度设计。
适用：公共 API、配置项较多、需要默认值的场景。
如何避免闭包导致的内存泄漏？▶
常见内存泄漏场景：
1. 闭包捕获了大对象的引用，大对象无法被 GC
2. goroutine 中的闭包持有资源引用，goroutine 泄漏导致资源无法释放
3. 事件监听器/回调中的闭包没有反注册

避免方法：
• 只捕获需要的字段，不捕获整个结构体
• goroutine 要有明确的退出机制（context、done channel）
• 注册的回调要在不需要时反注册
• 用 go tool pprof 检查 heap profile 发现内存泄漏
defer 中使用闭包与不使用闭包的区别？▶
关键区别在于参数/变量的求值时机：

defer fmt.Println(x)：x 在 defer 语句处立即求值（值拷贝）
defer func() { fmt.Println(x) }()：x 在闭包执行时（函数返回时）求值（引用捕获）

示例：
x := 1; defer fmt.Println(x); x = 2 → 打印 1（defer 处已捕获 x=1 的值）
x := 1; defer func() { fmt.Println(x) }(); x = 2 → 打印 2（闭包引用 x，执行时 x=2）

修改命名返回值也利用了这一点：defer func() { result += 1 }() 可以修改命名返回值。

易错点

❌ goroutine 中循环变量共享（Go 1.21 及之前）
urls := []string{"a", "b", "c"}
for _, url := range urls {
    go func() {
        fetch(url)  // ❌ url 被共享
    }()
}
// 所有 goroutine 可能都用同一个 url 值

所有 goroutine 捕获了同一个 url 变量的引用，可能都读到循环结束时的最后一个值。

for _, url := range urls {
    url := url  // ✓ 遮蔽，创建新变量
    go func() {
        fetch(url)
    }()
}
// 或：参数传递
for _, url := range urls {
    go func(u string) {
        fetch(u)
    }(url)  // 值传递
}

Go 1.22+ 自动修复，旧代码用变量遮蔽或参数传递解决。

❌ 闭包修改 slice 参数，外部看不到 append 效果
func main() {
    s := []int{1, 2}
    add := func() {
        s = append(s, 3)  // 闭包修改 s
    }
    add()
    fmt.Println(s)  // [1 2 3] ← 这里 OK
}
// 但如果 s 是函数参数就不同了
func addTo(s []int) {
    s = append(s, 3)  // ❌ 修改的是局部副本
}

闭包直接捕获外部变量 s 可以修改。但函数参数 s 是副本，append 只影响局部变量。

// 函数参数需要返回或传指针
func addTo(s []int) []int {
    return append(s, 3)  // ✓ 返回新 slice
}

// 或传 *[]int
func addTo(sp *[]int) {
    *sp = append(*sp, 3)
}

s := []int{1, 2}
s = addTo(s)  // 接收返回值

区分闭包捕获（引用）和函数参数（值传递）的行为差异。

❌ defer 中闭包捕获 vs 参数求值时机混淆
func logTime() {
    start := time.Now()
    // ❌ 参数在 defer 处求值
    defer fmt.Println("elapsed:",
        time.Since(start))
    // time.Since(start) 在 defer 语句处
    // 被求值，结果约为 0！
    time.Sleep(time.Second)
}

defer 语句中的函数参数在 defer 登记时就被求值，不是在函数返回时。

func logTime() {
    start := time.Now()
    // ✓ 使用闭包，延迟求值
    defer func() {
        fmt.Println("elapsed:",
            time.Since(start))
        // 函数返回时才执行，计时正确
    }()
    time.Sleep(time.Second)
    // 打印约 1s
}

需要延迟求值时，用 defer func() { ... }() 包裹，使其成为闭包引用。
