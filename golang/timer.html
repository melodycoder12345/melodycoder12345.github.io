步骤 1

timer.go

面试题

time.NewTimer 和 time.After 的区别？▶
time.NewTimer 返回 *Timer 对象，可以 Stop()/Reset()，适合需要控制 timer 生命周期的场景。
time.After 是语法糖：NewTimer(d).C，返回只读 channel。无法 Stop，timer goroutine 会一直运行到触发（Go 1.23 前在 select 中使用时注意泄漏）。
推荐在循环中使用 NewTimer，在一次性 select 中可以用 time.After。
Timer.Stop() 返回 false 意味着什么？▶
Stop() 返回 false 表示 timer 已经触发（channel 中有未读取的值）或已经被 Stop。此时 timer 的 channel（.C）中可能有一个值，需要排空：if !t.Stop() { select { case <-t.C: default: } }。在 Reset 之前务必先排空，否则旧的触发值会被误当作新的 Reset 触发。
Ticker 和 Timer 的区别？▶
time.Timer：只触发一次，触发后 channel 关闭不再发送。可以通过 Reset 重置再触发。
time.Ticker：按固定间隔周期性触发，channel 持续发送。必须调用 Stop() 停止，否则 goroutine 和 channel 不会被 GC 回收。
Ticker 不保证每次触发准时（处理时间超过间隔时会跳过，不会积压）。
如何在 goroutine 中安全使用 Ticker？▶
defer ticker.Stop() 是最常见的做法，确保 goroutine 退出时 Ticker 被停止：
ticker := time.NewTicker(time.Second)\ndefer ticker.Stop()\nfor {\n    select {\n    case <-ticker.C:\n        doWork()\n    case <-ctx.Done():\n        return\n    }\n}
同时监听 context 取消信号，确保 goroutine 能够退出（防止泄漏）。

易错点

❌ Timer.Reset 竞态条件
t := time.NewTimer(d)
// 错误的 Reset 方式
t.Stop()
t.Reset(newD) // 竞态！
// Stop 返回 false 说明已触发
// channel 中有旧值未读取
// Reset 后旧值仍在 channel
// 正确方式：先排空 channel
if !t.Stop() {
    select {
    case <-t.C:
    default:
    }
}
t.Reset(newD)

// Go 1.23+ 修复了部分行为
// 但最佳实践仍是先排空再 Reset

Stop 后若 channel 有值，Reset 不会清空，导致下次 select 立即触发旧值。

❌ 忘记 Stop Ticker 导致泄漏
func monitor() {
    ticker := time.NewTicker(time.Second)
    for {
        select {
        case <-ticker.C:
            check()
        // 没有退出条件！
        // ticker 永远不被 Stop
        }
    }
    // goroutine 永远运行，ticker 泄漏
}
func monitor(ctx context.Context) {
    ticker := time.NewTicker(time.Second)
    defer ticker.Stop() // 确保停止
    for {
        select {
        case <-ticker.C:
            check()
        case <-ctx.Done():
            return // 收到取消信号退出
        }
    }
}

Ticker 必须调用 Stop()，否则内部 goroutine 永远运行，channel 不被释放。

❌ 用 time.Sleep 代替 Ticker 做定时任务
for {
    doWork() // 耗时 200ms
    time.Sleep(time.Second)
    // 实际间隔 = 1s + 200ms = 1.2s
    // 间隔随任务耗时漂移
    // 长期运行误差积累
}
ticker := time.NewTicker(time.Second)
defer ticker.Stop()
for range ticker.C {
    go doWork() // 并发执行，不阻塞 ticker
}
// ticker 每隔精确 1s 触发
// 不受任务耗时影响
// 但若任务比间隔慢，需要控制并发数

Ticker 基于绝对时钟触发，不受任务耗时影响；Sleep 每次都是相对延迟，会漂移。
