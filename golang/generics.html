类型参数基础

func F[T any](v T) 语法

核心

Go 1.18 引入泛型，使用方括号 [T constraint] 声明类型参数。类型参数可以用在函数、方法（有限制）和类型上。

// 泛型函数
func Map[T, U any](s []T, f func(T) U) []U {
    result := make([]U, len(s))
    for i, v := range s {
        result[i] = f(v)
    }
    return result
}

// 调用时可以显式指定类型，或让编译器推断
nums := []int{1, 2, 3}
strs := Map(nums, strconv.Itoa)  // 类型推断
strs2 := Map[int, string](nums, strconv.Itoa)  // 显式指定

// 泛型类型（容器）
type Stack[T any] struct {
    items []T
}
func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }
func (s *Stack[T]) Pop() (T, bool) {
    if len(s.items) == 0 {
        var zero T
        return zero, false
    }
    n := len(s.items) - 1
    v := s.items[n]
    s.items = s.items[:n]
    return v, true
}

s := &Stack[int]{}
s.Push(1); s.Push(2)
v, _ := s.Pop()  // 2

约束（Constraints）

comparable、~ 操作符与 union 约束

核心

约束用于限制类型参数可以是哪些类型，基于接口语法扩展而来。

// comparable：支持 == 和 != 的类型
func Contains[T comparable](s []T, v T) bool {
    for _, x := range s {
        if x == v { return true }
    }
    return false
}

// ~ 操作符：包含底层类型为 T 的所有类型
// ~int 包括 int 以及 type MyInt int
type Number interface {
    ~int | ~int8 | ~int16 | ~int32 | ~int64 |
    ~uint | ~float32 | ~float64
}

func Sum[T Number](nums []T) T {
    var total T
    for _, n := range nums { total += n }
    return total
}

// 自定义类型也满足 Number
type Celsius float64
temps := []Celsius{36.5, 37.2, 38.0}
Sum(temps)  // OK，Celsius 的底层类型是 float64

// golang.org/x/exp/constraints 包提供了常用约束
// constraints.Ordered：可排序类型（支持 < > 等）
// constraints.Integer/Float/Complex

约束也可以包含方法要求：

type Stringer[T any] interface {
    fmt.Stringer
    Less(other T) bool
}

any vs comparable

两个内置约束的区别

核心

any 是 interface{} 的别名，作为约束时表示"任意类型"，即不加任何限制。comparable 是一个内置约束，表示支持 == 和 != 的类型。

any 约束

接受一切类型，包括 slice、map、func 等不可比较的类型。但在函数体内不能用 == 比较，不能用作 map 的 key。

comparable 约束

只接受可比较类型（bool、数值、string、指针、channel、array、struct 所有字段可比较）。可以用 ==，可以用作 map key。

// 泛型 Set（需要可比较类型）
type Set[K comparable] struct {
    m map[K]struct{}
}
func (s *Set[K]) Add(k K) { s.m[k] = struct{}{} }

// interface{}/any 不满足 comparable
// 因为 any 可以持有 slice 等不可比较的值
var _ = Set[any]{}  // ❌ 编译错误
var _ = Set[int]{}  // ✓

泛型适用场景

什么时候用，什么时候不用

进阶

适合使用泛型的场景：

  • 容器/集合类型：Stack、Queue、Set、Map 等，需要类型安全
  • 对多种类型做相同操作：Map、Filter、Reduce 等函数式操作
  • 排序、搜索（需要 Ordered/comparable 约束）
  • Go 1.21+ 标准库：slices、maps、cmp 包大量使用泛型

不适合使用泛型的场景：

  • 函数本身只有一种实现，不需要类型参数化（不要为了泛型而泛型）
  • 接口已经足够表达多态（不同类型有不同行为）
  • 类型参数只用在函数内部不需要类型安全的地方
// Go 1.21 slices 包 — 泛型的正确使用
import "slices"

s := []int{3, 1, 4, 1, 5}
slices.Sort(s)          // 泛型排序
slices.Contains(s, 4)  // 泛型查找
slices.Max(s)           // 泛型最大值

// Go 1.21 maps 包
import "maps"
m1 := map[string]int{"a": 1}
m2 := maps.Clone(m1)   // 泛型克隆
maps.Equal(m1, m2)     // 泛型相等比较

面试题

泛型和 interface{} 哪个性能更好？▶
没有脱离具体代码和 Go 版本的固定答案。接口转换不保证发生堆分配，接口调用也并非语言层面保证“不能内联”；编译器可能去虚拟化并优化它们。泛型的实例化、形状共享和字典传递属于编译器实现细节，也会随版本变化。

泛型的稳定优势是编译期类型检查和复用同一算法；性能应使用目标 Go 版本、真实类型与负载做 benchmark，并结合逃逸分析和汇编结果判断。
约束里的 ~ 是什么意思？▶
~T 表示"底层类型（underlying type）为 T 的所有类型"，包括 T 本身以及所有以 T 为底层类型的自定义类型。

例如：~int 匹配 int 以及 type MyInt int、type Score int 等所有以 int 为底层类型的类型。

如果没有 ~，则只匹配精确的 int，不匹配 MyInt。

典型用法：type Ordered interface { ~int | ~float64 | ~string }，让约束覆盖所有"类 int/float/string"的自定义类型，而不只是内置类型本身。
泛型方法有什么限制？▶
Go 泛型的一个重要限制：方法不能有额外的类型参数（只有函数可以独立声明类型参数）。

合法：
type Stack[T any] struct { ... }
func (s *Stack[T]) Push(v T) { ... }（使用类型自身的类型参数）

非法：
func (s *Stack[T]) Map[U any](f func(T) U) []U（编译错误：方法不能有额外类型参数）

解决方案：将需要额外类型参数的操作改为包级别的泛型函数：func MapStack[T, U any](s *Stack[T], f func(T) U) []U
如何获取泛型类型参数 T 的零值？▶
直接声明该类型的变量即可获得零值：

var zero T

这是惯用法，在需要返回"空值"时使用：
func (s *Stack[T]) Pop() (T, bool) {
  if len(s.items) == 0 { var zero T; return zero, false }
  ...
}

Go 1.21+ 也可以用 *new(T)，但 var zero T 更清晰。对于结构体类型，零值是所有字段的零值；对于 interface 类型，零值是 nil。
泛型 vs interface：如何选择？▶
选择原则：

用 interface（多态行为）：
• 不同类型有不同的行为实现（io.Writer 的不同实现）
• 需要在运行时决定具体类型
• 需要将不同类型放入同一集合（[]Animal 存放不同动物）

用泛型（类型安全+代码复用）：
• 对多种类型执行完全相同的操作逻辑
• 容器/数据结构，需要类型安全的存取
• 算法（排序、搜索、Map/Filter/Reduce）
• 想要避免 interface{} 的装箱开销和类型断言

简单记忆：行为多态 → interface；代码复用+类型安全 → 泛型。

易错点

❌ 泛型滥用：简单情况不需要泛型
// ❌ 过度泛型化：完全没必要
func Print[T any](v T) {
    fmt.Println(v)
}
// fmt.Println 已经接受 any，这个泛型没意义

// ❌ 只有一种类型使用的"泛型"
func Add[T int](a, b T) T {
    return a + b
}
// 如果只处理 int，直接写 int 函数即可

泛型会增加代码复杂度，只在真正需要多类型复用时才使用。

// ✓ 真正需要泛型的场景
func Filter[T any](s []T,
    pred func(T) bool) []T {
    var result []T
    for _, v := range s {
        if pred(v) {
            result = append(result, v)
        }
    }
    return result
}
// 对 []int、[]string、[]User 都有用

当多种不同类型共享完全相同的操作逻辑时，泛型才有价值。

❌ 约束写法错误：union 约束不能用于方法
type NumOrStr interface {
    ~int | ~string
}

// ❌ 不能调用约束中没有指定的方法
func Bad[T NumOrStr](v T) string {
    // 不能调用 v.String()——int 没有这个方法
    return v.String()  // 编译错误
}

union 约束（A|B|C）只表示类型集合，不保证方法集。

// ✓ 约束中有方法时可以调用
type Stringer interface {
    String() string
}

func Print[T Stringer](v T) {
    fmt.Println(v.String())  // ✓
}

// ✓ union 约束只能用于操作符操作
func Max[T ~int|~float64](a, b T) T {
    if a > b { return a }  // 操作符 OK
    return b
}

union 约束中只能使用所有成员类型共同支持的操作（如 +、-、<、>）。

❌ 方法不支持额外类型参数
type Transformer[T any] struct{ data []T }

// ❌ 方法不能有自己的类型参数
func (t Transformer[T]) Map[U any](
    f func(T) U) []U { // 编译错误！
    ...
}

Go 不允许方法有额外的类型参数，这是与 C++/Java 泛型的重要区别。

// ✓ 改为包级函数
func TransformerMap[T, U any](
    t Transformer[T],
    f func(T) U) []U {
    result := make([]U, len(t.data))
    for i, v := range t.data {
        result[i] = f(v)
    }
    return result
}

需要额外类型参数的操作改为包级泛型函数，接受类型实例作为参数。
