基础概念

01

🎯Go 的定位与设计目标

Google 设计 Go 来解决大型软件工程的痛点：
· 编译快 — 模块化依赖，无头文件
· 部署简 — 静态链接，单二进制
· 并发原生 — goroutine + channel 是一等公民
· 简洁语法 — 约 25 个关键字，降低协作成本

✨核心特性速览

· 接口隐式满足，无需 implements 声明
· goroutine 初始栈仅 2KB，轻松创建百万级并发
· 无继承，用组合（embedding）实现代码复用
· 错误是普通值，显式处理，不依赖异常机制
· 内置 GC，目标停顿 <1ms（Go 1.14+）

与其他语言对比
vs Java
Go 没有 JVM 热身开销，启动更快；接口隐式满足比 Java 更灵活；但 Go 泛型比 Java 弱，GC 策略不同（低延迟 vs 高吞吐），不适合重 OOP 或复杂继承体系。
vs Python
Go 是编译型，性能高出数十倍；有类型系统，重构安全；并发模型原生。Python 脚本和数据科学更方便，Go 适合对性能和并发有要求的后端服务。
vs C++
Go 有 GC，不需要手动管理内存；编译更快，工具链统一；但运行时性能和底层控制不如 C++，Go 是"够快 + 更安全 + 更易写"的工程折中。
高频 Q & A
goroutine 和 thread 的区别？
goroutine 使用可动态扩缩的小栈，由 Go runtime 采用 M:N 模型调度到较少的 OS thread。栈大小与调度成本是版本相关实现细节；能否承载百万级 goroutine 取决于每个 goroutine 的栈、引用对象和工作负载。
什么时候用 channel，什么时候用 mutex？
传递所有权、协调工作流用 channel；保护共享状态用 mutex。简单计数器、缓存等场景用 mutex 往往更清晰，不要强行 channel。
Go GC 停顿有多长？
Go GC 通过并发标记尽量缩短 STW，但没有适用于所有程序的固定停顿上限，应使用 runtime/metrics、trace 和 profile 实测。GOGC 依据存活堆与 GC roots 调整目标堆大小；降低分配速率和存活对象规模通常更根本。
逃逸分析是什么，为什么重要？
编译器通过逃逸分析决定值更适合放在栈还是堆。返回指针、接口转换、闭包捕获等是常见候选，但并非脱离上下文就必然逃逸；结果取决于生命周期、内联、调用链和编译器版本。用 -gcflags=-m 观察当前构建的决定。
