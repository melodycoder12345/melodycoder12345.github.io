结构体嵌入基础

嵌入语法 vs 命名字段

core

嵌入（embedding）通过省略字段名称只写类型来声明，与普通命名字段的本质区别在于：嵌入会将内层类型的字段和方法提升到外层，可直接访问。

type Animal struct {
    Name string
    Age  int
}

// 命名字段 —— 必须通过 .A. 访问
type DogNamed struct {
    A Animal   // 命名字段
}
d1 := DogNamed{A: Animal{Name: "Rex"}}
_ = d1.A.Name   // 必须显式访问

// 嵌入 —— 字段/方法提升，可直接访问
type Dog struct {
    Animal        // 嵌入，字段名自动为 "Animal"
    Breed string
}
d2 := Dog{Animal: Animal{Name: "Rex"}}
_ = d2.Name     // 提升后直接访问
_ = d2.Animal.Name // 完整路径同样有效

字段与方法提升规则

core

提升（promotion）让外层类型直接拥有内层字段和方法的访问路径，规则如下：

  • 嵌入类型的导出和未导出字段均被提升到外层
  • 外层若有同名字段/方法，则外层优先（shadowing）
  • 同级多个嵌入类型有同名成员时，编译器报ambiguous selector错误，必须通过完整路径消歧
  • 提升是语法糖，底层仍是代理调用，不会复制方法
type Base struct{ ID int }
func (b Base) Describe() string { return fmt.Sprintf("id=%d", b.ID) }

type Ext struct {
    Base
    Extra string
}

e := Ext{Base: Base{ID: 42}}
fmt.Println(e.ID)          // 提升字段
fmt.Println(e.Describe())  // 提升方法

访问路径与字面量初始化

core

结构体字面量初始化嵌入类型时，必须使用类型名作为字段名，不能直接展开内层字段。

type Address struct{ City, Country string }
type Person  struct{ Address; Name string }

// 正确：用类型名作为键
p := Person{
    Name:    "Alice",
    Address: Address{City: "Beijing", Country: "CN"},
}

// 错误：不能直接写 City: "Beijing"
// p2 := Person{Name: "Bob", City: "Shanghai"} // 编译失败

// 赋值时可直接访问提升字段
p.City = "Shanghai"    // 等价于 p.Address.City

方法集与接口满足

嵌入后方法集变化

advanced

Go 规范规定，嵌入类型的方法会被提升到外层类型的方法集，但提升范围取决于嵌入的是值类型还是指针类型：

嵌入方式T 的方法集获得*T 的方法集获得
Inner（值）Inner 的值接收者方法Inner 的值+指针接收者方法
*Inner（指针）Inner 的值+指针接收者方法Inner 的值+指针接收者方法
type W struct{}
func (w  W) ValMethod() {}
func (w *W) PtrMethod() {}

type A struct{ W }   // 嵌入值
type B struct{ *W }  // 嵌入指针

// A 的值类型只有 ValMethod；*A 有两者
// B 的值类型和 *B 都有两者

接口隐式满足

core

通过嵌入提升的方法，可以让外层类型自动满足某个接口，无需重写方法。这是 Go 组合设计的核心实践。

type Stringer interface {
    String() string
}

type Named struct{ Value string }
func (n Named) String() string { return n.Value }

type Tag struct {
    Named       // 提升 String() 方法
    Color string
}

// Tag 自动满足 Stringer，不需要显式声明
var _ Stringer = Tag{}

func Print(s Stringer) { fmt.Println(s.String()) }
func main() {
    Print(Tag{Named: Named{Value: "go"}, Color: "blue"})
}

值接收者 vs 指针接收者嵌入对比

advanced

嵌入值类型时，外层类型的值变量无法访问内层指针接收者方法；而嵌入指针类型时，值变量也可以访问，但需确保指针不为 nil。

type Mutable struct{ Count int }
func (m *Mutable) Inc() { m.Count++ }

type Wrapper struct{ Mutable }

w := Wrapper{}
w.Inc()           // OK: w 可寻址，编译器自动取 &w.Mutable
fmt.Println(w.Count) // 1

// 不可寻址的值不能调用指针接收者方法
// Wrapper{}.Inc() // 编译错误: cannot take address

接口嵌入

接口嵌入接口

core

接口可以嵌入其他接口，组合后的接口要求实现方包含所有嵌入接口的方法集。这是 Go 标准库常用的组合方式。

type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}

// 组合接口：实现者必须同时满足 Reader 和 Writer
type ReadWriter interface {
    Reader
    Writer
}

// 标准库等价：io.ReadWriter, io.ReadWriteCloser 等
type ReadWriteCloser interface {
    Reader
    Writer
    Close() error
}

小接口组合的优势

core

Go 推崇"接口越小越好"（io.Reader 只有1个方法），通过嵌入组合大接口，既保持了接口的原子性，又能按需组合使用。

  • 小接口更易于 mock 和测试
  • 函数参数只声明所需接口，符合最小权限原则
  • 组合接口可按场景扩展，不影响已有实现
  • Go 1.14 起接口嵌入允许重叠方法集（方法签名相同则合并）
// 只需读权限的函数，用小接口
func ParseConfig(r io.Reader) (Config, error) { /* ... */ }

// 需要读写的函数，用组合接口
func Transform(rw io.ReadWriter) error { /* ... */ }

结构体嵌入接口

advanced

结构体可以嵌入接口类型，这让结构体自动满足该接口（但运行时调用未实现的方法会 panic）。常见用法是局部覆盖接口方法，构造测试替身。

type Storage interface {
    Get(key string) string
    Set(key, val string)
}

// 只覆盖 Get，其余方法来自嵌入接口（nil时panic）
type ReadOnlyStub struct {
    Storage                 // 嵌入接口
    data map[string]string
}
func (s *ReadOnlyStub) Get(key string) string {
    return s.data[key]
}
// Set 未覆盖：调用 s.Set() 会 panic（Storage 为 nil）

继承 vs 组合对比

core
维度继承（OOP）Go 嵌入组合
耦合度强耦合，子类依赖父类实现松耦合，可替换内层类型
方法覆盖虚方法 / override外层同名方法遮蔽（shadowing）

方法遮蔽（Shadowing）

advanced

外层类型定义与嵌入类型同名的方法时，外层方法遮蔽内层方法。通过完整路径仍可访问被遮蔽的方法。

type Engine struct{}
func (e Engine) Start() { fmt.Println("Engine starting") }

type Car struct{ Engine }

// Car 覆盖 Start，实现自定义逻辑
func (c Car) Start() {
    fmt.Println("Car: pre-check...")
    c.Engine.Start()  // 调用被遮蔽的内层方法
    fmt.Println("Car: ready")
}

c := Car{}
c.Start()        // 调用 Car.Start
c.Engine.Start() // 调用 Engine.Start

多层嵌入与冲突解决

advanced

多个同级嵌入类型存在同名字段或方法时，Go 编译器报 ambiguous selector，必须使用完整路径。但不同深度时，浅层优先。

type A struct{ X int }
type B struct{ X int }

type C struct{ A; B }  // 同级嵌入，X 冲突
c := C{}
// c.X      // 编译错误: ambiguous selector c.X
c.A.X = 1  // 必须指定路径
c.B.X = 2

// 不同深度：浅层（D.X）遮蔽深层（D.A.X）
type D struct{ A; X string }
d := D{}
d.X = "outer"  // D.X（string），不歧义

实用组合模式

core

通过组合可以实现"Mixin"风格的代码复用：将通用逻辑封装为独立类型，按需嵌入。

// 通用日志能力
type Logger struct{ prefix string }
func (l *Logger) Log(msg string) {
    fmt.Printf("[%s] %s\n", l.prefix, msg)
}

// 通用指标能力
type Metrics struct{ hits int64 }
func (m *Metrics) RecordHit() { atomic.AddInt64(&m.hits, 1) }

// 按需组合
type Service struct {
    *Logger
    *Metrics
    name string
}

svc := &Service{
    Logger:  &Logger{prefix: "svc"},
    Metrics: &Metrics{},
    name:    "auth",
}
svc.Log("started")
svc.RecordHit()

面试题

嵌入和命名字段有何区别？字段提升是什么？ ▶
命名字段（如 A Animal）需要通过 .A. 两级路径访问内部成员，内层字段和方法不会出现在外层类型的方法集中。

嵌入（如 Animal 不带字段名）会将内层的字段和方法"提升"（promote）到外层，可以直接用 .Name 访问，完整路径 .Animal.Name 同样有效。提升是编译器的语法糖，底层仍是代理调用，不会复制方法代码。字段名自动等于类型名（或包含包路径的最后一节）。
嵌入类型的方法集如何影响接口满足？ ▶
嵌入值类型 T：外层值类型获得 T 的值接收者方法集；外层指针类型获得 T 的值+指针接收者方法集。

嵌入指针类型 *T：外层值类型和指针类型均获得 T 的值+指针接收者方法集，但需确保嵌入的指针已初始化（非 nil）。

接口满足是在编译期静态检查的，只要方法集满足接口要求，外层类型就隐式实现了该接口，无需显式声明。
嵌入值类型 vs 嵌入指针类型有什么区别？ ▶
嵌入值类型：内层对象随外层对象一起分配，复制外层时内层也被复制（值语义）；值类型变量只能调用内层值接收者方法（不可寻址时无法调用指针接收者方法）。

嵌入指针类型：内层对象独立分配，外层只持有指针（引用语义）；复制外层仅复制指针，多个外层共享同一内层；值和指针变量都能调用内层的指针接收者方法。风险：若指针未初始化（nil），调用其方法会 panic。
两个嵌入类型有同名方法时如何解决冲突？ ▶
Go 编译器遵循深度优先、浅层优先规则：
1. 若同名成员在不同深度，浅层（外层直接字段/方法）自动优先，无歧义。
2. 若同名成员在同一深度（同级嵌入），编译器报 ambiguous selector 错误。
3. 解决方式：在外层类型中显式定义同名方法（遮蔽），或通过完整路径 outer.EmbedA.Method() 明确调用具体实现。
如何用嵌入实现"继承"，又如何覆盖方法？ ▶
Go 没有继承，但嵌入可以达到相似效果：将"父类"逻辑封装为独立类型，"子类"嵌入它，从而复用字段和方法。

覆盖方法：在外层类型中定义与嵌入类型同名的方法，外层方法会遮蔽内层。若需在覆盖方法内调用原始逻辑，通过完整路径 s.EmbedType.Method() 显式调用即可，类似 OOP 的 super.Method()。

易错点

✗ 嵌入指针类型未初始化，调用方法 nil panic
type Logger struct{ level int }
func (l *Logger) Log(s string) {
    fmt.Println(l.level, s)
}

type Svc struct{ *Logger }

s := Svc{}     // Logger 为 nil
s.Log("hi")  // panic: nil pointer

嵌入指针类型时，若未在初始化时赋值，内层指针为 nil，调用任何方法都会触发 nil pointer dereference。

type Logger struct{ level int }
func (l *Logger) Log(s string) {
    fmt.Println(l.level, s)
}

type Svc struct{ *Logger }

// 初始化时提供非 nil 指针
s := Svc{Logger: &Logger{level: 1}}
s.Log("hi")  // OK

嵌入指针类型时，务必在构造时初始化内层指针，或使用构造函数确保非 nil。

✗ 误以为嵌入会把方法"复制"到外层类型
type Base struct{ val int }
func (b *Base) Double() { b.val *= 2 }

type Outer struct{ Base }

o := Outer{Base: Base{val: 3}}
o.Double() // 修改的是 o.Base.val
// o.val 不存在！修改的仍是内层 Base

嵌入方法并未生成新的方法体，调用 o.Double() 实际上是 (&o.Base).Double() 的语法糖，接收者是内层 Base，不是 Outer。

// 若需要 Outer 自己的行为，显式定义
func (o *Outer) Double() {
    // 可在调用前后添加 Outer 级别逻辑
    o.Base.Double()
}

// 或直接操作 Outer 特有字段
type Outer2 struct {
    Base
    multiplier int
}
func (o *Outer2) Scale() {
    o.val *= o.multiplier // 提升访问
}

理解嵌入是代理调用而非复制，有助于正确设计数据修改和接收者选择。

✗ 外层同名方法遮蔽内层，导致接口满足失效
type Stringer interface{ String() string }

type Inner struct{ V string }
func (i Inner) String() string { return i.V }

type Outer struct{ Inner }
// 不小心定义了返回值不同的 String
func (o Outer) String() int { return 0 }

// Outer 不再满足 Stringer！
// var _ Stringer = Outer{} // 编译错误

外层定义了与内层同名但签名不同的方法，会遮蔽内层方法，导致通过嵌入获得的接口满足失效。

// 解决：保持签名一致，或不定义同名方法
type Outer struct{ Inner }

// 若要扩展，保持相同签名
func (o Outer) String() string {
    return "Outer: " + o.Inner.String()
}

// 用编译期断言确保接口满足
var _ Stringer = Outer{}

fmt.Println(Outer{
    Inner: Inner{V: "hello"},
}.String()) // "Outer: hello"

使用编译期断言 var _ Interface = Type{} 可以在编译阶段捕获此类错误。
