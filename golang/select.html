面试题

select 多个 case 同时就绪时如何选择？▶
当多个通信 case 同时可执行时，规范要求以均匀伪随机方式选择一个。select 不按书写顺序设置优先级，但这不等于严格公平，也不保证某个 case 永远不会饥饿。
select {} 空语句有什么作用？▶
select{} 会永远阻塞当前 goroutine（没有任何 case）。常用于 main 函数结尾让程序保持运行（代替 for{}）。示例：func main() { go server(); select{} }。与 for{} 的区别：空 select 会让出 CPU（调度到其他 goroutine），而空 for 循环会忙等（busy-wait）占用 CPU。
select case 可以发送也可以接收吗？▶
是的，case 可以包含发送操作（case ch <- val）或接收操作（case v := <-ch），以及双值接收（case v, ok := <-ch）。select 会同时评估所有 case 的可用性，选择第一个（随机）可执行的。注意：case 的 channel 表达式在 select 语句开始时就被求值（不是懒求值）。
如何用 select 实现超时控制？▶
方式1（time.After）：select { case v:=<-ch: ... case <-time.After(1*time.Second): return }
方式2（context.WithTimeout，推荐）：传入 ctx，case <-ctx.Done()，可以被外部取消，且不会泄漏 timer goroutine。
注意：time.After 在 select 中每次都创建新 timer，如在循环中使用会导致 timer goroutine 积累（Go 1.23+ 已修复）。
如何用 select 实现非阻塞的 channel 操作？▶
加 default 分支即可实现非阻塞：select { case v:=<-ch: process(v) default: // ch 无数据，立即返回 }
常用场景：① 检查 channel 是否有数据但不阻塞（轮询）；② 尝试发送但不等待（fire-and-forget）；③ tryLock 模式（结合 mutex 实现非阻塞加锁尝试）。

易错点

❌ for-select 中 break 只退出 select
outer:
for {
    select {
    case v := <-ch:
        if v == 0 {
            break // 只退出 select！
            // for 循环继续
        }
    }
}
// 方式1: labeled break
outer:
for {
    select {
    case v := <-ch:
        if v == 0 {
            break outer // 退出 for 循环
        }
    }
}
// 方式2: return（函数中）
// 方式3: done channel

在 for-select 中，break 只退出 select，不退出 for 循环。需要 labeled break 或 return。

❌ time.After 在循环中泄漏 timer
for {
    select {
    case v := <-work:
        process(v)
    case <-time.After(30 * time.Second):
        // 每次循环都创建新 timer！
        // 旧 timer goroutine 直到触发才释放
        cleanup()
    }
}
// 在循环外创建 timer
t := time.NewTimer(30 * time.Second)
defer t.Stop()
for {
    select {
    case v := <-work:
        if !t.Stop() { <-t.C }
        t.Reset(30 * time.Second)
        process(v)
    case <-t.C:
        cleanup()
        t.Reset(30 * time.Second)
    }
}

在循环外创建 Timer 并复用，避免每次循环积累 timer goroutine。

❌ select case 中 channel 求值顺序
// 以为 case 是惰性求值
ch := getChannel() // 返回 nil
select {
case v := <-ch:     // 立即求值 ch！
    // ch 是 nil，这个 case 永不触发
case <-done:
    return
}
// select 开始时所有 channel 表达式立即求值
// 若 ch 是 nil，该 case 永不就绪
// 这其实是禁用 case 的惯用法：

var ch chan int // nil
if condition {
    ch = realChannel
}
select {
case v := <-ch:  // condition 为假时自动跳过
    use(v)
case <-done:
    return
}

nil channel 的 case 永远不就绪，可用来动态禁用 select 分支。
