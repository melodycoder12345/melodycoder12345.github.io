struct tag 与编解码

json tag 核心选项

核心

struct 字段的 json:"..." tag 控制序列化行为。常用选项：

  • json:"name" — 自定义 JSON 字段名（默认用字段名）
  • json:"name,omitempty" — 零值时省略该字段（空字符串、0、false、nil 等）
  • json:"name,string" — 数字类型序列化为 JSON 字符串（适合大整数传前端）
  • json:"-" — 完全忽略该字段，不参与序列化/反序列化
  • json:"-," — 字段名为字面量 -（逗号前是名称）
type User struct {
    ID       int64  `json:"id,string"`       // 序列化为 "id":"123456789"
    Name     string `json:"name"`
    Email    string `json:"email,omitempty"`  // 为空时省略
    Password string `json:"-"`               // 永远不序列化
    Score    int    `json:"score,omitempty"`  // 0 时省略
}

u := User{ID: 123456789, Name: "Alice", Password: "secret"}
data, _ := json.Marshal(u)
// {"id":"123456789","name":"Alice"}
// Email 和 Score 是零值被省略，Password 被忽略

匿名字段嵌入与大小写匹配

核心

匿名嵌入的 struct 字段会被"提升"——其字段直接出现在外层 JSON 对象中，无需嵌套层级。

type Base struct {
    CreatedAt time.Time `json:"created_at"`
    UpdatedAt time.Time `json:"updated_at"`
}

type Article struct {
    Base            // 匿名嵌入，字段被提升
    Title string `json:"title"`
}

// 输出：{"created_at":"...","updated_at":"...","title":"..."}
// 而非：{"Base":{"created_at":"..."},"title":"..."}

反序列化时字段名匹配是大小写不敏感的：JSON 中的 "userid"、"UserID"、"userId" 都能匹配 Go 字段 UserID。但若有精确匹配的 tag，优先使用 tag 匹配。

自定义 Marshal/Unmarshal

实现 json.Marshaler / json.Unmarshaler

进阶

实现 MarshalJSON() ([]byte, error) 和 UnmarshalJSON([]byte) error 接口即可完全控制编解码逻辑。常见用途：特殊时间格式、枚举字符串化、敏感字段加密。

type MyTime struct { time.Time }

// 自定义时间格式序列化
func (t MyTime) MarshalJSON() ([]byte, error) {
    formatted := t.Format(`"2006-01-02 15:04:05"`)
    return []byte(formatted), nil
}

// 自定义反序列化
func (t *MyTime) UnmarshalJSON(data []byte) error {
    s := strings.Trim(string(data), `"`)
    parsed, err := time.Parse("2006-01-02 15:04:05", s)
    if err != nil { return err }
    t.Time = parsed
    return nil
}

自定义枚举类型序列化

进阶

将整数枚举序列化为可读字符串，反序列化时再映射回整数，比直接暴露数字更友好。

type Status int

const (
    StatusActive   Status = 1
    StatusInactive Status = 2
)

var statusNames = map[Status]string{
    StatusActive:   "active",
    StatusInactive: "inactive",
}

func (s Status) MarshalJSON() ([]byte, error) {
    name, ok := statusNames[s]
    if !ok { return nil, fmt.Errorf("unknown status: %d", s) }
    return json.Marshal(name)  // 序列化为 "active"
}

func (s *Status) UnmarshalJSON(data []byte) error {
    var name string
    if err := json.Unmarshal(data, &name); err != nil { return err }
    for k, v := range statusNames {
        if v == name { *s = k; return nil }
    }
    return fmt.Errorf("unknown status: %s", name)
}

流式 Decoder/Encoder

json.Decoder 处理大文件与 HTTP 响应

核心

json.Unmarshal 需要先将整个 JSON 读入内存再解析；json.NewDecoder 可以边读边解析，适合 HTTP response body、大文件、NDJSON（每行一个 JSON）等场景。

// 解析 HTTP 响应（推荐方式）
func decodeResponse(resp *http.Response) (User, error) {
    defer resp.Body.Close()
    var u User
    dec := json.NewDecoder(resp.Body)
    dec.DisallowUnknownFields()  // 严格模式：未知字段报错
    if err := dec.Decode(&u); err != nil {
        return User{}, err
    }
    return u, nil
}

// 逐行解析 NDJSON（newline-delimited JSON）
func parseNDJSON(r io.Reader) {
    dec := json.NewDecoder(r)
    for dec.More() {  // 是否还有更多 JSON 值
        var item map[string]interface{}
        if err := dec.Decode(&item); err != nil { break }
        // 处理每条记录...
    }
}

UseNumber 避免 float64 精度损失

进阶

JSON 解码到 interface{} 时，数字默认被解析为 float64；绝对值超过 2^53 的整数不能保证逐个整数都可精确表示（2^53 本身仍可精确表示）。UseNumber() 让数字保持为 json.Number 文本形式，按需转换。

data := []byte(`{"id": 9007199254740993}`)  // 超过 float64 精度

// 默认方式：精度丢失
var m1 map[string]interface{}
json.Unmarshal(data, &m1)
fmt.Println(m1["id"])  // 9.007199254740992e+15（精度错误）

// UseNumber：保留原始精度
var m2 map[string]interface{}
dec := json.NewDecoder(bytes.NewReader(data))
dec.UseNumber()
dec.Decode(&m2)
n := m2["id"].(json.Number)
fmt.Println(n.String())  // "9007199254740993" ✓
i64, _ := n.Int64()     // 转 int64

常见操作与性能

json.RawMessage 延迟解析

核心

json.RawMessage 是 []byte 的别名，可以将 JSON 某个字段先原样保留，后续按需解析。适合字段类型未知、或需要转发原始 JSON 的场景。

type Response struct {
    Code int              `json:"code"`
    Data json.RawMessage `json:"data"`  // 暂不解析
}

body := []byte(`{"code":200,"data":{"user":"Alice","score":99}}`)
var resp Response
json.Unmarshal(body, &resp)

// 根据 code 决定如何解析 data
if resp.Code == 200 {
    var user struct{ User string; Score int }
    json.Unmarshal(resp.Data, &user)
}

高性能库对比

性能

标准库 encoding/json 使用反射，性能有限。高并发场景可考虑以下替代方案：

库原理性能（相对标准库）兼容性
encoding/json反射基准（1x）完全兼容
json-iterator/go反射优化 + codegen~3-4xAPI 兼容
bytedance/sonicJIT codegen (amd64)~6-10xAPI 兼容，仅 x86
go-json预编译 + 无反射~4-6xAPI 兼容
tidwall/gjson路径查询，不反序列化极快（只读）不同 API
// sonic：字节码替换标准库（仅需改 import）
import "github.com/bytedance/sonic"

data, _ := sonic.Marshal(obj)
sonic.Unmarshal(data, &obj)

// gjson：快速读取嵌套字段，无需定义 struct
import "github.com/tidwall/gjson"

name := gjson.Get(jsonStr, "user.profile.name").String()
age  := gjson.Get(jsonStr, "user.age").Int()

面试题

json.Marshal 处理 nil pointer 和 nil slice 有何不同？▶
nil pointer：序列化为 JSON 的 null。
nil slice：同样序列化为 null，而 空 slice（[]T{}） 序列化为 []。

这一区别在 API 响应中很重要：前端收到 null 和 [] 行为不同。
如果要确保空集合序列化为 []，需要初始化为 make([]T, 0) 或 []T{}，而不是声明后不赋值。

var s []int → null
s := []int{} → []
s := make([]int, 0) → []
如何控制字段在序列化时的名称和行为？▶
通过 struct tag json:"..." 控制：
• json:"fieldName"：自定义 JSON key
• json:"fieldName,omitempty"：零值时省略（注意：空 struct 不算零值，omitempty 对 struct 类型无效）
• json:"fieldName,string"：数字/bool 序列化为带引号的字符串
• json:"-"：完全排除该字段

若字段没有 json tag，Go 默认使用字段名（大驼峰），反序列化时大小写不敏感匹配。
未导出字段（小写开头）不论有无 tag 都会被忽略，且不报错。
json.Decoder 和 json.Unmarshal 各自适合什么场景？▶
json.Unmarshal(data, &v)：适合已经将 JSON 完整加载到内存的场景（[]byte 已就绪）。简洁直接，一行完成。

json.NewDecoder(r).Decode(&v)：适合从 io.Reader 流式读取，如：
• HTTP request/response body（避免 ioutil.ReadAll 先读全部）
• 读取大 JSON 文件（内存效率高）
• 解析多个连续 JSON 对象（NDJSON），用 More() 循环读取

此外 Decoder 支持 DisallowUnknownFields() 和 UseNumber() 等选项，Unmarshal 不直接支持（需要通过 Decoder 间接实现）。
如何解析一个 JSON 中字段类型未知的字段（动态 JSON）？▶
三种方案：

1. 解码到 map[string]interface{}：灵活，但需要类型断言，数字默认为 float64（用 UseNumber() 改善）

2. json.RawMessage：先保留原始字节，根据其他字段的值再决定如何解析。适合 discriminated union 模式（如根据 "type" 字段决定 "data" 的结构）

3. gjson/jq 风格路径查询：只提取需要的字段，不完整反序列化整个结构。适合只读、字段稀疏的场景

生产中最常见的是方案 2：先解析外层已知字段 + RawMessage，再对 RawMessage 二次解析。
为什么大数字通过 interface{} 反序列化会精度损失？如何解决？▶
JSON 规范不区分整数和浮点数，Go 标准库在解码到 interface{} 时统一使用 float64 存储数字。
IEEE 754 binary64 有 53 位有效精度，安全整数范围是 −(2^53−1) 到 2^53−1；2^53 = 9007199254740992 本身可精确表示，但从该量级开始相邻整数不再都能表示，雪花 ID、数据库 bigint 等可能丢失低位精度。

解决方案：
1. json.Decoder.UseNumber()：数字保存为 json.Number（字符串），按需调用 .Int64() 或 .Float64()
2. 使用强类型 struct，将字段声明为 int64（而非 interface{}），标准库会正确解析
3. 使用 json:"id,string" tag，让前端以字符串形式传递大整数，避免 JS 端也丢精度

易错点

❌ 未导出字段（小写）被忽略，不会报错
type Config struct {
    Host    string `json:"host"`
    port    int    `json:"port"`  // 小写！
    timeout int    // 小写且无 tag
}

c := Config{Host: "localhost", port: 8080}
data, _ := json.Marshal(c)
// 输出：{"host":"localhost"}
// port 和 timeout 消失，无任何错误！

小写字段在 JSON 编解码中完全不可见，也不报错，极易导致数据静默丢失。

type Config struct {
    Host    string `json:"host"`
    Port    int    `json:"port"`    // 大写
    Timeout int    `json:"timeout"` // 大写
}

c := Config{Host: "localhost", Port: 8080}
data, _ := json.Marshal(c)
// {"host":"localhost","port":8080,"timeout":0}

需要参与 JSON 编解码的字段必须大写（导出），用 tag 控制 JSON key 名称。

❌ omitempty 对结构体不起作用（零值 struct 不会省略）
type Address struct {
    City  string `json:"city"`
}
type User struct {
    Name string  `json:"name"`
    Addr Address `json:"addr,omitempty"`
}

u := User{Name: "Alice"}
data, _ := json.Marshal(u)
// {"name":"Alice","addr":{"city":""}}
// Addr 是零值 struct，但未被省略！

omitempty 对 struct 类型的"零值"不生效，空 struct 依然会被序列化。

type User struct {
    Name string   `json:"name"`
    Addr *Address `json:"addr,omitempty"`
}

// 使用指针：nil 指针会被 omitempty 省略
u := User{Name: "Alice"}  // Addr 为 nil
data, _ := json.Marshal(u)
// {"name":"Alice"}  ✓

将 struct 字段改为指针类型，nil 指针会被 omitempty 正确省略。

❌ 数字默认解码为 float64，大整数精度丢失
data := []byte(`{"id":9007199254740993}`)
var m map[string]interface{}
json.Unmarshal(data, &m)
// m["id"] 类型是 float64
fmt.Println(m["id"])
// 9.007199254740992e+15（末位精度错误）

雪花ID、数据库 bigint 等大整数解码到 interface{} 时精度丢失，且无警告。

// 方案1：UseNumber 保留原始字符串
dec := json.NewDecoder(bytes.NewReader(data))
dec.UseNumber()
var m map[string]interface{}
dec.Decode(&m)
m["id"].(json.Number).Int64() // ✓

// 方案2：强类型 struct
var s struct{ ID int64 `json:"id"` }
json.Unmarshal(data, &s) // 直接解码为 int64 ✓

用 UseNumber() 或强类型 struct 避免 float64 精度问题。
