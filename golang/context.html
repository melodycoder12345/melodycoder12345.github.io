面试题

context.Background() 和 context.TODO() 的区别？▶
两者在功能上完全相同（都是空 context，不可取消、无截止时间、无值），区别在于语义：
Background()：程序入口点使用，作为整个 context 树的根
TODO()：不知道该用哪个 context 时暂时使用，意味着"需要后续重构"
实践中：main、init、test 用 Background()，接口内部临时用 TODO()。
context 的取消信号如何传播？▶
取消信号单向向下传播：父 context 取消时，所有派生自它的子 context（及其子孙）都会被取消。子 context 取消不影响父 context。内部实现：每个 cancelCtx 维护一个 children map，取消时遍历所有子 context 调用 cancel()。时间复杂度 O(n)，n 为子孙数量。
WithValue 在实际项目中应该存什么？▶
只存请求作用域的横切关注点（cross-cutting concerns）：
✅ request-id、trace-id、user-id（来自中间件、需要传递给所有层）
✅ 认证信息（user 对象、权限）
❌ 不存可选参数（应该是函数参数）
❌ 不存数据库连接、logger（应该是依赖注入）
键要使用私有类型（非 string/int），防止不同包的 key 冲突。
如何检查 context 是否已取消？▶
方式1 — 非阻塞检查（适合循环中）：select { case <-ctx.Done(): return ctx.Err() default: }
方式2 — 阻塞等待取消：<-ctx.Done()
检查取消原因：ctx.Err() 返回 context.Canceled（主动取消）或 context.DeadlineExceeded（超时）。
标准库函数大多接受 ctx 并在循环中检查 ctx.Done()，推荐在 IO 密集型代码中也这样做。
WithTimeout 和 WithDeadline 的关系？▶
WithTimeout(ctx, d) 是 WithDeadline(ctx, time.Now().Add(d)) 的语法糖。两者功能相同，区别在于指定时间的方式（相对时间 vs 绝对时间）。
两者都返回 cancel 函数，必须 defer cancel() 确保资源释放，即使在超时发生后也需要调用（清理 timer）。Deadline() 方法可以查询截止时间及是否设置了截止时间。

易错点

❌ 将 context 存储在结构体中
type Server struct {
    ctx context.Context  // 错误！
    db  *sql.DB
}

func (s *Server) Handle(r *Request) {
    // 使用 s.ctx，但此 ctx 可能
    // 是程序启动时的 ctx，不是
    // 当前请求的 ctx
    s.db.QueryContext(s.ctx, ...)
}
type Server struct {
    db *sql.DB  // 只存依赖，不存 ctx
}

func (s *Server) Handle(
    ctx context.Context,  // 每次传入
    r *Request) {
    // ctx 是当前请求的 context
    // 包含正确的超时和取消信号
    s.db.QueryContext(ctx, ...)
}

context 应该作为函数的第一个参数显式传递，不要存储在结构体中（Go 官方准则）。

❌ 用 string 作为 WithValue 的 key
// 危险：任何包都能读取 "userID"
ctx = context.WithValue(ctx,
    "userID", user.ID)

// 另一个包可能用相同字符串 key
// 导致 key 冲突或意外读取
v := ctx.Value("userID")
// 使用包内私有类型作为 key
type ctxKey int
const userIDKey ctxKey = iota

func WithUserID(ctx context.Context,
    id int64) context.Context {
    return context.WithValue(ctx, userIDKey, id)
}
func UserIDFromCtx(ctx context.Context) int64 {
    v, _ := ctx.Value(userIDKey).(int64)
    return v
}

自定义不可导出类型作为 key，确保类型安全且不与其他包冲突。

❌ 传递 nil context
func fetch(ctx context.Context) {
    resp, err := http.Get(url)
    // 忘记传 ctx，或传 nil
}

// 调用时传 nil
fetch(nil) // panic: nil context
// 永远不要传 nil context
// 如果不确定用哪个，用 Background() 或 TODO()
func fetch(ctx context.Context) {
    req, _ := http.NewRequestWithContext(
        ctx, "GET", url, nil)
    http.DefaultClient.Do(req)
}

// 调用
fetch(context.Background())

不知道用什么 context 时，用 context.TODO() 作为占位符，而不是 nil。
