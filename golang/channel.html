面试题

无缓冲 channel 和有缓冲 channel 有什么区别？▶
无缓冲 channel 发送和接收必须同时就绪，否则阻塞（同步语义）。有缓冲 channel 在缓冲区未满时发送不阻塞，缓冲区为空时接收阻塞（异步语义）。无缓冲适合 goroutine 间握手/同步，有缓冲适合削峰填谷。
向 closed channel 发送数据会发生什么？▶
panic: send on closed channel。关闭 channel 的原则：只由发送方关闭，不要由接收方关闭。常用 done channel 或 context 来通知 goroutine 退出，而不是在接收方关闭 channel。
如何判断 channel 已被关闭？▶
使用双值接收 v, ok := <-ch，ok 为 false 表示 channel 已关闭且缓冲区为空。也可用 for v := range ch 自动在关闭后退出循环。不能用 close() 检测是否关闭（只能关一次）。
select 的 case 选择规则是什么？▶
当多个 case 同时就绪时，Go runtime 随机选择一个执行（伪随机，防止饥饿）。有 default 时，若所有 channel 都未就绪立即走 default（非阻塞）。没有 default 且无 case 就绪则阻塞等待。
channel 的底层数据结构是什么？▶
runtime.hchan 结构体，核心字段：
• buf：循环队列指针（有缓冲时）
• sendq / recvq：等待发送/接收的 goroutine 队列（sudog 链表）
• lock：互斥锁
• closed：是否关闭标志
发送/接收时先检查对端等待队列，直接拷贝绕过缓冲区（zero-copy fast path）。
nil channel 发送/接收/在 select 中的行为？▶
向 nil channel 发送或接收会永远阻塞。在 select 中，nil channel 的 case 永远不会被选中——这是一个实用技巧：动态禁用某个 case 时将其 channel 设为 nil。

易错点

❌ 接收方关闭 channel
// 消费者关闭，生产者不知道
func consumer(ch chan int) {
    for v := range ch {
        process(v)
    }
    close(ch) // 危险！
}
func producer(ch chan int) {
    ch <- 1  // panic if closed
// 生产者负责关闭
func producer(ch chan int) {
    defer close(ch)
    for _, v := range data {
        ch <- v
    }
}
func consumer(ch chan int) {
    for v := range ch { // 自动退出
        process(v)
    }
}

原则：发送方拥有 channel 的生命周期，接收方通过 range 或 ok 检测关闭。

❌ goroutine 泄漏：发送阻塞
func work() <-chan int {
    ch := make(chan int)
    go func() {
        ch <- heavyWork() // 若调用方
        // 放弃接收，这里永远阻塞
    }()
    return ch
}
// 调用方提前 return，goroutine 泄漏
func work(ctx context.Context) <-chan int {
    ch := make(chan int, 1) // 缓冲1
    go func() {
        select {
        case ch <- heavyWork():
        case <-ctx.Done(): // 可取消
        }
    }()
    return ch
}

方案：用带缓冲 channel 或 context 取消来防止 goroutine 泄漏。

❌ for-select 忘记退出条件
for {
    select {
    case v := <-ch:
        process(v)
    // 没有退出条件，永远循环
    }
}
for {
    select {
    case v, ok := <-ch:
        if !ok { return } // ch 关闭退出
        process(v)
    case <-ctx.Done():
        return // context 取消退出
    }
}

总是在 for-select 中加上 context 或 done channel 的退出分支。

❌ 缓冲满导致发送方死锁
ch := make(chan int, 2)
ch <- 1
ch <- 2
ch <- 3 // 死锁！缓冲已满
// 没有接收方消费
ch := make(chan int, 2)
go func() {
    for v := range ch {
        process(v)
    }
}()
ch <- 1
ch <- 2
ch <- 3 // 正常，消费者在消费
close(ch)

有缓冲 channel 不是无限队列，满了仍会阻塞发送方。
