面试题

pipeline 模式的优势是什么？▶
① 流式处理：数据不需要完全加载到内存，逐步处理（低内存）
② 并发：各阶段 goroutine 并行运行，充分利用多核
③ 可组合：每个阶段是独立函数，签名统一（接收/返回 channel），易于测试和替换
④ 背压：有缓冲 channel 自动控制流速，下游慢时上游自动减速
fan-out/fan-in 解决什么问题？▶
Fan-out：将单一输入分发给多个 goroutine 并行处理（加速 CPU 密集或 IO 密集任务）。
Fan-in：将多个 channel 的输出合并到一个 channel，供下游串行消费。
典型用途：并行爬虫、并行文件处理、并行 API 调用后汇总结果。
Fan-in 通常用 goroutine + WaitGroup 或 select 实现。
worker pool 的适用场景和注意事项？▶
适用：限制并发数（防止爆内存/爆连接数）、复用重型资源（DB 连接）、限流控制。
注意：
① worker 数量不是越多越好，CPU 密集任务通常 = GOMAXPROCS
② job channel 关闭是 worker 退出的信号，用 range 接收
③ 收集结果时 result channel 容量需足够，或用单独 goroutine 消费，防止 worker 阻塞
④ errgroup 可简化带错误处理的 worker pool
如何在 pipeline 中处理错误？▶
方案1 — 携带错误的数据结构：type Result struct { Val T; Err error }，每个阶段传递 Result channel，下游检查 Err。
方案2 — errgroup：golang.org/x/sync/errgroup 管理 goroutine 组，第一个错误会取消所有其他 goroutine（通过 context）。
方案3 — done channel：ctx.Done() 通知所有阶段停止生产，防止 goroutine 泄漏。

易错点

❌ pipeline 中忘记关闭上游 channel
func generate(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        for _, n := range nums {
            out <- n
        }
        // 忘记 close(out)！
        // 下游 range 永远阻塞
    }()
    return out
}
func generate(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out) // 关键！
        for _, n := range nums {
            out <- n
        }
    }()
    return out
}
// defer close 确保即使 panic 也能关闭

每个 pipeline 阶段的生产者必须在完成后关闭 output channel，否则下游 range 死锁。

❌ worker pool 结果 channel 容量不足死锁
results := make(chan int) // 无缓冲！
for i := 0; i < numWorkers; i++ {
    go worker(jobs, results)
}
// workers 向 results 发送，但主线程
// 还没开始接收 → 所有 worker 阻塞
// 死锁！
for r := range results { // 永远等不到
    process(r)
}
// 方案1: 足够缓冲
results := make(chan int, numJobs)

// 方案2: 先启动接收者 goroutine
go func() {
    for r := range results {
        process(r)
    }
}()

// 方案3: 用 sync.WaitGroup 关闭 results
var wg sync.WaitGroup
// ... wg.Add/Done/Wait + close(results)

确保 result channel 有足够缓冲，或先启动消费者，再启动 worker。
