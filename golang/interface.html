隐式满足（Duck Typing）

不需要 implements 关键字

核心

Go 的接口是隐式实现的——只要某类型拥有接口要求的所有方法，它就自动实现了该接口，无需任何显式声明。这是 Go 与 Java/C# 等语言的重要区别。

type Animal interface {
    Sound() string
    Name() string
}

type Dog struct{}

// Dog 不需要写 "implements Animal"
// 只要拥有 Sound() 和 Name() 方法就满足接口
func (d Dog) Sound() string { return "Woof" }
func (d Dog) Name() string  { return "Dog" }

var a Animal = Dog{}  // 自动满足 Animal 接口

// 编译时验证接口实现（惯用法）
var _ Animal = (*Dog)(nil)

接口方法集规则：值类型 T 的方法集只包含值接收者方法；指针类型 *T 的方法集包含值接收者和指针接收者的所有方法。

iface vs eface 内存布局

接口的运行时表示

进阶

接口值在运行时占 16 字节，包含两个指针：

iface（有方法的接口）

tab *itab类型+方法表
data unsafe.Pointer指向具体值

eface（空接口 interface{}）

_type *_type类型信息
data unsafe.Pointer指向具体值
// itab 结构（简化）
type itab struct {
    inter *interfacetype  // 接口类型信息
    _type *_type         // 具体类型信息
    hash  uint32          // 类型哈希（用于类型断言）
    fun   [1]uintptr      // 方法地址表（动态分发）
}

itab 会被缓存（itabTable），同一 (接口类型, 具体类型) 对只创建一次，避免重复计算。类型断言时通过比较 itab 指针或 hash 来判断类型。

nil interface 陷阱

(*T)(nil) != nil 的经典陷阱

核心

interface 值只有在 type 和 value 都为 nil 时，整个 interface 才等于 nil。如果只有 value 是 nil，但 type 字段非空，则 interface != nil。

type MyError struct{ msg string }
func (e *MyError) Error() string { return e.msg }

// 错误示例：返回具体类型的 nil 指针
func badFunc() error {
    var err *MyError = nil
    return err  // 接口持有 (type=*MyError, value=nil)
}

err := badFunc()
fmt.Println(err == nil)  // false ！！！
fmt.Println(err)          // <nil>

// 正确：直接返回 nil
func goodFunc() error {
    return nil  // interface 的 type 和 value 都为 nil
}

接口嵌入与组合

io.ReadWriter 等组合接口

进阶

接口可以嵌入其他接口，形成更大的接口。实现组合接口的类型必须实现所有嵌入接口的方法。

// io 包的经典组合
type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}
// 嵌入组合
type ReadWriter interface {
    Reader  // 嵌入 Reader
    Writer  // 嵌入 Writer
}

// 自定义组合
type Stringer interface {
    String() string
}
type Named interface {
    Stringer
    Name() string
}

接口设计原则：接口越小越好（最小接口原则）。io.Reader、io.Writer 只有一个方法，组合性极强。设计时优先用小接口组合，而非大而全的接口。

面试题

nil interface 和含 nil 指针的 interface 区别？▶
接口值包含两个字段：(type, value)。
• nil interface：type == nil && value == nil，整个接口 == nil
• 含 nil 指针的 interface：type != nil（有具体类型）但 value == nil（指针为空），整个接口 != nil

这是 Go 中最著名的陷阱之一。最常见场景是函数返回 error 接口时，不要返回具体类型的 nil 指针，要直接 return nil。
interface{} 和 any 有什么区别？▶
没有区别。Go 1.18 引入 any 作为 interface{} 的内置别名（type any = interface{}），完全等价，可以互换使用。

Go 标准库和新代码推荐使用 any，更简洁。老代码中的 interface{} 无需修改，两者可以混用。
接口方法集规则：值接收者和指针接收者的区别？▶
方法集规则：
• 类型 T 的方法集：只包含值接收者定义的方法
• 类型 *T 的方法集：包含值接收者和指针接收者定义的所有方法

实践含义：如果接口的方法用指针接收者实现，必须用 *T 赋值给接口，不能用 T：
var r io.Reader = &myReader{}（正确）
var r io.Reader = myReader{}（如果 Read 是指针接收者，编译错误）
接口的动态分发（dynamic dispatch）是如何实现的？▶
接口方法调用通过 itab 中的 fun 函数指针表实现间接调用（类似 C++ vtable）。调用流程：
1. 从接口值取出 itab 指针
2. 从 itab.fun 数组中找到对应方法的函数指针（按接口方法排序）
3. 间接调用该函数，传入 data 指针作为第一个参数（即 receiver）

与直接调用相比，接口调用多一次内存读（load itab）和一次间接跳转，在热路径上可能有影响，但通常可以忽略。如果需要极致性能，可以用泛型或 type switch 替代。
如何在编译时检查某类型是否实现了某接口？▶
Go 惯用法：使用空赋值触发编译时接口检查：
var _ io.Reader = (*MyReader)(nil)
或：var _ io.Reader = MyReader{}

这行代码本身不占运行时资源（空标识符丢弃值，nil 不会实际分配），只是让编译器验证接口是否被满足。如果未满足，编译时立刻报错。通常放在 struct 定义附近，作为文档和编译保证。

易错点

❌ 返回 (*T)(nil) 赋给 interface，导致 != nil
type MyErr struct{}
func (e *MyErr) Error() string { return "" }

func doSomething() error {
    var e *MyErr
    if someCondition {
        e = &MyErr{}
    }
    return e  // ❌ 即使 e==nil 也返回非nil error
}

即使 someCondition 为 false，返回的 error 接口不为 nil。

func doSomething() error {
    if someCondition {
        return &MyErr{}
    }
    return nil  // ✓ 直接返回 nil
}

// 调用方可以正确判断
err := doSomething()
if err != nil {  // 正确工作
    log.Fatal(err)
}

返回错误接口时，正常情况直接 return nil，不要先声明具体类型变量再返回。

❌ 值类型实现指针接收者方法，无法赋给接口
type Counter struct{ n int }

// 指针接收者方法
func (c *Counter) Inc() { c.n++ }

type Incer interface{ Inc() }

var i Incer = Counter{}
// 编译错误：Counter 的方法集不包含
// 指针接收者方法 Inc

值类型的方法集不包含指针接收者方法，只有指针类型才包含。

// 正确：用指针类型赋给接口
var i Incer = &Counter{}  // ✓

// 或者改用值接收者方法
func (c Counter) Inc() { /* 但无法修改 c.n */ }

// 编译时检查接口实现
var _ Incer = (*Counter)(nil)

规则记忆：方法需要修改 receiver 时用指针接收者，接口变量用 &T。

❌ 空接口和具体类型的类型断言未做 ok 检查
func process(v any) {
    // 单值断言：失败时 panic
    s := v.(string)
    fmt.Println(s)
}

process(42)
// panic: interface conversion:
// interface {} is int, not string

不检查 ok 的类型断言失败时直接 panic。

func process(v any) {
    // 两值断言：安全
    s, ok := v.(string)
    if !ok {
        fmt.Println("not a string")
        return
    }
    fmt.Println(s)
}

// 或用 type switch 处理多类型
switch x := v.(type) {
case string: ...
case int: ...
}

始终用两值形式的类型断言，或用 type switch 处理多种类型。
