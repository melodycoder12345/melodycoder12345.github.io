reflect.Type 与 reflect.Value

TypeOf 与 ValueOf 基础

core

reflect.TypeOf(x) 返回 reflect.Type 接口，描述 x 的静态类型信息（类型名、方法集等）；reflect.ValueOf(x) 返回 reflect.Value 结构体，封装 x 的具体值，可进行读取、修改和调用操作。

import "reflect"

type Point struct{ X, Y float64 }

p := Point{1.0, 2.0}

t := reflect.TypeOf(p)
fmt.Println(t.Name())       // "Point"
fmt.Println(t.Kind())       // struct
fmt.Println(t.NumField())  // 2

v := reflect.ValueOf(p)
fmt.Println(v.Field(0).Float()) // 1.0
fmt.Println(v.FieldByName("Y").Float()) // 2.0

Kind vs Type 的区别

core

Type 是具体的命名类型（如 main.Point、int、[]string），Kind 是底层的类型种类（如 struct、int、slice），是一组有限枚举值。

type MyInt int
v := reflect.ValueOf(MyInt(5))
fmt.Println(v.Type())       // main.MyInt
fmt.Println(v.Kind())       // int
fmt.Println(v.Kind() == reflect.Int) // true

reflect.DeepEqual

core

reflect.DeepEqual 递归比较两个值是否"深度相等"，可处理 map、slice、struct 等复合类型。常用于测试断言，但有一些语义陷阱需要注意。

  • nil slice 和 空 slice（[]int{}）不相等
  • nil map 和 空 map 不相等
  • 函数值只有两个都为 nil 时才相等
  • 循环引用的结构可能无限递归（DeepEqual 内部有循环检测）
reflect.DeepEqual([]int{1,2}, []int{1,2}) // true
reflect.DeepEqual([]int{}, ([]int)(nil))    // false! 注意

var a, b map[string]int
reflect.DeepEqual(a, b)                // true (both nil)
reflect.DeepEqual(a, map[string]int{}) // false!

读取与修改值

Value.Field / Method / Interface

core

通过 reflect.Value 可以枚举和访问结构体字段、调用方法、提取原始值。

type User struct {
    Name string `json:"name"`
    Age  int    `json:"age"`
}
func (u User) Greet() string { return "Hi, " + u.Name }

u := User{Name: "Alice", Age: 30}
v := reflect.ValueOf(u)
t := reflect.TypeOf(u)

// 遍历字段
for i := 0; i < t.NumField(); i++ {
    f := t.Field(i)
    fmt.Printf("%s = %v (tag:%s)\n",
        f.Name, v.Field(i), f.Tag.Get("json"))
}

// 调用方法
m := v.MethodByName("Greet")
res := m.Call(nil)
fmt.Println(res[0].String()) // "Hi, Alice"

// 提取原始值
name := v.FieldByName("Name").Interface().(string)

可设置性与 CanSet

advanced

修改值的前提：Value.CanSet() 返回 true。要让 Value 可设置，必须通过指针取反射，并调用 Elem() 解引用，且字段必须是导出的。

type Config struct {
    Host    string
    Port    int
    timeout int // 未导出
}

cfg := Config{Host: "localhost", Port: 8080}

// 必须传指针
v := reflect.ValueOf(&cfg).Elem()

fmt.Println(v.CanSet()) // true

v.FieldByName("Host").SetString("0.0.0.0")
v.FieldByName("Port").SetInt(9090)
fmt.Println(cfg) // {0.0.0.0 9090 0}

// 未导出字段无法设置
tf := v.FieldByName("timeout")
fmt.Println(tf.CanSet()) // false
// tf.SetInt(30) // panic: unexported field

动态创建与修改 Slice/Map

advanced

反射可以动态创建和操作 slice、map，在泛型化框架（如 ORM、序列化）中很有用。

// 动态创建 slice
sliceType := reflect.TypeOf([]int{})
s := reflect.MakeSlice(sliceType, 0, 3)
s = reflect.Append(s, reflect.ValueOf(10))
s = reflect.Append(s, reflect.ValueOf(20))
fmt.Println(s.Interface()) // [10 20]

// 动态创建 map
mapType := reflect.MapOf(
    reflect.TypeOf(""),
    reflect.TypeOf(0),
)
m := reflect.MakeMap(mapType)
m.SetMapIndex(
    reflect.ValueOf("key"),
    reflect.ValueOf(42),
)
fmt.Println(m.Interface()) // map[key:42]

利用反射读取 struct tag

core

Struct tag 是 Go 序列化（JSON/XML/ORM）的基础。反射可以在运行时读取 tag，实现字段映射和验证逻辑。

type Article struct {
    Title   string `json:"title"   db:"title"   validate:"required"`
    Content string `json:"content" db:"content"`
    Views   int    `json:"-"       db:"views"`
}

t := reflect.TypeOf(Article{})
for i := 0; i < t.NumField(); i++ {
    f := t.Field(i)
    jsonTag := f.Tag.Get("json")
    dbTag   := f.Tag.Get("db")
    fmt.Printf("Field: %-8s json:%-8s db:%s\n",
        f.Name, jsonTag, dbTag)
}

类型断言与 type switch

单值断言 vs 双值断言

core

类型断言从接口值中提取具体类型。单值形式在类型不匹配时直接 panic；双值形式通过 ok 安全检查，推荐在类型不确定时使用。

var i interface{} = "hello"

// 单值：类型不匹配直接 panic
s := i.(string)          // OK
// n := i.(int)           // panic: interface conversion

// 双值：安全检查
if s, ok := i.(string); ok {
    fmt.Println("string:", s)
}
if n, ok := i.(int); ok {
    fmt.Println("int:", n)
} else {
    fmt.Println("not int", n) // n 为零值 0
}

type switch 语法与使用

core

type switch 是处理多种可能类型的惯用写法，比多个 if/else 类型断言更清晰。每个 case 中变量会自动绑定为对应类型。

func describe(i interface{}) string {
    switch v := i.(type) {
    case int:
        return fmt.Sprintf("int(%d)", v)
    case string:
        return fmt.Sprintf("string(%q)", v)
    case bool:
        return fmt.Sprintf("bool(%v)", v)
    case []byte:
        return fmt.Sprintf("bytes(len=%d)", len(v))
    case nil:
        return "nil"
    default:
        return fmt.Sprintf("unknown(%T)", v)
    }
}

fmt.Println(describe(42))          // int(42)
fmt.Println(describe("go"))         // string("go")
fmt.Println(describe([]byte{1,2}))  // bytes(len=2)

接口类型断言

advanced

类型断言不仅可以断言到具体类型，也可以断言到接口类型，用于检查一个接口值是否同时满足另一个接口。

type Animal interface{ Sound() string }
type Runner interface{ Run() }

type Dog struct{}
func (d Dog) Sound() string { return "woof" }
func (d Dog) Run()           { fmt.Println("running") }

var a Animal = Dog{}

// 断言到另一个接口
if r, ok := a.(Runner); ok {
    r.Run() // Dog 同时满足 Runner
}

// type switch 中也可用接口类型
switch v := a.(type) {
case Runner:
    v.Run()
}

反射的性能与适用场景

反射的性能开销

高频考点

反射操作比直接调用慢约 10~100 倍，主要来源：

  • 类型信息查找：运行时通过 typelinks 查找类型元数据
  • 接口装箱/拆箱：每次 ValueOf/Interface() 都涉及 heap 分配
  • 间接调用：方法调用通过函数指针，无法内联
  • 逃逸分析失效：反射传值基本都逃逸到堆上，GC 压力增大
// 基准对比（仅示意数量级）
// 直接调用:  ~1  ns/op
// 类型断言:  ~2  ns/op
// 反射调用:  ~50 ns/op
// 反射 Set:  ~80 ns/op

合理使用场景

core

反射适合在框架层使用，业务代码应尽量避免：

推荐使用避免使用
encoding/json、XML 序列化热路径的类型判断（用接口代替）
ORM 字段映射（GORM、sqlx）简单的 map/slice 遍历
依赖注入框架已知类型的字段访问
测试断言库（testify）每次请求都执行的逻辑
配置文件解析（viper）可以用泛型解决的场景（Go 1.18+）

反射优化策略

advanced

在必须使用反射的场景下，以下策略可显著降低开销：

  • 缓存 reflect.Type：TypeOf 结果是不可变的，可以存入全局变量复用
  • 缓存字段索引：用 FieldByName 找到字段后记录 Index，后续用 Field(i)
  • sync.Map 缓存类型方案：按类型缓存编解码器，避免重复反射
  • unsafe 包直接操作：极端性能场景下绕过反射直接操作内存偏移量
// 缓存字段偏移，避免每次 FieldByName
var nameIdx int
func init() {
    t := reflect.TypeOf(User{})
    f, _ := t.FieldByName("Name")
    nameIdx = f.Index[0] // 缓存索引
}

func GetName(u User) string {
    return reflect.ValueOf(u).Field(nameIdx).String()
}

泛型 vs 反射的选择（Go 1.18+）

advanced

Go 1.18 引入泛型后，许多以前依赖反射的场景可以用泛型替代，获得编译期类型安全和更好的性能。

// 反射版本：运行时类型检查，有开销
func ContainsReflect(slice, elem interface{}) bool {
    sv := reflect.ValueOf(slice)
    for i := 0; i < sv.Len(); i++ {
        if reflect.DeepEqual(sv.Index(i).Interface(), elem) {
            return true
        }
    }
    return false
}

// 泛型版本：编译期类型安全，性能接近直接代码
func Contains[T comparable](s []T, e T) bool {
    for _, v := range s {
        if v == e { return true }
    }
    return false
}

面试题

reflect.Type 和 reflect.Value 分别表示什么？ ▶
reflect.Type 是一个接口，描述某个 Go 类型的静态元数据：类型名、包路径、字段列表、方法集、Kind 等。它是不可变的，可以安全地缓存。

reflect.Value 是一个结构体，封装某个变量的具体值和类型信息。通过它可以读取字段值、调用方法、设置值（需满足 CanSet 条件）。Value 包含一个指向实际数据的指针，因此修改 Value 内部字段会影响原始变量（前提是通过指针取的 Elem）。
Kind() 和 Type() 有何区别？举例说明 ▶
Type() 返回具体的命名类型，Kind() 返回底层的类型种类（枚举值）。

例如：type MyInt int，则 reflect.TypeOf(MyInt(0)).Type() 返回 main.MyInt，而 .Kind() 返回 reflect.Int。

实际应用中，通常用 Kind 来做通用的类型分发（switch on Kind），用 Type 来做精确的类型匹配或类型注册（如 JSON codec 按类型缓存编码器）。
如何用反射修改一个 struct 的字段值？有什么前提条件？ ▶
前提条件：
1. 必须通过指针调用 reflect.ValueOf(&s)，再通过 .Elem() 解引用得到可寻址的 Value。
2. 目标字段必须是导出的（首字母大写），未导出字段 CanSet() 返回 false。
3. 调用对应类型的 Set 方法（SetString、SetInt、SetFloat 等），或通用的 Set(reflect.Value)。

若对不可寻址的 Value 调用 Set，会触发 panic: reflect: reflect.Value.SetString using value obtained using unexported field 或 reflect.Value.Set using unaddressable value。
类型断言和类型 switch 各自适用什么场景？ ▶
类型断言（v, ok := i.(T)）适合已知少数几种可能类型，或仅需判断是否满足某个接口的场景。使用双值形式可以安全检查，单值形式在类型确定的情况下使用更简洁。

type switch 适合需要区分多种类型分别处理的场景，代码可读性更好。编译器会对 type switch 进行优化，性能略优于多个 if/else 类型断言。

两者都只能作用于接口类型值；若 i 是具体类型（非接口），断言会在编译期报错。
反射为何性能低？有哪些优化策略？ ▶
性能低的原因：
1. 类型元数据查找需要在运行时遍历 typelinks 链表；
2. ValueOf/Interface() 产生接口装箱，触发堆分配和 GC 压力；
3. 方法调用是间接调用（函数指针），编译器无法内联；
4. 逃逸分析无法优化反射路径上的变量。

优化策略：
1. 缓存 reflect.Type 和字段索引，避免重复查找；
2. 使用 sync.Map 按类型缓存编解码方案（如 encoding/json 内部实现）；
3. 代码生成（go generate）在编译期生成具体类型的处理代码，完全避免反射；
4. Go 1.18+ 优先考虑泛型替代反射，兼顾类型安全和性能。

易错点

✗ 对不可寻址的 Value 调用 CanSet/Set 导致 panic
type User struct{ Name string }

u := User{Name: "Alice"}

// 错误：直接传值，不可寻址
v := reflect.ValueOf(u)
fmt.Println(v.CanSet()) // false
// v.FieldByName("Name").SetString("Bob")
// panic: reflect.Value.SetString using
// unaddressable value

直接传值给 ValueOf，得到的是值的副本，不可寻址，无法修改原始变量。

type User struct{ Name string }

u := User{Name: "Alice"}

// 正确：传指针再 Elem()
v := reflect.ValueOf(&u).Elem()
fmt.Println(v.CanSet()) // true
v.FieldByName("Name").SetString("Bob")
fmt.Println(u.Name)   // Bob

传指针并调用 Elem() 解引用，得到可寻址的 Value，才能安全修改字段值。

✗ 混淆 Kind（底层种类）和 Type（具体类型名）
type Celsius float64

temp := Celsius(37.5)
v := reflect.ValueOf(temp)

// 错误理解：以为 Type() == "float64"
// 实际 Type() 是 "main.Celsius"
if v.Type().Name() == "float64" {
    // 永远不会进入！
    fmt.Println("is float64")
}

混淆 Type 和 Kind 导致条件永远不满足，逻辑静默失效。

type Celsius float64

temp := Celsius(37.5)
v := reflect.ValueOf(temp)

// 用 Kind 检查底层类型种类
if v.Kind() == reflect.Float64 {
    fmt.Println("float-like:", v.Float())
}

// 用 Type 精确匹配具体类型
if v.Type() == reflect.TypeOf(Celsius(0)) {
    fmt.Println("is Celsius")
}

通用处理用 Kind，精确匹配用 Type，两者职责不同，不可混用。

✗ 类型断言不用双值形式，类型不匹配时 panic
func process(v interface{}) {
    // 单值断言：若 v 不是 string 直接 panic
    s := v.(string)
    fmt.Println("len:", len(s))
}

process("hello") // OK
process(42)      // panic: interface conversion:
                  // interface {} is int, not string

在类型不确定的情况下使用单值类型断言，一旦类型不匹配就会 panic，导致服务崩溃。

func process(v interface{}) {
    // 双值断言：安全处理
    s, ok := v.(string)
    if !ok {
        fmt.Printf("expected string, got %T\n", v)
        return
    }
    fmt.Println("len:", len(s))
}

process("hello") // len: 5
process(42)      // expected string, got int

类型不确定时始终用双值形式；只有在确保类型正确（如先经过 type switch 分支）时才可用单值形式。
