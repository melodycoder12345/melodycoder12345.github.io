基本类型

内置基本类型总览

核心

Go 的基本类型分为布尔、整数、浮点、复数、字符串五大类。每种类型都有明确的零值，变量声明后未赋值时自动使用零值。

类型零值说明
boolfalse布尔型
int / int8/16/32/640有符号整数，int大小平台相关
uint / uint8/16/32/640无符号整数
float32 / float640浮点数，推荐用float64
string""不可变字节序列
byte0uint8的别名
rune0int32的别名，代表Unicode码点
pointernil指针类型

类型别名 vs 新类型定义

核心

type T = U（别名）：T 和 U 完全等价，可以互换使用，没有新的类型产生。
type T U（新类型）：T 是新的类型，底层类型是 U，但两者不能直接赋值，需要显式转换。

// 类型别名 — T 和 U 完全等同
type MyByte = byte   // MyByte 就是 byte，可直接赋值

// 新类型定义 — T 是全新类型
type Celsius float64
type Fahrenheit float64

var c Celsius = 100
// var f Fahrenheit = c  // 编译错误！不同类型
var f Fahrenheit = Fahrenheit(c)  // 显式转换 OK

新类型可以定义自己的方法，别名则不能添加新方法（方法属于原类型）。

复合类型

Array vs Slice

核心
  • Array：固定长度，长度是类型的一部分，[3]int != [4]int，值类型（赋值复制整个数组）
  • Slice：动态长度，底层是 {指针, len, cap} 三字段，引用类型（赋值共享底层数组）
// Array — 值类型
var a [3]int = [3]int{1, 2, 3}
b := a  // b 是 a 的拷贝，修改 b 不影响 a

// Slice — 引用类型
s := []int{1, 2, 3}
t := s  // t 和 s 共享底层数组
t[0] = 99  // s[0] 也变成 99

Map 与 Struct

核心
  • map：引用类型，key 必须是可比较类型，未初始化的 map 读可以（返回零值），写会 panic
  • struct：值类型，字段可以是任意类型，可嵌入其他 struct 实现组合
  • pointer：&x 取地址，*p 解引用，nil 指针解引用会 panic
type Point struct {
    X, Y float64
}

// map 必须用 make 初始化
m := make(map[string]int)
m["key"] = 1

// 零值 map 可读不可写
var m2 map[string]int
_ = m2["x"]   // 返回 0，不 panic
m2["x"] = 1  // panic: assignment to entry in nil map

类型转换

显式类型转换

核心

Go 不存在隐式类型转换（C 风格的强制转换）。所有类型转换必须显式写明，语法为 T(x)。数值类型之间转换可能丢失精度（截断）但不报错。

var i int = 42
var f float64 = float64(i)  // int → float64
var u uint = uint(f)          // float64 → uint（截断小数）

// string ↔ []byte ↔ []rune
s := "hello"
b := []byte(s)   // string → []byte（拷贝）
r := []rune(s)   // string → []rune（拷贝）
s2 := string(b)  // []byte → string（拷贝）

unsafe.Pointer：绕过类型系统的"逃生舱"，可以将任意指针转换为 unsafe.Pointer 再转换为其他类型，但这是不安全操作，仅在极特殊场景使用（如与 C 互操作、零拷贝优化）。

import "unsafe"

// 零拷贝 string → []byte（不推荐生产使用）
func unsafeBytes(s string) []byte {
    return *(*[]byte)(unsafe.Pointer(&s))
}

接口与空接口

interface{} 与 any

进阶

Go 1.18 引入 any 作为 interface{} 的别名。空接口可以持有任意类型的值，但使用时需要类型断言或 type switch 才能获取具体值。

var x any = 42

// 类型断言（单值形式，失败会 panic）
n := x.(int)

// 安全类型断言（两值形式，推荐）
n, ok := x.(int)
if !ok { /* x 不是 int */ }

// type switch
switch v := x.(type) {
case int:
    fmt.Println("int:", v)
case string:
    fmt.Println("string:", v)
default:
    fmt.Println("unknown")
}

面试题

零值的实际用途是什么？▶
零值设计让 Go 程序更安全，避免了未初始化变量的 undefined behavior。实际用途：
• sync.Mutex 零值可直接使用，无需构造函数
• bytes.Buffer 零值是空缓冲区，可直接调用 Write
• 数值零值做累加器初始值
• bool false 做 flag 默认关闭
• nil slice 可以直接 append，nil map 可以读（返回零值）
惯用法：设计 struct 时让零值代表"最合理的默认状态"。
type T U 和 type T = U 的本质区别？▶
type T = U（别名）：T 就是 U，在编译器眼中完全相同，无法为 T 定义新方法（因为方法属于 U）。主要用于代码重构/兼容性迁移。

type T U（定义新类型）：T 是全新的类型，底层类型是 U。T 和 U 之间不能直接赋值，必须显式转换。T 可以定义自己的方法。用途：语义化（Celsius vs float64）、类型安全（防止意外混用）。
int 和 int32 可以直接赋值吗？▶
不可以。虽然在 64 位平台上 int 和 int64 底层都是 64 位整数，但在 Go 类型系统中它们是不同的类型，int、int32、int64 三者互相不兼容，必须显式转换：
var i32 int32 = 100; var i int = int(i32)

同理，byte（uint8）和 int 也不能直接赋值。唯一例外是无类型常量，它可以被赋值给任何兼容的数值类型。
哪些类型可以赋值为 nil？▶
在 Go 中，以下类型的零值是 nil：
• 指针（pointer）
• 切片（slice）
• 映射（map）
• 通道（channel）
• 函数（func）
• 接口（interface）

基本类型（int, bool, string 等）和 struct、array 不能赋值为 nil。将 nil 接口和含有 nil 指针的接口混淆是常见错误（详见易错点）。
byte 和 rune 有什么区别？▶
byte 是 uint8 的别名，表示一个字节（0-255），用于处理原始字节数据。
rune 是 int32 的别名，表示一个 Unicode 码点（U+0000 到 U+10FFFF），用于处理字符。

一个 UTF-8 编码的中文字符占 3 个字节，但只是 1 个 rune。用 len(s) 获取的是字节数，用 len([]rune(s)) 或 utf8.RuneCountInString(s) 才是字符数。
unsafe.Pointer 的四条转换规则是什么？▶
Go 规范允许的 unsafe.Pointer 合法转换模式：
1. 任何类型的指针可以转换为 unsafe.Pointer
2. unsafe.Pointer 可以转换为任何类型的指针
3. uintptr 可以转换为 unsafe.Pointer（反之亦然），但中间不能有 GC 触发点
4. unsafe.Pointer 可以转换为 uintptr 后做算术运算，再转回（需要在同一表达式内完成以避免 GC 移动对象）

违反这些规则可能导致内存安全问题，go vet 和 go tool vet 会做部分检查。

易错点

❌ 整型溢出不报错，静默截断
var i8 int8 = 127
i8++
// i8 变成 -128，不报错
fmt.Println(i8) // -128

var u8 uint8 = 255
u8++
// u8 回绕到 0

整型溢出是静默行为，不触发 panic 或编译错误。

// 需要手动检查边界
import "math"

func safeAdd(a, b int8) (int8, error) {
    sum := int16(a) + int16(b)
    if sum > math.MaxInt8 {
        return 0, fmt.Errorf("overflow")
    }
    return int8(sum), nil
}

用更宽的类型做中间计算，或使用 math.MaxInt8 等常量检查边界。

❌ byte 与 rune 混淆导致中文截断
s := "你好世界"
fmt.Println(len(s))  // 12（字节数）

// 错误：按字节切片中文
first := s[:3]
// first 是 "你" 的 UTF-8 编码
// 但 s[:2] 是乱码！

len() 返回字节数，对中文字符串按字节下标操作会产生乱码。

s := "你好世界"
runes := []rune(s)
fmt.Println(len(runes))  // 4（字符数）

// 正确：转换为 rune slice 后操作
first := string(runes[:2])  // "你好"

// 或用 range 遍历
for i, r := range s {
    fmt.Printf("%d: %c\n", i, r)
}

处理多字节字符时转换为 []rune，或使用 range 遍历（自动处理 UTF-8）。

❌ nil 赋值给多种类型后比较行为不同
var p *int = nil
var i interface{} = p

// 陷阱：interface 值不为 nil！
fmt.Println(p == nil)  // true
fmt.Println(i == nil)  // false !!!

interface 存储了 (type=*int, value=nil)，类型信息非空，所以整个 interface 不等于 nil。

// 正确做法：返回 nil 接口时
// 直接返回 nil，不要返回
// (*T)(nil) 赋给 error/interface

func getError() error {
    var p *MyError = nil
    // return p  // 错误：caller 看到非 nil error
    return nil  // 正确
}

返回 error 接口时，永远直接 return nil，不要返回具体类型的 nil 指针。

❌ int 和 int64 在不同平台大小不同
// int 大小取决于平台
// 32位平台: int == int32 (4字节)
// 64位平台: int == int64 (8字节)

// 序列化时假设 int 是 64 位
type Msg struct {
    ID int  // 跨平台不安全
}

int 的大小不固定，跨平台序列化/网络传输时可能出现问题。

// 跨平台时用明确宽度的类型
type Msg struct {
    ID int64  // 明确 8 字节
}

// 数组下标、长度用 int 是OK的
// API 参数/协议字段用明确宽度
import "unsafe"
fmt.Println(unsafe.Sizeof(int(0)))
// 8 on 64-bit, 4 on 32-bit

协议/序列化字段使用 int32/int64，本地计算和索引用 int。
