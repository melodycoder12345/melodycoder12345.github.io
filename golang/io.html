Reader / Writer 接口

核心接口定义

[核心]

io.Reader 和 io.Writer 是 Go 中最重要的接口，几乎所有 I/O 操作都基于它们组合实现，体现了 Go 的接口组合哲学。

  • Read(p []byte) (n int, err error) — 读入最多 len(p) 字节，返回实际读取数和错误
  • Write(p []byte) (n int, err error) — 写出 len(p) 字节，n < len(p) 时必须返回非 nil 错误
  • Read 返回 io.EOF 表示流结束；Write 返回 io.ErrShortWrite 表示部分写入
  • 组合接口：io.ReadWriter、io.ReadCloser、io.ReadWriteCloser
// Reader 接口
type Reader interface {
    Read(p []byte) (n int, err error)
}
// Writer 接口
type Writer interface {
    Write(p []byte) (n int, err error)
}

// 实现 Reader 的类型示例
// *os.File, *bytes.Buffer, *strings.Reader,
// *bufio.Reader, net.Conn, http.Response.Body

常用组合工具

io 包工具函数与 bufio

[核心]

io 包提供大量基于 Reader/Writer 的组合工具，bufio 包提供带缓冲的包装器以减少系统调用次数。

  • io.TeeReader(r, w) — 读取时同时写入 w（"分叉"读流，常用于日志/校验）
  • io.MultiReader(r1, r2...) — 将多个 Reader 串联（依次读取）
  • io.LimitReader(r, n) — 限制最多读取 n 字节，防止无限读
  • bufio.NewReader(r) — 带缓冲，减少 syscall；提供 ReadLine/ReadString
  • bufio.NewWriter(w) — 带缓冲写，需要 Flush() 才真正写出
// TeeReader：读取同时计算 hash
h := sha256.New()
tee := io.TeeReader(resp.Body, h)
io.Copy(dst, tee)
checksum := h.Sum(nil)

// LimitReader：防止超大响应
limited := io.LimitReader(resp.Body, 10<<20) // 10MB
data, _ := io.ReadAll(limited)

io.Copy

高效数据传输

[核心]

io.Copy 是最常用的数据传输函数，自动使用 32KB 缓冲区循环读写，返回传输字节数和错误。

  • io.Copy(dst, src) — 传输直到 EOF 或错误，使用内部 32KB buffer
  • io.CopyN(dst, src, n) — 只传输 n 字节
  • io.CopyBuffer(dst, src, buf) — 使用自定义 buffer（可配合 sync.Pool）
  • 若 src 实现 WriteTo 或 dst 实现 ReadFrom，会利用零拷贝（如 sendfile）
// 文件拷贝
src, _ := os.Open("input.txt")
defer src.Close()
dst, _ := os.Create("output.txt")
defer dst.Close()
n, err := io.Copy(dst, src)

// 用 Pool buffer 减少分配
buf := bufPool.Get().([]byte)
defer bufPool.Put(buf)
io.CopyBuffer(dst, src, buf)

io.Pipe

同步内存管道

[进阶]

io.Pipe 创建一对同步的 PipeReader/PipeWriter，写端写入的数据直接被读端读取，无内部缓冲，写端阻塞直到读端消费。

  • 并发安全，适合连接两个需要 io.Reader/io.Writer 的 API
  • 需在不同 goroutine 中使用，否则死锁
  • 典型用途：将 HTTP response body 直接 stream 到下游处理
  • CloseWithError(err) — 关闭并传递错误给对端
// 将 JSON 编码流直接上传
pr, pw := io.Pipe()

go func() {
    enc := json.NewEncoder(pw)
    err := enc.Encode(largeData)
    pw.CloseWithError(err)  // 关闭通知读端
}()

// 上传时直接从 pipe 读取（流式，无需全部缓存）
resp, err := http.Post(url, "application/json", pr)
defer pr.Close()

面试问答

io.Reader 的 Read 方法 n < len(p) 时表示什么？▶
n < len(p) 表示本次读取的字节数少于请求的字节数，这是完全合法的行为（"short read"）。可能的原因：底层数据不足（如网络缓冲区暂时为空）、到达文件末尾（此时 err = io.EOF）、或 Reader 的实现策略。调用者必须根据 n（而非 len(p)）处理数据，不能假设 p[:n] 之后的字节有意义。需要精确读取 n 字节时，应使用 io.ReadFull。
bufio.Scanner 和 bufio.Reader 的区别？▶
bufio.Reader 是通用缓冲读取器，提供 ReadByte、ReadRune、ReadLine、ReadString、Peek 等低级方法，适合需要精细控制读取的场景。bufio.Scanner 是高级扫描器，专为按"token"（默认行）扫描设计，API 简单（Scan/Text/Bytes），但默认最大 token 64KB（可调）。按行读取文本文件用 Scanner；需要读取固定格式/二进制数据用 Reader。
strings.Reader 和 bytes.Buffer 有什么区别？▶
strings.Reader 是只读的，实现了 io.Reader/Seeker/WriterTo，底层是不可变字符串，无分配；适合将字符串作为 Reader 传入函数。bytes.Buffer 是读写缓冲区，实现了 io.Reader 和 io.Writer，可动态增长，适合构建字节数据然后读取。若只需要一个"字符串 Reader"，用 strings.NewReader；若需要构建再读，用 bytes.Buffer 或 bytes.NewReader（只读，类似 strings.Reader）。
io.Pipe 和 channel 有什么区别？▶
io.Pipe 实现了 io.Reader 和 io.Writer 接口，适合连接两个期望 Reader/Writer 的 API（如 json.Encoder 写 → http.Post 读），数据以字节流传输，无需预先知道大小。channel 传输的是离散的 Go 值，需要额外序列化；适合传递结构化消息或信号。io.Pipe 无内部缓冲（同步），写端必须等读端消费；channel 可以有缓冲。
bufio.Writer 什么情况下数据会丢失？▶
bufio.Writer 将数据先写入内部缓冲区，只有在缓冲区满或显式调用 Flush() 时才写入底层 Writer。若程序在 Flush 前崩溃，或忘记调用 Flush，缓冲中的数据会丢失。正确用法：始终在 defer 中调用 bw.Flush()（注意检查 Flush 的返回错误）。对于需要即时写入的场景（如日志），不要使用 bufio.Writer 或调整缓冲策略。

常见陷阱

❌ 忘记关闭 resp.Body（vs ✅ defer Body.Close）
resp, err := http.Get(url)
if err != nil { return err }
// 忘记关闭 Body！
data, err := io.ReadAll(resp.Body)
// 连接无法复用，最终耗尽连接池

Body 未关闭，底层 TCP 连接无法归还连接池，导致连接泄漏。

resp, err := http.Get(url)
if err != nil { return err }
defer resp.Body.Close() // 立即 defer
data, err := io.ReadAll(resp.Body)
// Body 关闭后连接可复用

获取 resp 后立即 defer Close，且需读完 Body 才能复用连接。

❌ Read 后没检查 n，使用完整 p（vs ✅ 只处理 p[:n]）
p := make([]byte, 1024)
r.Read(p)            // 忘记检查 n
process(p)           // 处理了 p 全部 1024 字节
// 实际只读了 n 字节，
// p[n:] 是旧数据或零值！

Read 实际读取字节数可能少于 len(p)，未检查 n 导致处理垃圾数据。

p := make([]byte, 1024)
n, err := r.Read(p)
if err != nil && err != io.EOF {
    return err
}
process(p[:n])  // 只处理实际读到的字节

使用 p[:n] 确保只处理实际读取的数据，并正确处理 io.EOF。

❌ 不读完 Body 导致连接不复用（vs ✅ 读完或 Discard）
resp, _ := http.Get(url)
defer resp.Body.Close()
// 只解码前几行，没读完 Body
dec := json.NewDecoder(resp.Body)
dec.Decode(&partial)
// Close 时 Body 未读完，连接不复用

HTTP 复用要求 Body 被完整读取。关闭未读完的 Body 会关闭底层连接。

resp, _ := http.Get(url)
defer func() {
    // 丢弃剩余数据，保证连接复用
    io.Copy(io.Discard, resp.Body)
    resp.Body.Close()
}()
dec := json.NewDecoder(resp.Body)
dec.Decode(&partial)

在 Close 前用 io.Discard 耗尽 Body，允许底层 TCP 连接复用。
