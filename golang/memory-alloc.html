面试题

Go 内存分配器的三层结构是什么？▶
mcache（线程缓存）：每个 P 私有，无锁分配，存储 67 种 size class 的小对象 span。
mcentral：每种 size class 一个，所有 P 共享，有锁，mcache 用完时从这里补充。
mheap：全局堆，从 OS 申请内存，以 span 为单位管理（一个 span = 多个 page = 8KB/page）。
小对象（≤32KB）走三层；大对象（>32KB）直接从 mheap 分配。
什么是 size class？为什么这样设计？▶
Go 将小对象按大小分为 67 个 size class（8B ~ 32KB），每种 size class 对应一种规格的 span（每个 span 存储同规格对象）。好处：
① 减少内存碎片（同规格对象紧凑排列）
② 分配快（只需从对应 size 的 freelist 弹出）
③ GC sweep 高效（扫描同规格对象）
内存浪费率约 12.5%（向上取整到最近 size class）。
Go 何时会触发 GC？可以如何调节？▶
触发条件：① 堆大小达到上次 GC 后的 2 倍（默认 GOGC=100，100%增长触发）；② 定时（2分钟一次 sysmon 强制触发）；③ 手动 runtime.GC()。
调节：GOGC=200 减少 GC 频率（更大内存占用换更少 STW）；GOGC=off 禁用 GC；Go 1.19+ 支持 runtime/debug.SetMemoryLimit 基于内存上限触发。
tiny allocator 是什么？▶
对于 ≤16B 的无指针小对象（如 string header、小 struct），Go 使用 tiny allocator：将多个小对象合并分配到同一个 16B 内存块，减少每次分配的开销和内存碎片。同一个 16B 块中的对象只有当全部不可达时才能被 GC 回收（注意：不要将小生命周期对象和大生命周期对象合并到同一 tiny block）。
栈分配和堆分配的区别？▶
栈分配：函数调用时移动栈指针，函数返回时自动回收，零 GC 压力，速度极快（~1ns）。
堆分配：通过 mallocgc 分配，需要 GC 追踪和回收，速度较慢（~100ns）。
Go 编译器通过逃逸分析决定：不逃逸的变量分配在栈上，逃逸的变量分配在堆上。用 go build -gcflags=-m 查看逃逸信息。
如何减少 Go 程序的 GC 压力？▶
① sync.Pool：复用临时对象（[]byte buffer、大 struct）
② 预分配 slice/map：make([]T, 0, n) 避免多次扩容
③ 减少指针：使用值类型而不是指针类型（GC 不需要扫描无指针对象）
④ 避免不必要的接口转换（interface 会导致值逃逸到堆）
⑤ 使用 []byte 而不是 string 拼接（strings.Builder）
⑥ pprof heap 分析定位高分配热点

易错点

❌ 大量小对象分配加重 GC
// 每次请求都分配新 buffer
func handle(r *http.Request) {
    buf := make([]byte, 4096)
    io.ReadFull(r.Body, buf)
    process(buf)
    // buf 逃逸到堆，GC 需要追踪
}
var bufPool = sync.Pool{
    New: func() any {
        b := make([]byte, 4096)
        return &b
    },
}
func handle(r *http.Request) {
    bufp := bufPool.Get().(*[]byte)
    defer bufPool.Put(bufp)
    io.ReadFull(r.Body, *bufp)
    process(*bufp)
}

sync.Pool 复用 buffer，减少堆分配次数，降低 GC 压力。

❌ slice append 引起意外内存保留
// 从大 slice 取一小部分
data := loadBigData() // 100MB
small := data[:10]    // 仍引用整个底层数组
// data 可以 GC，但底层数组不能
// 因为 small 还持有引用
data := loadBigData()
// 显式拷贝，断开对大数组的引用
small := make([]byte, 10)
copy(small, data[:10])
// 现在 data 的底层数组可以被 GC
data = nil // 可选，加速 GC

子 slice 持有整个底层数组引用，需要 copy 来断开引用。

❌ map 不会收缩
m := make(map[string]int)
for i := 0; i < 1000000; i++ {
    m[fmt.Sprintf("key%d",i)] = i
}
// 清空后内存不释放
for k := range m {
    delete(m, k)
}
// map 仍占用大量内存
// 方案1: 重新创建 map
m = make(map[string]int)

// 方案2: 用于临时 map
// 使用完后直接丢弃引用
// 让 GC 回收整个 map

// 注意：map 只增不缩是设计决策
// 需要动态缩容时考虑 sync.Map
// 或分片 map（sharded map）

Go map 删除元素后内存不收缩。需要频繁增删的场景要注意内存使用。
