IP 协议基础

网络层协议，负责主机间数据包的寻址和路由。IP 地址标识主机，子网掩码划分网络边界，路由表决定下一跳。ARP 将 IP 地址解析为 MAC 地址，TTL 防止包无限转发，ICMP 用于网络诊断。

核心术语
  • ARP（地址解析协议）广播询问"Who has IP X?"，目标主机单播回复自己的 MAC，结果缓存在 ARP 表。
  • 路由表 / 最长前缀匹配路由器对目标 IP 做最长前缀匹配找下一跳，默认路由 0.0.0.0/0 是最后兜底。
  • TTL（生存时间）每路由器减 1，到 0 时丢包并返回 ICMP Time Exceeded，Traceroute 原理。
  • CIDR 子网划分/24 可拆为两个 /25，每个子网独立广播域，不同子网通信必须经路由器。

背景与机制

IP 协议（RFC 791）是 Internet 的基石，工作在网络层（OSI L3），提供无连接、尽力而为的数据包交付。主要组件：

IP 地址 32 位逻辑地址，点分十进制表示（如 192.168.1.1）。与 MAC 地址不同，IP 地址是网络拓扑上的逻辑位置，可以重新分配；MAC 地址是硬件标识，通常固定。

子网掩码/CIDR 决定哪部分是网络位、哪部分是主机位。/24 = 255.255.255.0，前 24 位是网络位，最多 254 台主机（去掉网络地址和广播地址）。

路由 数据包到达路由器时，查路由表找最长前缀匹配，确定下一跳 IP，再通过 ARP 找到下一跳 MAC 封装以太网帧。

常见误区

  • ARP 只在同子网内有效。跨子网通信时，源主机的 ARP 请求是找"默认网关"的 MAC，而不是目标主机的 MAC。目标主机 MAC 只在最后一跳路由器的局域网段才需要。
  • TTL 减到 0 时，路由器会丢包并向源主机发 ICMP Time Exceeded，不是向目标主机。Traceroute 正是利用这一点逐跳探测路径。
  • CIDR 拆分后的子网必须经路由器转发才能互通，同一物理交换机下的两个 /25 子网，主机也无法直接二层通信。
  • IP 头的 Checksum 只校验头部，不校验数据负载。数据完整性由上层 TCP/UDP Checksum 负责。

工程场景

  • ARP 缓存投毒（ARP Spoofing）：攻击者发送伪造 ARP 回复将网关 IP 映射到自己的 MAC，实现中间人攻击。防御：Dynamic ARP Inspection (DAI)、静态 ARP 绑定。
  • Traceroute 诊断网络路径：逐 TTL 探测，结合响应延迟可识别网络抖动点，mtr 命令提供连续 ping+traceroute。
  • 云 VPC 子网规划：/16 VPC 划分多个 /24 子网（不同可用区），跨 AZ 通信走 VPC 路由，不同子网间用 Security Group + NACL 控制访问。
  • BGP/OSPF 路由协议：大型网络中路由表由动态路由协议维护，而不是手动配置，路由变更可以毫秒级收敛。

边界情况

动画涵盖：① ARP 广播→单播回复→缓存建立；② 跨子网 3 跳路由，每跳 MAC 重新封装；③ TTL 从 1 开始递增探测 Traceroute 完整路径；④ /24 拆分为 /25，广播域隔离，主机范围变化。

注意：每跳路由器重写以太网帧的源/目标 MAC（L2），但 IP 头中的源/目标 IP 始终保持不变（NAT 例外）。这是 L2 和 L3 分层的关键体现。
