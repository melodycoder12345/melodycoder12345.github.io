CDN

内容分发网络（CDN）通过在全球各地部署 PoP 边缘节点，将静态内容缓存到离用户最近的地方。GSLB 根据地理位置将请求路由到最近 PoP，命中缓存时直接返回（绿色，延迟低），未命中时回源（橙色，延迟高），TTL 到期后缓存自动刷新。

PoPGSLBCache-ControlTTL回源边缘节点
核心术语
  • PoP（接入点）全球边缘缓存节点，离用户最近的 CDN 站点。
  • GSLB通过 DNS 将请求路由到地理最近的 PoP。
  • Cache Hit / Miss命中直接返回（快），未命中回源获取（慢）。
  • TTLCache-Control 头控制缓存生存时间，到期则回源刷新。

CDN 工作流程

  • 用户发起请求，DNS 查询 CDN 域名
  • GSLB 根据用户 IP 地理位置、延迟、PoP 健康状态，返回最近 PoP 的 IP
  • 请求到达最近 PoP，查找缓存
  • 命中：直接返回缓存内容，延迟 10–30ms
  • 未命中：向源站或上级 PoP 回源，缓存内容，返回响应，延迟 100–300ms
  • TTL 到期后，PoP 缓存自动过期，下次请求触发回源刷新

缓存策略

  • 静态资源：Cache-Control: max-age=31536000, immutable（1年），内容用哈希做文件名保证唯一
  • HTML 页面：TTL 短（60–300s）或不缓存，保证内容更新及时
  • Cache-Control vs Expires：现代优先用 Cache-Control，Expires 是旧标准
  • Vary 头：按请求头（如 Accept-Encoding）分别缓存不同版本
  • 主动缓存刷新：CDN API 支持手动 Purge 指定 URL 或路径的缓存
  • CDN 绕过：带 ?v=xxx 参数或修改文件名强制获取新版本

高级功能

  • Edge Functions：在 PoP 节点运行代码（Cloudflare Workers/Lambda@Edge），A/B 测试、URL 重写、个性化内容
  • 动态加速：对不可缓存的动态请求，CDN 通过优化路由（骨干网快速通道）减少延迟
  • DDoS 防护：CDN 天然分散了流量，边缘节点可过滤恶意流量
  • HTTPS 卸载：TLS 握手在 PoP 完成，与源站之间走内网/HTTP，减少握手延迟
  • HTTP/3：支持 QUIC 协议，在弱网下减少队头阻塞

CDN 选型

  • Cloudflare：最大 PoP 网络（~310 个），免费套餐，企业安全功能强
  • AWS CloudFront：与 S3/ALB/API Gateway 原生集成，Lambda@Edge 功能强大
  • Fastly：VCL 配置灵活，实时配置生效（<1s），即时 Purge
  • Akamai：最老牌，PoP 遍布全球，企业级 SLA
  • 国内：阿里云 CDN、腾讯云 CDN，国内节点多，需要备案
