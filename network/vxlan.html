VXLAN Overlay 网络

Virtual Extensible LAN，将二层以太网帧封装在 UDP 包中，在三层网络上模拟二层广播域。K8s 跨主机 Pod 通信、云上多租户隔离的核心技术。VTEP 负责封包/解包，VNI 区分不同租户，外层 IP 是主机地址，内层是 Pod/VM 地址。

VTEPVNIUDP 封装OverlayEVPNK8s 网络
核心术语
  • VTEP（隧道端点）封包/解包节点，外层 src/dst IP = 主机 IP，内层保留 Pod/VM 的原始以太网帧。
  • VNI（24位租户 ID）VXLAN 头中的网络标识，最多 1600 万个隔离 overlay 网络，不同 VNI 互不干扰。
  • EVPN 控制平面用 BGP 分发 MAC→IP→VTEP 映射，避免 BUM 泛洪，支持大规模集群。
  • BUM 泛洪Broadcast/Unknown-unicast/Multicast，MAC 未知时向所有 VTEP 泛洪，EVPN 可消除。

背景与封包格式

VXLAN 协议（RFC 7348）在 UDP 8472 端口传输，封包格式（外→内）：

外层以太网帧 → 外层 IP（主机IP）→ 外层 UDP（dport=4789/8472）→ VXLAN 头（8字节，含 24 位 VNI） → 内层以太网帧 → 内层 IP（Pod IP）→ 内层 TCP/UDP → 数据

封装开销约 50 字节（以太网帧 14 + IP头 20 + UDP头 8 + VXLAN头 8），MTU 需要相应调整（通常内层 MTU=1450 而非 1500）。

Linux 内核从 3.7 版本原生支持 VXLAN，flannel/Calico/Cilium 等 CNI 均可基于内核 VXLAN 实现跨主机 Pod 通信。

常见误区

  • VXLAN 不是加密隧道，内层数据仍为明文。加密需要额外的 WireGuard/IPSec 封装（如 Cilium 支持 WireGuard 加密 VXLAN）。
  • VTEP 失败后不会自动切换——需要 EVPN 撤回路由通知其他 VTEP 更新转发表，否则流量会黑洞。
  • VXLAN 是 L2-over-L3，同一 VNI 内的 Pod 能互相 ARP（二层可达），但不同 VNI 的 Pod 需要 L3 路由（不同 overlay 网络）。
  • 大规模集群（1000+ 节点）时 BUM 泛洪会产生大量无效流量，必须用 EVPN 或静态 MAC 表代替泛洪学习。

工程场景

  • K8s flannel VXLAN 模式：每个节点运行 flanneld，监听 etcd 路由表。Pod 发包→Linux VXLAN 设备→封包→通过主机物理网卡发出→对端 flanneld 解包→投递到目标 Pod。
  • 云 VPC（阿里云/AWS）：不同 ECS 实例/VPC 内网通信走 VXLAN Overlay，硬件 VTEP（智能网卡）实现封包/解包，对宿主机 CPU 零影响。
  • OpenStack Neutron：用 VXLAN 实现租户之间的网络隔离，每个租户一个 VNI，OVS 作为软件 VTEP。
  • 数据中心互联（DCI）：两个数据中心通过 VXLAN 拉伸 L2 网络，实现跨机房虚拟机无感迁移（vMotion）。

VXLAN vs 其他 Overlay

  • VXLAN vs GRE：GRE 封装更简单（无 VNI），但不支持多租户隔离，不支持 UDP ECMP 负载均衡。
  • VXLAN vs WireGuard：WireGuard 提供加密，但无 VNI 隔离，通常在 VXLAN 外层叠加 WireGuard。
  • VXLAN vs Geneve：Geneve（RFC 8926）是 VXLAN 的后继，支持可变长度元数据头，被 OVN/Cilium 采用。
