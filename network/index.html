网络基础概念

协议分层 · 核心协议 · 面试重点
OSI 7层模型
7 应用层 用户数据接口 HTTP, FTP, DNS, SMTP
6 表示层 数据格式转换 SSL/TLS, JSON, XML
5 会话层 建立/维护会话 RPC, NetBIOS
4 传输层 端到端可靠传输 TCP, UDP
3 网络层 逻辑地址路由 IP, ICMP, ARP
2 数据链路层 MAC 帧传输 Ethernet, WiFi
1 物理层 比特流传输 光纤, 双绞线, 无线电
TCP/IP 4层模型
应用层 对应 OSI 5-7 层 HTTP, DNS, FTP, SMTP
传输层 对应 OSI 第4层 TCP, UDP
网络层 对应 OSI 第3层 IP, ICMP, ARP
网络接口层 对应 OSI 1-2 层 Ethernet, WiFi, 光纤
为什么用 TCP/IP 而不是 OSI？
OSI 是理论模型，TCP/IP 是实际实现。现实中表示层和会话层功能由应用层自己处理（如 TLS），因此实践中普遍使用 TCP/IP 4层模型。
协议 层级 传输方式 特点 典型端口/场景
TCP 传输层 面向连接 可靠、有序、流控、拥塞控制 80/HTTP, 443/HTTPS, 22/SSH
UDP 传输层 无连接 不可靠、低延迟、无序、无流控 53/DNS, 123/NTP, 视频/游戏
HTTP/1.1 应用层 TCP 持久连接, 队头阻塞, 文本协议 80, Keep-Alive
HTTP/2 应用层 TCP + TLS 多路复用, 二进制帧, 头部压缩 443, HPACK
HTTP/3 应用层 QUIC/UDP 解决队头阻塞, 0-RTT 重连, 连接迁移 443/UDP
DNS 应用层 UDP/TCP 域名→IP 映射, 分层缓存, TTL 53, 递归/迭代查询
TLS 1.3 会话/表示 TCP 1-RTT 握手, 前向安全, AES-GCM 443, HTTPS 基础
  • TCP 三次握手为什么不能是两次？两次握手不能确认客户端的接收能力，可能导致旧连接请求复活。
  • TIME_WAIT 状态为什么要等待 2MSL？确保最后一个 ACK 能到达对端，同时让网络中的重复报文消失。
  • TCP 如何保证可靠传输？序列号+确认号、超时重传、滑动窗口、校验和、拥塞控制。
  • HTTP/1.1 和 HTTP/2 的核心区别？HTTP/2 使用二进制帧、多路复用，解决应用层队头阻塞，并支持 HPACK 头部压缩；TCP 层队头阻塞仍由 HTTP/3/QUIC 解决。
  • HTTPS 握手过程是什么？TLS 1.3: Client Hello → Server Hello+证书 → 密钥交换 → 加密通信，共 1-RTT。
  • DNS 解析完整过程？浏览器缓存 → OS缓存 → hosts文件 → 递归解析器 → 根NS → TLD NS → 权威NS。
  • 负载均衡有哪些算法？轮询、加权轮询、最少连接、IP Hash、一致性哈希（减少节点变化影响）。
  • TCP 拥塞控制的四个阶段？慢启动 → 拥塞避免 → 快速重传 → 快速恢复（Reno/CUBIC/BBR）。
  • UDP 和 TCP 如何选择？延迟敏感（游戏/视频/DNS）选 UDP；需要可靠传输（文件/HTTP）选 TCP。
  • 什么是 CDN？内容分发网络，将静态资源缓存到边缘节点，利用 DNS 调度将用户导向最近节点。
