Bloom Filter

Bloom Filter 用位图和多个 hash 判断元素是否可能存在，以可控误判换取极低内存。

背景

海量集合判重时，完整保存所有 key 成本很高。Bloom Filter 不保存原值，只保存多个 hash 位置是否出现过。

运行机制

  • 插入时对 key 做多个 hash，并把对应 bit 置 1。
  • 查询时检查多个 bit，只要一个为 0 就一定不存在。
  • 所有 bit 都为 1 时只能说明可能存在，因为不同 key 可能碰撞。

常见误区

  • 普通 Bloom Filter 不支持安全删除，删除可能影响其他 key。
  • 误判率会随元素数量增长而升高，需要容量规划。

工程场景

  • 缓存穿透防护、黑名单过滤、日志去重和大集合预过滤都常用 Bloom Filter。

边界判断

判断这个概念是否适用时，先看它解决的核心约束，再看代价是否落在业务可接受范围内。不要只记名字，要能说清楚它牺牲了什么、保留了什么。
