贪心算法

贪心在每一步都选择当前最优解，不回溯。成立条件是问题具有"贪心选择性质"和"最优子结构"。理解适用边界和证明方法，比死记算法更重要。

局部最优贪心选择性质最优子结构交换论证
核心术语
贪心选择性质全局最优解可以通过一系列局部最优选择来构造，每步局部最优不影响后续选择的正确性。
最优子结构问题的最优解包含子问题的最优解，与动态规划相同，但贪心不枚举所有子问题答案。
交换论证证明贪心正确性的常用方法：假设最优解与贪心解不同，通过交换操作证明可改进或等价，推出矛盾。

贪心的本质

贪心算法在每一步做出当前看起来最优的选择，希望这些局部最优选择能导向全局最优。与动态规划的区别：

  • DP：枚举所有子问题，存储结果，自底向上构造最优解（适合不满足贪心性质的问题）
  • 贪心：每步只做一个选择，不回溯，不枚举（适合满足贪心性质的问题，复杂度更低）

贪心成立的两个必要条件：

  • 贪心选择性质：每步的局部最优选择不会使后续步骤变得不可能达到全局最优
  • 最优子结构：选择了贪心步骤后，剩余子问题仍然是独立的最优化问题
重要认知：只有证明贪心选择性质后才能使用贪心。具体复杂度取决于算法；不少经典贪心算法是排序后线性扫描，但不存在“贪心必然比 DP 快”这一通用复杂度结论。

活动选择问题

给定 n 个活动，每个活动有开始和结束时间，选择最多个互不重叠的活动。

贪心策略：按结束时间排序，每次选择结束最早且与已选活动不冲突的活动。

type Activity struct{ start, end int }

func activitySelection(acts []Activity) []Activity {
    // 按结束时间升序排序（贪心选择的关键）
    sort.Slice(acts, func(i, j int) bool {
        return acts[i].end < acts[j].end
    })
    var result []Activity
    lastEnd := -1
    for _, a := range acts {
        // 贪心：只要当前活动开始时间 >= 上一个结束时间，就选
        if a.start >= lastEnd {
            result = append(result, a)
            lastEnd = a.end
        }
    }
    return result
}
// 示例：活动 [(1,4),(3,5),(0,6),(5,7),(3,8),(5,9),(6,10),(8,11),(8,12),(2,13),(12,14)]
// 贪心结果：4 个活动

正确性证明（交换论证）：设贪心首选活动 a₁，任何最优解 O 若不含 a₁，则把 O 中第一个活动换成 a₁，新解仍然合法且大小不变，因此贪心解不劣于最优解。

霍夫曼编码

给字符分配最短的前缀编码，使高频字符用更短的码字，总编码长度最小。

贪心策略：每次从最小堆取两个频率最低的节点合并，重复直到只剩一个根节点。

type HNode struct {
    freq        int
    char        byte
    left, right *HNode
}

func huffman(freqs map[byte]int) *HNode {
    h := &MinHeap{}
    for char, f := range freqs {
        heap.Push(h, &HNode{freq: f, char: char})
    }
    for h.Len() > 1 {
        // 每次取出频率最小的两个节点
        left := heap.Pop(h).(*HNode)
        right := heap.Pop(h).(*HNode)
        // 合并为新节点，频率相加
        parent := &HNode{
            freq:  left.freq + right.freq,
            left:  left,
            right: right,
        }
        heap.Push(h, parent)
    }
    return heap.Pop(h).(*HNode) // 根节点
}
// 字符频率：{a:5, b:9, c:12, d:13, e:16, f:45}
// f:0, c:100, d:101, a:1100, b:1101, e:111
// 总编码长度：224 位（最优前缀码）

霍夫曼编码的贪心性质：合并最小两个频率节点保证了每次"花费"最小，可用数学归纳证明最终树是最优前缀码树。

区间调度类经典问题

区间问题是贪心的高频考点，多种不同的问题有不同的贪心策略：

// 1. 区间合并（排序后按序合并）
func merge(intervals [][]int) [][]int {
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][0] < intervals[j][0]
    })
    res := [][]int{intervals[0]}
    for _, iv := range intervals[1:] {
        last := res[len(res)-1]
        if iv[0] <= last[1] {
            if iv[1] > last[1] { last[1] = iv[1] }
        } else {
            res = append(res, iv)
        }
    }
    return res
}

// 2. 最少跳跃次数（LC 45）
func jump(nums []int) int {
    jumps, curEnd, farthest := 0, 0, 0
    for i := 0; i < len(nums)-1; i++ {
        if i+nums[i] > farthest {
            farthest = i + nums[i]
        }
        if i == curEnd { // 到达当前跳跃边界
            jumps++
            curEnd = farthest
        }
    }
    return jumps
}

// 3. 分糖果（LC 135）：先左→右，再右→左
func candy(ratings []int) int {
    n := len(ratings)
    c := make([]int, n)
    for i := range c { c[i] = 1 }
    for i := 1; i < n; i++ {
        if ratings[i] > ratings[i-1] { c[i] = c[i-1] + 1 }
    }
    for i := n - 2; i >= 0; i-- {
        if ratings[i] > ratings[i+1] && c[i] <= c[i+1] {
            c[i] = c[i+1] + 1
        }
    }
    sum := 0
    for _, v := range c { sum += v }
    return sum
}

什么时候不能用贪心？

贪心最大的陷阱是"看起来正确"但实际不成立。以下情况不能用贪心：

反例 1：0/1 背包问题

// 物品：重量[2,3,4], 价值[3,4,5], 容量=5
// 贪心（按价值密度）：先选 3/2=1.5 的物品（3,2）
//   再选 4/3≈1.33 的物品 → 价值=7，用了容量5 ✓
// 但最优解：选 (3,2)+(4,3)=7，或 (4,3)+(3,2)=7...
// 实际上分数背包可以用贪心（物品可分割）
// 0/1 背包不能用贪心，必须用 DP

反例 2：硬币找零（非标准面值）

// 面值 [1, 3, 4]，找零 6
// 贪心：选 4 → 剩 2 → 选 1 → 选 1 → 共 3 枚
// 最优：选 3 → 选 3 → 共 2 枚！
// 标准美元/人民币面值才满足贪心性质
// 任意面值组合 → 必须用 DP

误区：贪心不需要证明是大忌

误区 1：局部最优 ≠ 全局最优，不能无脑套贪心
// 图中找最短路（有负权边）
// 贪心：每次选最近节点（Dijkstra 思路）
// 当存在负权边时，Dijkstra 会给出错误答案：
//
// 0 ——3→ 1
// |        |
// 1    -5  ↓
// ↓        2
// 3 ←←←←←←
//
// 贪心选 0→1→2，但 0→3→2 通过负权更短

Dijkstra 的贪心性质依赖"已确定节点不会被更新"，负权边破坏了这一性质，导致错误。

// 需要 Bellman-Ford 或 SPFA 处理负权边
func bellmanFord(n int, edges [][3]int, src int) []int {
    dist := make([]int, n)
    for i := range dist { dist[i] = math.MaxInt32 }
    dist[src] = 0
    // 松弛 n-1 次，不贪心
    for i := 0; i < n-1; i++ {
        for _, e := range edges {
            u, v, w := e[0], e[1], e[2]
            if dist[u]+w < dist[v] {
                dist[v] = dist[u] + w
            }
        }
    }
    return dist
}

遇到负权边时果断放弃贪心，切换到可以处理负权的算法，不要试图"修补"贪心。

误区 2：贪心策略选错，选择维度不对
// 活动选择 - 错误贪心：按开始时间排序
sort.Slice(acts, func(i, j int) bool {
    return acts[i].start < acts[j].start
})
// 反例：活动 [(1,10),(2,3),(4,5)]
// 按开始排序选 (1,10)，只选1个
// 正确应选 (2,3),(4,5) 共2个

贪心策略的选择维度非常关键。按开始时间贪心看似合理，但最优解是按结束时间贪心。

// 活动选择 - 正确贪心：按结束时间排序
sort.Slice(acts, func(i, j int) bool {
    return acts[i].end < acts[j].end
})
// 结束越早，给后续活动留下的空间越多
// 交换论证可严格证明此策略正确
// 时间复杂度：O(n log n)

贪心策略的正确性需要严格证明（通常用交换论证），感觉正确不等于真正正确。

贪心 vs DP 选择标准
// 用贪心的信号：
// 1. 问题有"排序后选最优"的直觉
// 2. 做了一个选择后，子问题规模缩小
//    且子问题结构与原问题相同
// 3. 选择之间没有复杂依赖关系
// 4. 能用交换论证或数学归纳证明

能证明贪心选择性质，才能放心用贪心。证明方法：假设存在不用贪心步骤的更优解，推出矛盾。

// 用 DP 的信号：
// 1. 贪心选择会影响后续选择的可能性
//    （如 0/1 背包：选了大物品影响小物品选择）
// 2. 需要考虑"选"和"不选"两种分支
// 3. 存在重叠子问题且子问题答案互相依赖
// 4. 贪心在反例上给出了错误答案

当构造出一个贪心给出错误结果的反例时，立即换用 DP，不要继续调整贪心策略。

贪心算法复杂度汇总

  • 活动选择：O(n log n) 排序 + O(n) 线性扫描 = O(n log n)
  • 霍夫曼编码：O(n log n)——n 次堆操作，每次 O(log n)
  • 区间合并：O(n log n) 排序 + O(n) 合并 = O(n log n)
  • 最少跳跃次数：O(n)——单次线性扫描，无排序
  • Dijkstra（无负权）：O((V+E) log V) with 优先队列

许多经典贪心算法只需排序加线性扫描，因此实现紧凑、效率较高；这不是所有贪心问题的统一复杂度保证。正确性仍必须由交换论证、拟阵结构等方式证明。
