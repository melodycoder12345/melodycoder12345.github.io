Big O 描述随输入规模增长的上界趋势，常用于说明最坏、平均或均摊复杂度，具体场景要明确。
比如 3n² + 2n + 1 → O(n²)，因为 n 足够大时 n² 项主导增长，常数和低阶项会被忽略。

🧮 算法 (Algorithm)

解决问题的步骤序列，是一组指令

  • 输入 → 处理 → 输出
  • 必须在有限步骤内结束
  • 例：如何将数组排序、如何找最短路
func bubbleSort(arr []int) {
  // 步骤1: 外层循环...
  // 步骤2: 比较相邻...
  // 步骤3: 若逆序则交换
}

🏗️ 数据结构 (Data Structure)

组织和存储数据的方式，决定数据如何排列

  • 决定内存中数据的布局
  • 影响操作的效率
  • 例：数组、链表、哈希表、树
type Stack struct {
  items []int  // 存储方式
}
// 定义数据如何组织
两者相辅相成： 数据结构是"容器"，算法是"操作方法"。同一个算法在不同数据结构上效率迥异 —— 比如二分搜索只能在有序数组（随机访问 O(1)）上达到 O(log n)， 在链表上只能 O(n)。选对数据结构，往往比优化算法更关键。
使用场景 推荐结构 关键操作复杂度 原因
按下标随机访问 数组 O(1) 读写 内存连续，直接计算地址
频繁头部/中间插入删除 链表 O(1) 插删 / O(n) 查找 无需移动其他元素，调指针即可
后进先出（撤销、括号匹配） 栈 O(1) push/pop LIFO 语义，代码简洁
先进先出（任务队列、BFS） 队列 O(1) enqueue/dequeue FIFO 语义，天然模型
键值快速查找（缓存、计数） 哈希表 O(1) 平均查找 哈希函数直接定位，最快的查找
有序数据 / 范围查询 BST / AVL 树 O(log n) 查找/插入 有序性，支持范围查询和中序遍历
始终取最大/最小值 堆（优先队列） O(1) 取顶 / O(log n) 插入 堆顶始终是极值，插删只需调整堆
数据库索引 / 磁盘存储 B 树 / B+ 树 O(log n) 查找 多路树减少磁盘 I/O，节点填满一个磁盘页
图的最短路径 Dijkstra + 堆 O((V+E) log V) 贪心策略，每次扩展最近未访问节点

最小生成树 Kruskal + Union-Find O(E log E) 贪心选最小权边，并查集判环
最小生成树（稠密图） Prim + 优先队列 O(E log V) 从起点扩展，优先队列贪心选边
