滑动窗口

滑动窗口用左右边界维护连续区间，在边界单调移动时增量更新状态，将暴力 O(n²) 降为 O(n)。

双指针窗口状态流式统计
核心术语
窗口当前被左右边界包住的连续区间。
增量状态窗口变化时能 O(1) 或近似 O(1) 更新的计数、和、频率表。
单调边界左右指针只向前移动，不回退。

背景

许多问题要求在一个数组或字符串上找满足条件的连续子区间。暴力做法枚举所有起止位置，O(n²) 或更高。

滑动窗口的核心洞察：如果区间状态可以随边界移动做增量更新（加入一个元素 / 移除一个元素的代价是 O(1)），那么右指针只向右扩展、左指针只向右收缩，总移动次数不超过 2n，整体 O(n)。

适用条件：

  • 问题关注连续子数组 / 子串
  • 状态可以增量维护（频率表、和、计数）
  • 窗口满足单调性：扩大窗口使条件更容易/更难满足

不适用的信号：

  • 子序列问题（不要求连续）
  • 状态需要全窗口排序（中位数、众数等需辅助结构）
  • 缩小窗口不一定让条件恢复（无单调性）

运行机制

模板分为两类：最长满足条件和最短满足条件。

  • 右指针扩展：每轮循环右移一步，将新元素加入窗口状态。
  • 左指针收缩：当窗口不满足约束（最长类）或已满足约束（最短类）时，左指针右移并移除旧元素。
  • 状态维护：常用 map[byte]int 记频率、int 记和、int 记满足条件的字符数。
  • 答案更新：在合法窗口处更新 max/min 长度或记录起始位置。

两类模板对比：

  • 最长类：外层 for 扩展右边界，内层 for/while 当窗口不合法时收缩左边界，在收缩后或循环外更新 max。
  • 最短类：外层 for 扩展右边界，内层 for/while 当窗口已满足时更新 min 并收缩左边界。
// 模板一：最长无重复子串（最长满足条件）
func lengthOfLongestSubstring(s string) int {
    freq := make(map[byte]int)
    left, ans := 0, 0
    for right := 0; right < len(s); right++ {
        freq[s[right]]++
        // 窗口不合法：有重复字符，收缩左边界
        for freq[s[right]] > 1 {
            freq[s[left]]--
            left++
        }
        if right-left+1 > ans {
            ans = right - left + 1
        }
    }
    return ans
}
// 输入: "abcabcbb" → 输出: 3 ("abc")

// 模板二：长度为 K 的最大子数组和（固定窗口）
func maxSumSubarray(nums []int, k int) int {
    sum, maxSum := 0, 0
    for i := 0; i < len(nums); i++ {
        sum += nums[i]
        if i >= k {
            sum -= nums[i-k] // 左边界滑出
        }
        if i >= k-1 && sum > maxSum {
            maxSum = sum
        }
    }
    return maxSum
}

代码示例：最小覆盖子串（最短满足条件）

LeetCode 76 - Minimum Window Substring：在 s 中找包含 t 所有字符的最短子串。这是"最短满足条件"模板的经典应用。

思路：扩展右边界直到包含 t 所有字符，然后持续收缩左边界并更新最短长度，直到不再满足条件。

func minWindow(s, t string) string {
    need := make(map[byte]int)
    for i := range t {
        need[t[i]]++
    }
    window := make(map[byte]int)
    left, matched := 0, 0
    start, minLen := 0, len(s)+1

    for right := 0; right < len(s); right++ {
        c := s[right]
        window[c]++
        if window[c] == need[c] {
            matched++
        }
        // 窗口已满足条件，尝试收缩
        for matched == len(need) {
            if right-left+1 < minLen {
                minLen = right - left + 1
                start = left
            }
            d := s[left]
            if window[d] == need[d] {
                matched--
            }
            window[d]--
            left++
        }
    }
    if minLen > len(s) {
        return ""
    }
    return s[start : start+minLen]
}

复杂度分析：外层 for 循环 right 走 n 步，内层 for 循环 left 总共最多走 n 步（因为 left 只增不减）。两个指针总步数 <= 2n，所以是 O(n)。空间取决于状态结构——频率 map 最多 O(字符集大小)。

常见误区

误区 1：左指针收缩过于激进
// 错误：一发现不合法就把 left 跳到 right
for freq[s[right]] > 1 {
    left = right // 跳过太多，丢失有效字符
}

直接跳到 right 会跳过中间合法字符，导致结果偏小。

// 正确：逐步收缩，每次只移一位
for freq[s[right]] > 1 {
    freq[s[left]]--
    left++
}

逐步移动保证中间字符的状态被正确移除。

误区 2：收缩时忘记更新状态
// 错误：left 移动了但没更新 freq
for freq[s[right]] > 1 {
    left++ // freq 没减，状态失真
}

窗口状态和实际窗口内容不一致，后续判断全部出错。

// 正确：移除前先更新状态
for freq[s[right]] > 1 {
    freq[s[left]]-- // 先更新
    left++          // 再移动
}

左指针移动前必须把离开元素的贡献从状态中扣除。

误区 3：状态不可增量维护时强行套窗口
// 错误场景：求窗口中位数
// 中位数不能只靠常数个标量 O(1) 维护
// 双堆（配合延迟删除）或平衡树可做到每次 O(log k)

如果状态变化不能 O(1) 更新，滑动窗口未必是线性的；配合双堆或平衡树等结构仍可把固定窗口中位数维护到 O(n log k)，而不是每个窗口重新排序。

// 正确选型：
// 窗口中位数 → 双堆 / SortedList
// 窗口最大值 → 单调队列
// 窗口和/频率 → 滑动窗口

先判断状态能否增量维护，再决定用哪种算法。

面试问答

滑动窗口为什么是 O(n) 而不是 O(n²)？▶
虽然有两层循环（外层 right、内层 left），但 left 指针在整个过程中最多移动 n 次（只向右不回退）。right 也最多移动 n 次。所以总操作次数不超过 2n，即 O(n)。关键在于左右指针都是单调递增的。
固定窗口和可变窗口有什么区别？▶
固定窗口：窗口大小 k 不变，右指针每走一步左指针也走一步，适合"长度为 k 的子数组最大和"类问题。
可变窗口：窗口大小由条件决定，左指针只在不满足条件时收缩，适合"最长/最短满足条件的子串"类问题。
固定窗口是可变窗口的特殊情况。
什么时候滑动窗口不适用？▶
三种情况不能直接套用线性模板：
1. 状态不能常数时间维护（如窗口众数、中位数通常需要额外数据结构）
2. 可变窗口的判定不具备让边界单调推进的性质
3. 不是连续子区间问题（如子序列问题，元素可不相邻）
这时可能需要前缀和、动态规划、单调结构，或滑动窗口配合平衡树/堆。
滑动窗口和双指针有什么关系？▶
滑动窗口是双指针的一种特殊形式：两个指针同向移动且维护一个连续区间。广义双指针还包括相向移动（如两数之和的排序数组解法）、快慢指针（如链表环检测）等。滑动窗口的特征是：同向、不回退、维护区间状态。

工程应用

  • TCP 滑动窗口：发送方维护已发送未确认的字节范围，窗口左边界随 ACK 右移，右边界受接收方通告窗口限制。
  • 限流算法：固定窗口计数器（每秒重置）和滑动窗口计数器（按毫秒滑动）都是窗口思想的应用。
  • Kafka 消费 lag：观测最近 N 秒的消费速率变化，判断是否需要扩容 consumer。
  • 实时指标聚合：Prometheus 的 rate() 函数本质是在时间序列上做滑动窗口平均。
  • 流媒体缓冲：视频播放器维护一个前向缓冲窗口，根据网络状况动态调整窗口大小。

经典题目清单：LC 3（最长无重复子串）、LC 76（最小覆盖子串）、LC 209（最短子数组之和）、LC 438（找异位词）、LC 567（排列的字符串）、LC 424（替换后最长重复子串）、LC 1004（最大连续1的个数 III）。

变体与扩展

  • 多指针滑动窗口：有些问题需要三个指针（如同时维护满足和不满足的边界），本质仍是窗口但状态更复杂。
  • 前缀和 + 二分：当窗口条件不满足单调性（如绝对值最小的子数组和），可用前缀和排序后二分搜索，O(n log n)。
  • 滑动窗口 + 单调队列：求滑动窗口最大/最小值时，窗口维护用单调队列而非暴力扫描。两种技巧组合使用。
  • 双窗口/嵌套窗口：如"恰好 K 个不同字符"= "最多 K 个" - "最多 K-1 个"，用两个窗口差分求解。

复杂度总结

  • 时间：O(n)——左右指针各最多移动 n 次，总 2n 步。
  • 空间：取决于状态结构。频率 map → O(字符集) 或 O(k)；求和 → O(1)；频率数组 → O(26) 或 O(128)。
  • 对比暴力：暴力枚举起止 O(n²) + 内部状态计算 O(n) = O(n³) 或 O(n²)。滑动窗口把外两层合并为 O(n)。

面试答题思路

遇到以下关键词时考虑滑动窗口：

  • "最长/最短子串/子数组" → 可变窗口
  • "包含/不包含某些字符" → 频率表状态
  • "和 >= target 的最短子数组" → 求和状态 + 最短模板
  • "最多 K 个不同字符" → 频率表 + 计数器
  • "连续 1 的最大个数（可翻转 K 个 0）" → 窗口内 0 的数量作为约束

答题步骤：1. 确认是连续子区间问题 2. 确认状态可增量维护 3. 判断最长/最短选择模板 4. 定义窗口合法条件 5. 写出收缩逻辑。
