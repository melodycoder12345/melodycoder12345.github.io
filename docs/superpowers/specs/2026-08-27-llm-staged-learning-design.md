# 大模型底层分阶段学习路径设计

## 背景

当前 `ai/` 模块已经覆盖 LLM 基础概念、Prompt、上下文、结构化输出、Agent、Tokenization、Embedding、Transformer Attention、训练流水线、微调、对齐和推理服务等主题，但现有入口主要面向已经了解基础术语的工程师。初学者缺少一条从“会调用模型”逐步走到“能实现 Mini GPT、能分析训练算法”的连续路径。

本设计把目标拆成四个顺序交付、独立验收的阶段：

1. 使用大模型、调用 API；
2. 理解 Transformer 工作流程；
3. 从零实现小型 GPT；
4. 理解并尝试改进训练算法。

每个阶段只有在内容、交互、知识数据和测试均通过后才进入下一阶段。

## 目标与非目标

### 目标

- 为零基础读者建立明确、可执行的四阶段学习路线。
- 复用现有 AI 页面，避免同一概念在多个页面重复讲解却结论不一致。
- 将数学知识作为 LLM 概念的前置能力按需引入，而不是复制一套完整大学数学课程。
- 用动图、逐步计算、代码和失败场景解释抽象机制。
- 让新增页面进入现有知识图谱、页面画像、导航、SEO 和测试体系。

### 非目标

- 不建设完整的高等数学、线性代数或概率论课程。
- 不在本轮覆盖新模型架构研究、论文复现、CUDA 内核或大规模分布式训练。
- 不在浏览器直接调用外部模型服务，也不要求或保存真实 API Key。
- 不为追求页面数量重复已有 Prompt、Agent、KV Cache、微调或 RLHF 内容。

## 概念重合处理规则

新增或修改页面前，先为计划知识点指定唯一的“主讲页面”。处理方式只有四种：

- **复用**：已有页面已经完整承担该知识点，新路径只建立入口和前置关系。
- **扩展**：已有页面主题正确但缺少初学者解释，在原页面补充必要内容，不新建同主题页面。
- **新增**：现有页面没有承担该知识目标，创建新的主讲页面。
- **重构入口**：内容已经存在但学习顺序不清，只新增集合页或路线页，不复制正文。

知识点不得因为“属于不同阶段”而重复创建页面。阶段只表达学习顺序，页面和知识节点仍保持唯一。

## 信息架构

新增一个四阶段集合页 `ai/llm-learning-path.html`。它不复制详情页正文，只承担以下职责：

- 说明四阶段目标、前置知识和验收标准；
- 按顺序链接已有页面和新增页面；
- 标明必学、选学和进阶出口；
- 解释数学概念为何在当前节点出现；
- 展示每个阶段的最终实践任务。

第一版计划新增七个页面：

1. `ai/llm-learning-path.html`：四阶段总入口；
2. `ai/api-basics.html`：API 调用基础；
3. `ai/vector-matrix-for-llm.html`：向量、内积与矩阵乘法；
4. `ai/softmax-cross-entropy.html`：概率、Softmax 与交叉熵；
5. `ai/gradient-backprop.html`：导数、梯度、链式法则与反向传播；
6. `ai/mini-gpt.html`：Mini GPT 分步实验；
7. `ai/training-optimization-lab.html`：训练优化实验室。

页面名称可以在实施时根据现有命名规范微调，但一个知识目标只保留一个稳定节点 ID。

## 分阶段交付

### 第一阶段：使用大模型与 API

#### 交付内容

- 新增四阶段集合页，但只把第一阶段标记为当前学习内容，后续阶段展示目标和前置条件。
- 新增 API 调用基础页。
- 串联 `llm-overview`、`prompt-engineering`、`context-length`、`structured-output` 和 `agent-tool-calling`。
- 为 API 页面提供请求、排队、生成、流式返回和完成的逐步动画。
- 覆盖认证失败、超时、限流、上下文超限、连接中断和结构化结果校验失败。
- 给出服务端调用示例和安全说明；不提供把真实密钥写入浏览器的示例。

#### API 页面职责边界

API 页面从“调用方”视角解释：

`应用代码 -> 服务端代理 -> 模型 API -> 流式事件 -> 结果校验 -> 业务处理`

`inference-kv-cache.html` 继续从“模型服务内部”视角解释：

`Tokenize -> Prefill -> KV Cache -> Decode -> Sampling -> Streaming`

两页通过关系和互链衔接，不合并，也不重复彼此的主流程。

#### 第一阶段验收

- 读者能解释一次模型调用的完整生命周期。
- 读者能区分普通响应与流式响应。
- 读者知道 API Key 应保存在服务端。
- 读者能识别并处理超时、限流、上下文超限和结果校验失败。
- 所有动画步骤的画面、说明和代码片段一致。

### 第二阶段：理解 Transformer

#### 交付内容

- 新增三个面向 LLM 的数学基础页面。
- 复用 Tokenization、Embedding、Transformer Attention 和 Training Pipeline。
- 使用小尺寸、可手算的矩阵展示 Embedding、Q/K/V、相似度、Mask、Softmax 和加权求和。
- 使用简单函数展示 Loss、梯度、链式法则和一次参数更新。

#### 第二阶段验收

- 读者能从文本依次解释 Token、向量、Attention、Logits、Softmax 和下一个 Token。
- 读者能手算一次小规模 Attention。
- 读者能解释 Loss 如何通过反向传播影响参数。

### 第三阶段：从零实现 Mini GPT

#### 交付内容

- 新增一个分步骤 Mini GPT 实验页。
- 页面内使用 JavaScript 对小数据和小张量进行可视化模拟。
- 提供与动画步骤对应的 Python/PyTorch 参考实现。
- 串起字符级数据、Tokenizer、Embedding、Attention、MLP、Logits、Loss、Backward 和自回归生成。

#### 第三阶段验收

- 读者能说明 Mini GPT 每个模块的输入、输出和形状。
- 参考代码能够独立运行小规模训练与生成。
- 页面明确区分教学模型与生产级模型的差距。

### 第四阶段：训练算法

#### 交付内容

- 新增训练优化实验室。
- 对比 SGD 与 AdamW、不同学习率、Batch Size、梯度裁剪和正则化。
- 复用微调页解释 LoRA 与全量微调，实验页只呈现选择和效果差异。
- 将 RLHF、DPO 和模型融合作为进阶出口，不纳入核心实验。

#### 第四阶段验收

- 读者能根据 Loss 曲线识别学习率不当、过拟合和训练不稳定。
- 读者能解释 SGD、AdamW、梯度裁剪和正则化分别解决什么问题。
- 读者能判断基础训练实验与 LoRA 微调的职责边界。

## 页面与数据架构

每个新增详情页遵循现有静态页面体系：

1. HTML 页面承载内容和专题交互；
2. `knowledge/nodes/ai.json` 保存节点、画像和学习目标；
3. `knowledge/relations.json` 保存前置、机制、应用和对比关系；
4. `scripts/build-knowledge.js` 生成 `knowledge-data.js`；
5. `page-framework.js` 和 `knowledge-panel.js` 提供统一学习定位与关系入口；
6. AI 首页、站点地图和必要导航增加入口。

新增关系优先表达真实学习依赖，例如：

- API 基础 -> Prompt Engineering：应用关系；
- API 基础 -> 结构化输出：机制关系；
- 向量矩阵基础 -> Embedding：前置关系；
- 向量矩阵基础 -> Transformer Attention：前置关系；
- Softmax 与交叉熵 -> Transformer Attention：机制关系；
- 梯度与反向传播 -> Training Pipeline：前置关系；
- 三个数学基础页 + Attention + Training Pipeline -> Mini GPT：组成关系；
- Mini GPT -> 训练优化实验室：前置关系。

正式关系必须说明连接原因，不为消除孤立节点制造弱关系。

## 交互与错误处理

- 动画统一支持播放、暂停、上一步、下一步和重置。
- 每个动画至少覆盖正常路径、边界情况、故障路径和恢复或对比场景。
- API 动画不发出真实网络请求，使用确定性的本地状态数据展示生命周期。
- 代码示例中的模型名、SDK 细节和限额不作为稳定事实；供应商相关信息必须标明示例边界。
- 数学实验限制输入规模，避免浏览器主线程被大矩阵计算阻塞。
- Mini GPT 页面明确标注浏览器动画是教学模拟，Python 代码才是可运行训练参考。

## 验证策略

每个阶段至少执行：

- `npm run knowledge:check`
- `npm run layout:audit`
- 与该阶段页面对应的 Vitest 单元或集成测试
- Playwright 桌面端页面、导航、返回路径和交互测试
- 动画播放、暂停、步进、重置、异常和恢复场景检查
- 从 AI 首页、学习路线、知识星图三种入口检查跳转

测试只覆盖当前阶段新增和必要改动，不借机重写无关页面。

## 发布与工作区保护

- 每个阶段独立提交和验收；下一阶段不与当前阶段混合。
- 当前工作区包含大量既有未提交修改，实施时只暂存本阶段明确列出的文件。
- 不覆盖、回滚或格式化无关文件。
- 若现有页面的在途修改与本阶段重叠，先确认差异，再做最小合并。

## 文档与规范同步

当前项目没有 `openspec/`，因此不引入 OpenSpec 目录，使用本设计文档和现有知识数据规范记录行为与验收标准。

仓库规范要求同步外部 Obsidian Vault，但个人安全规则禁止在未明确授权时修改该知识库。因此本任务默认只修改当前仓库；外部 Obsidian 同步需要单独获得用户授权，在未授权前作为发布前待办报告，不会静默修改。

## 实施顺序

1. 用户审阅并确认本设计文档；
2. 为第一阶段编写详细实施计划；
3. 只实施并验收第一阶段；
4. 用户确认第一阶段结果；
5. 重新审计第二阶段与届时现有内容的重合关系；
6. 依次重复，直到第四阶段完成。
