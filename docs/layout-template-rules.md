# 详情页布局模板与审计规则

布局由知识的呈现方式和交互形态决定，不按 `algo`、`network` 等目录强制统一。迁移阶段尽量保留页面原有 DOM，先通过公共样式和画像修正收敛布局。

## 模板族

| 模板信号 | 适用内容 | 推荐骨架 | 画像建议 |
| --- | --- | --- | --- |
| `fullscreen` + `viz-code` | 算法、数据结构和代码执行过程 | 紧凑标题栏 + 概念/动画/代码区 + 控制栏 | `animation`, `code`; `stepper` 或 `simulator` |
| `hero` + `lab` | 协议、系统机制、多组件流程 | 紧凑 Hero + 实验区 + 深度说明 | `diagram`, `lab`; `stepper` 或 `simulator` |
| `article` | 概念解释、工程实践、API 用法 | 主标题 + 阅读正文 + 可选目录 | `article`; `none` |
| `hero` | 混合型技术文章 | 简洁 Hero + 图解/代码 + 分节正文 | 按内容组合 `article`, `diagram`, `code` |

一个页面可以同时具有多个模板信号，例如 gRPC 是 `hero + lab`，Dijkstra 是 `fullscreen + viz-code`。这些信号用于审计和迁移分组，不会在运行时改写页面结构。

## 主标题规则

- 每个详情页应有且仅有一个语义化 `h1`。
- 标题可位于标题栏、Hero 或正文开头，视觉样式不决定语义。
- 迁移前已有的 `.nav-title`、`.page-title` 等可信页级标题会作为回退识别，审计标记为 `semantic-title-fallback`，但仍建议最终改为 `h1`。
- 公共学习信息可绑定现有 `h1`，不应要求页面增加重复标题。

## 自动审计

运行：

```bash
npm run layout:audit
```

机器可读输出：

```bash
npm run layout:audit:json
```

审计只读取详情页 HTML 和结构化节点画像，不修改页面；模块的 `index.html` 与专题导航 `topic.html` 不属于详情页扫描范围。它报告：

- 缺少或重复的 `h1`；已有可信标题类时作为语义提示，完全无标题时才作为警告；
- 标题位于标题栏、Hero、正文或缺失；
- `fullscreen`、`hero`、`lab`、`viz-code`、`article` 模板信号；
- DOM 已有交互、实验、可视化或代码区域，但画像仍标为 `article + none` 的潜在不匹配。
- 正文超过约 7000 字符时的阅读密度风险，以及长正文包含至少 6 个二级标题但没有目录的情况；已有 `.side-nav` 等原生目录，或页面通过全局 `nav.js`/`page-framework.js` 且满足相同运行时门槛时，视为具备目录能力，不重复提示 `long-content-without-toc`；`long-content` 阅读密度提示仍保留；
- 主内容固定或最小宽度达到 1280px 的潜在横向溢出；
- 三列网格只有在断点中明确降为单列、纵向堆叠、隐藏次要面板或提供移动端面板切换时，才视为已有响应式兜底；仅存在 `max-width` 媒体查询但断点内仍保持三列，仍会提示；
- 至少包含 4 个交互控件的控制栏显式禁止换行，且没有横向滚动或窄屏换行兜底；
- 宽度至少 800px 的 SVG/canvas 没有 `max-width: 100%`，且可视化容器没有横向滚动兜底；
- 显式固定/最小宽度至少 800px 的代码块或表格没有横向滚动或 `max-width` 兜底。

长正文和移动端风险规则是保守的静态指标，只用于生成复核清单，不代表页面一定存在视觉缺陷。控制栏必须同时满足“控件较多”和“显式禁止换行”，图形、代码及表格必须出现明确的大尺寸声明，才会报告风险；普通内容、仅依赖 intrinsic size 的图形不会被批量提示。脚本会排除脚本、样式、导航和页脚文本，避免把源码内容误计为正文。

审计同时守护公共阅读工具契约：运行时目录、阅读进度、返回顶部和原生侧栏折叠的稳定标识及关键无障碍属性由单元测试与 `page-framework.js` 源码进行保守比对。审计不会执行页面脚本；交互实验和全屏实验仍排除在自动目录资格之外。

画像不匹配目前是迁移提示，不阻断测试。缺少结构化画像属于错误；可使用 `node scripts/layout-audit.js --strict` 让此类错误返回非零状态。

## 迁移原则

1. 先审计并修正画像，避免按目录猜测模板。
2. 优先通过公共 CSS 变量和附加类优化宽度、间距及响应式行为。
3. 只有语义缺失或现有结构无法满足可访问性时，才修改原页面元素。
4. 每次迁移一个模板族，并保留代表页面的集成与视觉回归检查。
