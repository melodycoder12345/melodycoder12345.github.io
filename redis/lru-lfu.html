LRU / LFU

LRU/LFU 在容量有限时决定保留哪些数据，连接 Redis 淘汰、Buffer Pool 和多级缓存。

CacheLRULFU
B 类型页面重点是把背景、术语、机制、误区和工程场景讲清楚；本页不强行加入动画。
核心术语
LRU最近最少使用，强调时间局部性。
LFU最不经常使用，强调访问频率。
近似采样Redis 为降低成本，不维护全局精确排序。

背景

缓存永远有容量上限。淘汰策略要在访问新鲜度、访问频率和维护成本之间取舍。

运行机制

  • LRU 访问后刷新最近访问时间，淘汰最久未访问候选。
  • LFU 更新访问频率，并随时间衰减。
  • Redis 在采样集合中选择最差候选，降低维护精确链表的开销。

常见误区

  • LRU 容易被一次性扫描污染。
  • LFU 对新热点响应慢，需要衰减和初始频率策略。

工程场景

  • 缓存穿透、热点 key、Buffer Pool 页替换和 CDN 缓存都要理解淘汰策略。

边界判断

判断这个概念是否适用时，先看它解决的核心约束，再看代价是否落在业务可接受范围内。不要只记名字，要能说清楚它牺牲了什么、保留了什么。

学习路径
