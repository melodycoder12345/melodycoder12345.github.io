Redis 集群原理

Redis Cluster 通过 16384 个哈希槽将数据分片到多个主节点，配合 Gossip 协议感知集群拓扑变化，主从自动故障转移保证高可用，实现水平扩展的分布式缓存方案。

  • MOVED / ASKMOVED 永久重定向到正确节点；ASK 在迁移中临时指引客户端。
  • Gossip (PING/PONG)节点间每秒随机交换心跳和集群状态，去中心化传播拓扑。
  • PFAIL -> FAIL超时疑似下线(PFAIL)经多数主节点确认后升级为已下线(FAIL)。

背景与机制

Redis Sentinel 提供高可用但无法水平扩展数据容量。Cluster 模式将 16384 个 slot 分布到 N 个主节点，每个节点只存部分数据，通过 Gossip 去中心化同步拓扑。

  • slot 数量固定 16384：心跳包用 2KB 位图表示，带宽友好；理论上限 1000 节点。
  • 客户端缓存 slot-to-node 映射表，直连目标节点，避免中心代理瓶颈。
  • 集群要求所有 16384 slot 被覆盖才对外提供服务（可配 cluster-require-full-coverage no 放宽）。

常见误区

  • Slot 不等于分区：slot 是逻辑概念，不是物理隔离；同节点的多个 slot 共享内存和线程。
  • MOVED 是正常行为：首次连接或 slot 迁移后收到 MOVED 是预期内的，Smart Client 只需更新路由表。
  • 不保证强一致：主从异步复制，极端情况下故障转移会丢失最后几笔写入（可开 WAIT 命令等待 N 个副本确认）。
  • 多 key 操作必须同 slot：MGET/MSET/Pipeline 跨 slot 会报错，需用 hash tag {} 约束。

工程场景

  • Hash Tag：{user:1}.name 和 {user:1}.age 用相同 hash tag 保证落在同一 slot，支持事务和 Lua 脚本。
  • Pipeline 陷阱：Pipeline 命令会被按 slot 拆分到不同节点并行执行，客户端需聚合结果；跨 slot 的原子性无法保证。
  • 扩缩容：使用 redis-cli --cluster reshard 在线迁移 slot，迁移期间 ASK 重定向保证请求不丢。
  • SDK 示例：go-redis NewClusterClient 自动路由；设置 RouteByLatency 读取就近副本，MaxRedirects 控制重定向次数。

边界与恢复

  • 最大节点数：官方建议不超过 1000 节点，Gossip 消息量随节点数平方增长。
  • 跨 slot 限制：不支持跨 slot 的 MULTI/EXEC 事务；Lua 脚本所有 key 必须属于同一 slot。
  • 脑裂保护：少数派分区的主节点在 cluster-node-timeout 后拒绝写入（变为 FAIL 状态）。
  • 手动故障转移：CLUSTER FAILOVER 支持运维场景下的平滑主从切换，不丢数据。
