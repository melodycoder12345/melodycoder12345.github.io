Redis 基础知识

学前必读，掌握核心原理
Redis（Remote Dictionary Server） 是一个开源的内存数据结构存储系统，可用作数据库、缓存和消息代理。 由 Salvatore Sanfilippo 于 2009 年创建，以极高的读写性能著称——单机可支持 10万+ QPS。

⚡ 缓存加速

将热点数据放入 Redis，绕过慢速数据库。典型场景：商品详情页、用户信息缓存。

🔑 Session 存储

分布式系统中共享会话状态。SET session:{token} data EX 3600 实现带过期的会话。

🏆 排行榜

利用 ZSet 有序集合，ZADD leaderboard score user，ZREVRANGE 获取 Top N。

📡 Pub/Sub

发布订阅消息系统。SUBSCRIBE channel 订阅，PUBLISH channel message 发布。

⏱️ 限流计数

INCR + EXPIRE 实现时间窗口限流。每次请求 INCR key，超过阈值则拒绝。

🔒 分布式锁

SET lock_key uuid NX PX 30000 原子获取锁，Lua 脚本原子释放，防止超卖等并发问题。

数据类型 内部编码 典型使用场景 常用命令
String int embstr raw 缓存、计数器、分布式锁、session SET GET INCR EXPIRE TTL
List listpack quicklist 消息队列、最新动态、时间轴 LPUSH RPUSH LPOP RPOP LRANGE
Hash listpack hashtable 用户信息、商品属性、对象存储 HSET HGET HGETALL HMSET
Set listpack hashtable 标签系统、好友关系、去重统计 SADD SMEMBERS SINTER SUNION
ZSet listpack skiplist+hashtable 排行榜、优先队列、时间序列 ZADD ZRANGE ZREVRANGE ZSCORE
内部编码自动升级： Redis 会根据元素数量和大小自动在紧凑编码（如 listpack）与高效编码（如 hashtable/skiplist）之间切换。 例如 Hash 元素超过 128 个或单个 field/value 超过 64 字节时，从 listpack 升级为 hashtable。

🔄 单线程模型

Redis 命令执行使用单线程，避免锁竞争，简化并发控制

  • 所有命令在一个线程中串行执行
  • 天然保证原子性，无需加锁
  • 避免线程切换开销
  • Redis 6.0+ I/O 多线程读写，命令仍单线程
// 命令队列示意
Client1: SET key1 v1 →
Client2: GET key2    → // 排队等待
Client3: INCR cnt   → // 串行执行

⚡ I/O 多路复用

用 epoll/kqueue 同时监听多个客户端连接，高效处理并发

  • 单线程处理万级并发连接
  • 事件驱动，就绪才读写
  • 非阻塞 I/O，CPU 不等待
  • 文件事件 + 时间事件双循环
// epoll 事件循环
for {
  events := epoll.Wait()
  for _, e := range events {
    handleEvent(e) // 单线程处理
  }
}
为什么 Redis 快？ ① 纯内存操作（μs 级）② 单线程避免锁竞争 ③ I/O 多路复用处理大量连接 ④ 高效数据结构（SDS、listpack、quicklist、跳表）⑤ 批量操作 Pipeline 减少网络往返。
