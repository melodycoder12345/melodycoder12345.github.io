Redis 内存淘汰策略

当 Redis 使用内存达到 maxmemory 限制时，需要通过淘汰策略（eviction policy）选择并驱逐部分 key 以释放空间。支持 noeviction、LRU、LFU、volatile-ttl 等 8 种策略，各有适用场景。

maxmemoryLRULFUvolatileallkeys
核心术语
  • maxmemory内存上限配置，达到后触发淘汰或拒绝写入。
  • 采样淘汰随机取 N 个 key 选最差的淘汰，避免全局扫描。
  • Morris Counter8bit 对数计数器，LFU 核心数据结构。
  • TTL过期时间，volatile 策略的筛选条件。

背景与机制

Redis 是内存数据库，物理内存有限。当数据量增长超过 maxmemory 后，必须在"拒绝写入"与"淘汰旧数据"之间选择。近似 LRU/LFU 用 O(1) 额外空间（每个 key 仅多 24bit）实现了接近理想算法的效果，是空间换精度的工程权衡。

常见误区

  • 认为 Redis LRU 是精确的双向链表实现。实际是随机采样近似，maxmemory-samples 控制精度。
  • volatile-* 策略在没有带 TTL 的 key 时等同于 noeviction，会直接报错。
  • LFU counter 最大 255，不是真实访问次数，是对数近似值。

工程场景

  • 纯缓存：maxmemory-policy allkeys-lru 或 allkeys-lfu
  • 会话存储：volatile-lru 保护无 TTL 的配置 key
  • 采样精度：maxmemory-samples 10（默认5，越大越精确）
  • LFU 调参：lfu-log-factor 10（增长速度）、lfu-decay-time 1（衰减分钟）
  • 监控：INFO memory 关注 used_memory / maxmemory / evicted_keys

边界与恢复

动画覆盖：内存增长 → 触发淘汰 → noeviction 拒绝 → allkeys-lru 采样 → volatile-lru 筛选 → LFU 频率淘汰 → LFU 衰减 → volatile-ttl → 释放恢复。关注采样框高亮与节点颜色变化理解淘汰流程。
