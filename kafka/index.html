Apache Kafka 是什么？

Kafka 是由 LinkedIn 开发、Apache 开源的分布式流式处理平台， 本质上是一个高吞吐量的分布式消息队列。 它以 Topic 为单位组织消息， 以 Partition 实现并行， 以 Replica 实现高可用。

三大核心能力：
1. 解耦：Producer 和 Consumer 独立扩展，无需直接通信
2. 缓冲：应对突发流量，削峰填谷，保护下游服务
3. 流处理：实时数据管道，与 Flink/Spark 结合做流计算

典型使用场景

🛒 电商订单系统

下单后发消息到 Kafka，库存服务、物流服务、积分服务异步消费，彻底解耦

📊 实时数据采集

日志收集、用户行为埋点，统一写入 Kafka，下游 Flink 实时分析

⚡ 流式计算

Kafka Streams / Flink 消费 Topic，实时计算 UV、PV、告警阈值

概念 类比理解 关键属性 说明
Broker 邮局 broker.id, host:port Kafka 服务节点，负责消息的存储和转发，多个 Broker 组成集群
Topic 频道 / 邮箱 name, partitions, replication-factor 消息的逻辑分类，Producer 向 Topic 写入，Consumer 从 Topic 读取
Partition 信道 / 队列分片 partition-id, leader, followers Topic 的物理分片，每个 Partition 是有序的消息日志，实现并行读写
Offset 页码 / 书签 数字，单调递增 消息在 Partition 中的唯一位置标识，Consumer 通过 Offset 记录消费进度
Producer 寄件人 acks, batch.size, linger.ms 消息生产者，将消息发送到指定 Topic，可指定 key 控制路由到哪个 Partition
Consumer Group 收件团队 group.id, partition assignment 消费者组，同一 Topic 的每个 Partition 只由组内一个 Consumer 消费，实现负载均衡
Replica / ISR 备份 / 活跃备份列表 leader, follower, ISR set 每个 Partition 可有多个副本，ISR (In-Sync Replica) 是追上 Leader 的副本集合
特性 Kafka RabbitMQ RocketMQ

消息回溯 支持按 Offset 回溯 不支持 支持按时间回溯
消息顺序 Partition 内有序 队列内有序 队列内有序

生态集成 Flink/Spark 原生支持 Spring 生态好 阿里云生态
适用场景 日志、大数据流处理 复杂路由、RPC 金融事务、顺序消息
选择建议： 日志收集、大数据实时处理 → Kafka； 复杂路由、低延迟 RPC → RabbitMQ； 电商秒杀、金融事务 → RocketMQ
