分布式共识与 etcd

后端和架构师需要理解的是：多数派如何保证唯一决定、网络分区时系统为何可能停止写入，以及 etcd 提供的能力边界。生产系统通常使用成熟 Raft 实现，而不是手写 Paxos。

业务优先看 Raft / etcd配置、选主、租约和元数据场景首先评估成熟系统的 API 与故障边界。
Paxos 保留为理论对照理解多数派交集与已选值不可被推翻即可，协议推演放在按需动画中。
共识不等于业务事务它复制决定或日志，不会自动解决跨服务补偿、幂等和业务不变量。
工程结论：需要强一致配置、选主或小规模元数据时，可使用 etcd 等成熟协调系统；高吞吐业务数据通常应由数据库或专用存储承担。只有在评估共识实现、故障恢复或论文机制时，才深入 Paxos 消息细节。
