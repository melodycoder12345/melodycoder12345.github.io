LLM 推理增强

单纯的 prompt-answer 在复杂推理任务上准确率有限。CoT 通过中间步骤引导推理，ToT 将搜索空间展开为树并剪枝，ReAct 交替推理和工具调用，Self-Consistency 多路采样投票提升稳健性——这些技术无需微调即可大幅提升 LLM 推理能力。

核心观察
中间步骤即计算CoT 生成的推理链不只是解释，本质上是让模型在 token 序列上执行分步计算，突破单次前向传播的推理深度限制。
搜索 vs 生成ToT 将 LLM 推理转化为搜索问题，通过模型自评估引导剪枝，适合答案空间离散的规划任务。
工具调用扩展边界ReAct 让模型知道自己不知道什么，通过 Action 获取实时信息，解决纯参数知识的时效与精度瓶颈。

工程意义
显式 CoT 提示可提升部分大模型在数学和符号推理基准上的表现，但并非所有 API 的默认行为，也不保证忠实解释模型内部计算。部分推理模型会使用未公开的内部推理过程；公开资料不足以把特定训练目标概括为“内化 CoT”。ToT 适合 Agentic 任务中的计划阶段，但多次 LLM 调用成本高，需在探索深度与 token 开销间权衡。ReAct 是许多 LLM Agent 实现采用的范式之一。

    
失败模式
  • CoT 幻觉传播：推理链中间步骤出现幻觉会传导到最终答案，且用户难以察觉。
  • ToT 评估偏差：模型自评估节点价值时存在自我确认偏差，可能剪掉正确路径。
  • ReAct 工具滥用：模型在不需要工具时也倾向于调用，增加延迟和成本。
  • Self-Consistency 成本：多路采样（通常 40 路）会将推理成本扩大数十倍。
