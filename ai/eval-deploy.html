AI 评测与部署

AI 应用上线最难的不是“能不能回答”，而是回答质量是否稳定、成本是否可控、延迟是否可接受、错误是否能被发现和回滚。评测与部署要把 Prompt、模型、检索、工具和观测纳入同一个版本闭环。

Golden SetCanaryObservabilityRollback
上线闭环
离线评测用固定样本比较质量、格式、引用、拒答、幻觉和安全边界。
在线灰度用真实流量观察延迟、成本、工具失败、用户反馈和 fallback 触发。
持续回归每次改 Prompt、模型、RAG 参数或工具 schema，都要跑回归集。

评测维度

  • 任务正确性：答案是否解决用户问题，是否遗漏关键约束。
  • 事实一致性：是否引用了检索材料，是否编造不存在的事实。
  • 格式稳定性：JSON、Markdown、函数参数是否满足下游解析要求。
  • 安全边界：Prompt injection、越权工具、隐私泄露和危险操作是否被拦截。
  • 成本与延迟：输入 token、输出 token、检索耗时、首 token 延迟和总耗时。

版本化对象

AI 应用的版本不只是一段代码。模型、system prompt、few-shot、检索参数、chunk 策略、reranker、tool schema、安全策略都可能改变输出。

release = {
  model: "gpt-x",
  prompt_version: "support-v18",
  retriever: { top_k: 8, rerank: true },
  tools: ["search_docs@3", "create_ticket@2"],
  guardrail: "policy-2026-06"
}

部署策略

  • Shadow：复制流量给新版本，不影响用户，用来比较结果和成本。
  • Canary：少量用户真实使用，失败时快速回退到旧版本。
  • A/B：比较两个策略对业务指标的影响，例如解决率、转人工率、满意度。
  • Fallback：模型超时、工具失败、置信度低时走模板、检索结果或人工兜底。

排障信号

  • 首 token 延迟升高：通常来自 prefill、检索、rerank 或模型队列拥塞。
  • 回答变长：输出 token 成本上升，也可能说明 prompt 约束失效。
  • 工具失败率升高：检查 schema 变更、权限、网络、超时和重试风暴。
  • 引用缺失：检查 chunk、top-k、rerank、prompt compose 和上下文截断。
上线前先问：如果新版本开始胡说、变慢、变贵或调用错工具，我们能在几分钟内发现并回滚吗？
