LLM 基础概念

LLM 不是“数据库里查答案”，而是基于上下文预测下一个 token 的概率模型。理解 Token、Embedding、训练阶段、上下文窗口和对齐，是阅读推理、RAG、Agent 页面的前置知识。

模型到底在做什么

自回归 LLM 的核心任务是：给定前面的 token 序列，预测下一个 token。训练时它看大量文本，学习“在这个上下文里，哪些 token 更可能出现”。推理时它反复采样下一个 token，再把新 token 放回上下文继续预测。

  • 不是精确检索：模型参数中压缩了训练语料里的统计规律，但不会像数据库一样保存可定位记录。
  • 不是固定规则引擎：同一个 prompt 在不同温度、采样策略和上下文下可能输出不同结果。
  • 不是无限记忆：上下文窗口之外的信息不会被当前推理直接看到，除非通过 RAG、Memory 或微调进入模型行为。

从文本到向量

文本先被 tokenizer 转成 token id，再通过 embedding table 查出向量。位置编码或 RoPE 提供顺序信息，Transformer 层通过 Attention 让每个 token 和上下文里的其他 token 建立关系。

text = "KV Cache saves compute"
tokens = tokenizer.encode(text)
vectors = embedding[tokens]
hidden = transformer(vectors, position)
next_token = sample(lm_head(hidden[-1]))
Embedding 不是“词典解释”，而是一个高维空间里的坐标。语义相近的 token 或句子通常距离更近，这也是 RAG 向量检索成立的基础。

训练阶段

  • Pretraining：用海量文本做 next-token prediction，学习语言、知识和推理模式。
  • SFT：用高质量指令数据训练模型按用户任务作答，把“会续写”转成“会响应”。
  • Alignment：用人类偏好或规则数据约束输出风格、安全边界和拒答策略。
  • Fine-tuning / LoRA：在特定领域或格式上调整模型行为，成本低于从头训练。

常见误区

  • 把参数量当作唯一指标。数据质量、推理策略、上下文工程和工具能力同样重要。
  • 把长上下文当作 RAG 替代品。长上下文能放更多材料，但检索、排序和引用仍需要系统设计。
  • 把 Prompt 当作代码。Prompt 可以表达任务意图，但缺少类型约束、测试覆盖和稳定依赖管理，需要评测闭环兜底。
