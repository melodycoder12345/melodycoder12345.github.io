Agent Tool Calling

Agent 不是模型自己“会操作世界”，而是宿主系统让模型规划、选择工具、接收 observation，再继续推理。可靠 Agent 的关键是权限、状态、错误处理和停止条件。

设计边界
模型只提议真正执行工具的是应用系统，必须校验权限、参数和副作用。
循环要有刹车最大步数、超时、预算和人工确认能避免无限调用。
Observation 要可追溯工具结果、错误和重试都应进入日志，方便回放与评测。

工程场景
客服自动化、代码助理、数据分析机器人和运维助手都属于 Agent 场景。它们的共同点是模型需要读取上下文、调用外部工具，并根据结果继续行动。
风险点
  • Prompt injection 可能诱导 Agent 忽略系统规则或泄露工具结果。
  • 工具 schema 过宽会扩大破坏面，写操作最好显式确认或分级授权。
