微调（Fine-tuning）

微调让预训练模型适应特定任务或领域，而不是从头训练。SFT 用高质量指令数据对齐任务格式，LoRA 通过低秩分解只更新少量参数，大幅降低计算成本。

SFTLoRAPEFT指令数据
核心术语
SFT（Supervised Fine-Tuning）用人工标注的指令-回答对训练模型，把预训练模型从"续写"能力转变为"指令跟随"能力。训练时只计算 output 部分的 loss，系统提示和指令部分的 loss 被 mask 掉。
LoRA（Low-Rank Adaptation）在原始权重矩阵 W 旁边插入低秩矩阵 A×B，只训练 A 和 B，参数量仅为原来的 0.1%-1%。推理时合并为 W_new = W + α×B×A，零额外延迟。
PEFT（参数高效微调）包含 LoRA、Prefix Tuning、P-Tuning 等方法，用小量可训练参数达到接近全量微调的效果，核心思想是"冻结大部分权重，只调整少量参数"。

全量微调 vs LoRA

      
全量微调更新模型所有参数，对 7B 模型需要约 40-80 GB GPU 显存（FP32 梯度+优化器状态），大多数团队无法承担。LoRA 只需训练 0.1%-1% 的参数，显存降低 4-8 倍，同时效果接近全量微调。

      
    
        
  • 参数量对比：7B 全量 = 7×10⁹ 参数；LoRA rank=8 ≈ 400万参数
    • 
        
  • 显存对比：全量 7B 需要 ≥56GB；LoRA 可在 16GB 单卡运行
    • 
        
  • 效果对比：大多数任务 LoRA ≈ 全量，特殊领域适配略差
    • 
        
  • QLoRA：用 4-bit 量化加载基础权重 + LoRA，进一步降低到 6-8GB
    • 
      

    

    

      
LoRA 超参数选择

      
LoRA 的三个核心超参：rank、alpha 和 target modules，直接影响微调效果和成本。

      
    
        
  • rank（r）：低秩矩阵的秩，常用 4、8、16、32。rank 越大，可学习容量越强，但显存越多。通常从 8 开始调。
    • 
        
  • alpha（α）：缩放系数，实际更新量 = α/r × B×A。通常设 alpha=2×rank。
    • 
        
  • target modules：通常微调注意力层的 q_proj、v_proj。复杂任务可以加 k_proj、o_proj 甚至 FFN 层。
    • 
      

      
from peft import LoraConfig, get_peft_model

config = LoraConfig(
    r=8, lora_alpha=16,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05, bias="none",
    task_type="CAUSAL_LM"
)
model = get_peft_model(base_model, config)

    

    

      
数据质量 > 数据数量

      
SFT 的核心原则：用 1000 条高质量指令数据往往优于 100万条低质量数据。数据构造的关键原则：

      
    
        
  • 多样性：覆盖目标任务的各种子类型、难度和风格，避免分布偏差。
    • 
        
  • 格式一致性：系统提示、指令、输出的格式要统一，模型会学习模板本身。
    • 
        
  • 输出质量：宁可少但精，低质量回答会直接降低模型表现，比没有数据更坏。
    • 
        
  • Alpaca 格式：{"instruction": "...", "input": "...", "output": "..."} 是常见的指令数据格式。
    • 
        
  • 去重和过滤：用相似度去重，过滤过短、过长或格式错误的样本。
    • 
      

    

    

      
常见问题与解决方案

      
    
        
  • 灾难性遗忘：微调后模型丧失通用能力。缓解方法：混入通用数据、降低学习率、减少 epoch。
    • 
        
  • 过拟合：训练 loss 降低但验证集变差。监控验证集 loss，设 early stopping，数据增强。
    • 
        
  • Domain Shift：微调数据分布和实际使用场景不一致，导致泛化差。需要构造更接近生产分布的数据。
    • 
        
  • 格式不稳定：模型在推理时不遵循输出格式。检查 prompt 模板一致性，增加格式错误的负例。
    • 
      

      
调参顺序建议：先确保数据质量，再选择 LoRA 超参，最后调学习率和 epoch。不要在数据质量差的情况下大量调参。
