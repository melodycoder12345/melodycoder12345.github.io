模型融合

Model Merging 让我们无需重新训练，直接通过合并多个微调模型的权重来组合不同专业能力——将代码能力、数学推理、安全对齐融合进同一个模型。核心洞见是：微调改变的增量权重（任务向量）可以像向量一样叠加。SLERP 做两模型的球面插值，Task Arithmetic 支持多任务向量相加，TIES/DARE 解决参数冲突。Mergekit 等开源工具让这一切在 CPU 上就能完成，无需 GPU。

为什么需要模型融合？

  • 微调成本高：每次全参数微调需要数十到数百 GPU 小时；融合已有的微调模型，几分钟 CPU 时间就能组合新能力，成本接近零
  • 组合专业能力：单次微调让模型专注一个方向（代码/数学/安全）；通过融合可以将多个专家模型的能力合并进同一个检查点
  • 不需要原始训练数据：许多微调模型的训练数据不公开；模型融合完全基于权重文件，无需访问数据
  • Mergekit 生态：arcee-ai/mergekit 提供 YAML 配置一键完成融合，Hugging Face 上存在大量社区融合模型（如 Mistral、LLaMA 的多种融合变体）
  • DARE+TIES 的突破：2023-2024 年研究表明，稀疏化后融合多个模型不仅可行，甚至可以超过单独任意一个基础模型
局限前提：所有要融合的模型必须来自同一基座（same base model）且架构相同，Llama-3-8B 的微调版不能与 Mistral-7B 的微调版直接融合。

Task Arithmetic 详解

  • 任务向量定义：τ_i = θ_ft_i − θ_base，即微调模型权重减去预训练基座权重，表示"微调在参数空间中移动的方向和幅度"
  • 融合公式：λ 是缩放系数（通常 0.3～0.7），控制任务向量对基座的影响程度
θ_merge = θ_base + λ · (τ₁ + τ₂ + … + τₙ)
  • 向量减法（遗忘）：θ_merge = θ_base − λ · τ_toxic，用负号可以消除某种能力（如有毒内容生成）
  • 多任务融合：将代码向量、数学向量、安全向量相加，理论上得到三者兼备的模型
  • 参数干扰问题：向量之间并非正交，直接相加时参数相互干扰，任务数量越多效果越差；这也是 TIES/DARE 需要解决的问题

SLERP 球形插值

  • 问题背景：线性插值（LERP）在中间点时向量长度缩短（趋近于零），导致模型能力下降。SLERP 在超球面上等速率弧线插值，保持向量长度不变
  • 公式：
SLERP(θ₁, θ₂, t) = sin((1-t)·Ω)/sin(Ω) · θ₁ + sin(t·Ω)/sin(Ω) · θ₂
Ω = arccos(θ₁·θ₂ / (‖θ₁‖·‖θ₂‖))，t ∈ [0,1]
  • 适用场景：融合两个模型（只支持两路）；同基座的两个微调变体，例如 Instruct 版本与 Chat 版本的平衡
  • t=0.5 的含义：两个模型能力等权重融合，t 偏向 0 时更接近 θ₁，偏向 1 时更接近 θ₂
  • 与 LERP 对比：向量角度大时 SLERP 明显优于 LERP；角度接近零时两者效果相近。实际权重矩阵的差异通常足够大，推荐优先使用 SLERP
import torch

def slerp(t: float, w1: torch.Tensor, w2: torch.Tensor) -> torch.Tensor:
    w1_flat = w1.flatten()
    w2_flat = w2.flatten()
    # 计算夹角 Ω
    cos_omega = (w1_flat @ w2_flat) / (w1_flat.norm() * w2_flat.norm())
    cos_omega = cos_omega.clamp(-1, 1)
    omega = torch.acos(cos_omega)
    if omega.abs() < 1e-6:  # 近似平行，退回线性插值
        return (1 - t) * w1 + t * w2
    sin_omega = torch.sin(omega)
    return (torch.sin((1 - t) * omega) / sin_omega * w1_flat +
            torch.sin(t * omega) / sin_omega * w2_flat).reshape(w1.shape)

TIES / DARE 方法

  • 问题根源：多个任务向量直接相加时，不同任务的参数更新方向可能相互抵消（符号冲突）或干扰，导致融合后性能低于预期

DARE（随机丢弃稀疏化）：以概率 p 随机将任务向量中的参数置零，剩余参数按 1/(1-p) 缩放补偿，降低参数间干扰密度。类似 Dropout 的思路，实验证明 p=0.9 时效果仍然保持。

TIES 三步流程：

  • ① Trim（裁剪）：对每个任务向量，仅保留绝对值最大的 top-k% 参数，其余置零，减少噪声干扰
  • ② Elect Sign（选举符号）：对每个参数位置，统计所有任务向量中该位置正值之和 vs 负值之和，取绝对值更大的方向作为最终符号，解决符号冲突
  • ③ Merge（融合）：对符号一致的参数取均值（或加权平均），符号不一致的参数丢弃
实验效果：TIES 在融合 7 个任务向量时，比直接 Task Arithmetic 平均提升 2-4%；DARE 可以将稀疏率提高到 90%，同时仅损失 1% 以内的性能。

Task Arithmetic 实现代码

import torch
from transformers import AutoModelForCausalLM

def task_arithmetic_merge(
    base_path: str,
    finetuned_paths: list[str],
    lam: float = 0.4
) -> dict:
    """Task Arithmetic 模型融合"""
    base = AutoModelForCausalLM.from_pretrained(base_path)
    base_sd = base.state_dict()

    # 收集所有任务向量
    task_vectors = []
    for path in finetuned_paths:
        ft_sd = AutoModelForCausalLM.from_pretrained(path).state_dict()
        tv = {k: ft_sd[k].float() - base_sd[k].float()
              for k in base_sd}
        task_vectors.append(tv)

    # 将所有任务向量求和后叠加到基座
    merged = {}
    for k in base_sd:
        tv_sum = torch.stack([tv[k] for tv in task_vectors]).sum(0)
        merged[k] = base_sd[k].float() + lam * tv_sum
    return merged

# Task Vector 减法：削弱 toxic 能力
def negate_task_vector(base_sd, toxic_sd, lam=0.3):
    tv_toxic = {k: toxic_sd[k].float() - base_sd[k].float()
                for k in base_sd}
    return {k: base_sd[k].float() - lam * tv_toxic[k]
            for k in base_sd}

局限与工程场景

  • 同架构同基座限制：融合的所有模型必须来自完全相同的基座（相同的权重初始化），Llama 3.1 8B Instruct 的各种微调版可以互相融合，但 Llama 3.1 8B 与 Mistral-7B-v0.3 不可融合
  • 能力平均化：融合后的模型在各任务上通常接近所有源模型的平均水平，而不是取每个任务的最优值；若需某一任务最佳，仍应使用该任务的专用微调版
  • 量化兼容性：融合前需要将模型反量化到 float32 或 bfloat16，融合后可再次量化（GPTQ/AWQ），整个流程需要 2-3× 模型大小的 RAM
  • 生产中的用法：融合模型通常用于 "capability combination" 原型验证，快速测试多能力组合效果；商业部署时仍需完整评估各任务 benchmark（MMLU、HumanEval、GSM8K 等）
  • 输出乱码问题：融合参数冲突严重时，模型可能重复输出或乱码；调低 λ（0.1-0.3）或使用 TIES 稀疏化可缓解，也可以检查各任务向量的 L2 范数是否差异悬殊
  • 跨架构融合研究：LinearMoE、FrankenMerge（拼接不同模型的层）等方法可部分突破同架构限制，但需要额外对齐训练，仍处于研究阶段
经验法则：λ 总和控制在 0.5-1.0 之间；多个任务向量时建议先用 DARE（density=0.5）稀疏化后再融合；融合后必须在目标任务上跑 eval 验证，不要直接发布。
