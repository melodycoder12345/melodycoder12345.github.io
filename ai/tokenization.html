BPE 分词

BPE（Byte-Pair Encoding）是 GPT 系列使用的分词算法。它从单字符开始，每轮统计语料中相邻符号对的频次，合并最高频的一对为新 token，反复迭代直到词表达到目标大小。动画逐步展示字符格的合并过程、频次统计气泡、词表的增长，以及同一个词在不同上下文中被切分成不同 token 的现象。

BPE 算法流程

  • 初始化：将语料中每个词拆成字符序列，添加词尾标记（如 </w>）
  • 统计频次：遍历所有相邻符号对，统计在全语料中出现的次数
  • 合并最高频：找到频次最高的对 (a, b)，将所有出现的 a b 替换为 ab
  • 更新词表：将合并规则 a+b→ab 添加到合并规则列表
  • 重复：重复上述过程直到词表大小达到目标（如 50257 for GPT-2）
  • 推理编码：按学到的合并规则顺序对新文本进行贪心编码

不同 Tokenizer 对比

  • BPE（GPT 系列）：字节级 BPE，语言无关，词表约 50k–100k
  • WordPiece（BERT）：类似 BPE，但合并选择基于似然而非频次，用 ## 前缀标记子词
  • SentencePiece（T5/Llama 等）：它是直接从原始句子训练的 tokenizer 工具包，可使用 Unigram 或 BPE；具体模型采用哪种算法需查其 tokenizer 配置
  • 字符级：无 OOV，但序列长、注意力计算昂贵
  • 词级：序列短，但词表大、OOV 严重、形态变化无法共享

Token 与模型训练

  • 模型输入是 token ID，不是字符；词嵌入表（Embedding）大小 = 词表大小
  • Token 边界效应："unhappiness" 可能切成 "un", "happiness" 或 "un", "hap", "pi", "ness"
  • 字符与 token 的比例由词表和文本分布决定；语言、空格、大小写、代码和生僻字都会改变结果，应使用目标模型 tokenizer 实测
  • 上下文窗口（如 8192）是 token 数而非字符数
  • Tiktoken（OpenAI）：BPE 的 Rust 高性能实现，GPT-4 使用 cl100k_base 词表
  • 特殊 token：<|endoftext|>、<|im_start|> 等标记对话格式

同词异分词现象

  • "lower" → ["low","er"] 或 ["lower"]，取决于语料频次和合并顺序
  • 大小写影响：" Hello" 和 "Hello" 是不同 token（前者有空格前缀）
  • 数字：可能按单个数字或多位片段切分，具体结果随 tokenizer 词表和正则预分词规则变化
  • 多语言：非英文字符在词表较少，中文字符平均消耗 token 更多
  • 工程意义：Prompt 长度 = token 数 ≠ 字符数，计费和上下文限制都基于 token
