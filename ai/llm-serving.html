LLM 推理服务

大型语言模型的推理服务需要解决 GPU 显存的高效利用问题。传统方式预留连续大块显存导致严重碎片，PagedAttention 将 KV Cache 分成固定页通过页表映射，碎片接近零。连续批处理让 GPU 始终满载。动画展示显存网格的分配状态、页表映射、多请求并行 decode 的 batch 组成。

核心术语
  • KV Cache缓存已计算的 Key/Value 矩阵，避免重复计算注意力。

  • 连续批处理请求完成即离开 batch，新请求立即加入，GPU 持续满载。

传统 vs PagedAttention 显存对比

  • 传统（连续分配）：为每个请求预留最大序列长度的连续显存，即使输出很短也占满
  • 碎片问题：预留空间用不完，空间已分配但未使用（内部碎片），且无法被其他请求使用
  • PagedAttention：KV Cache 分成固定大小的 page（如 16 tokens），按需分配物理页
  • 逻辑/物理解耦：逻辑上连续的 token 序列，物理上可以存在不连续的页中
  • 结果：显存碎片率从 60–80% 降到 <4%，单 GPU 并发请求数提升 3–4×

连续批处理原理

  • 静态批处理：等待一批请求都完成才处理下一批，先完成的请求等待其他请求，GPU 空置
  • Iteration-level scheduling：每个 decode step 都是一个独立的 forward pass
  • 动态 batch：每个 step 都可以加入新请求的 prefill 或移除完成的请求
  • Prefill 插入：新请求 prefill 结束后立即加入 decode batch 的下一步
  • 吞吐量提升：相比静态批处理，吞吐量提升 10–20×（vLLM 实测数据）

推理优化技术

  • 量化（Quantization）：FP16 → INT8/INT4，显存减半，精度略损
  • Flash Attention：重新实现注意力计算的内存访问模式，减少 HBM 读写
  • Speculative Decoding：小模型先生成多个候选 token，大模型并行验证
  • Tensor Parallelism：将模型权重矩阵按列/行切分到多 GPU，减少单卡显存占用
  • Prefix Caching：相同 system prompt 的 KV Cache 在多请求间共享

推理服务架构

  • vLLM：PagedAttention + 连续批处理的开源参考实现，支持 OpenAI 兼容 API
  • TGI（HuggingFace）：Rust gRPC server + Python 推理，支持流式输出
  • TensorRT-LLM：NVIDIA 专有编译优化，A100/H100 上性能最高
  • 调度层：多副本负载均衡，按队列深度或 GPU 利用率路由
  • Token 流式输出：Server-Sent Events（SSE），每生成一个 token 立即推送
  • SLA：TTFT（首 token 延迟）和 TPS（tokens/sec）是主要指标
