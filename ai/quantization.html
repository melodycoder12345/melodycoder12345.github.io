模型量化

量化用较低位宽表示权重或激活，通常减少模型存储和内存带宽；是否降低端到端延迟取决于量化范围、内核、硬件、batch 和反量化开销。

INT8INT4AWQGPTQQAT
核心权衡
位宽 vs 内存裸权重的理论位宽可从 FP32 的 32 bit 降至 INT8/INT4；实际占用还包含 scale、zero-point、分组元数据、对齐和运行时缓冲。
PTQ vs QATPTQ 在训练后校准或优化量化参数；QAT 在训练中模拟量化误差。耗时和精度差异依模型、数据、量化对象与工具链而定。
权重量化 vs 激活量化仅权重量化通常更容易部署，但仍是有损近似；激活量化可用静态校准或运行时动态 scale，对离群值和内核支持更敏感。

为什么要量化？

推理成本和可访问性是量化的主要动机。以下用 70 亿参数仅计算裸权重理论下限，不代表某个具体模型或可运行所需显存：

  • FP32：7B × 4 bytes ≈ 28 GB 裸权重（十进制）
  • BF16/FP16：7B × 2 bytes ≈ 14 GB 裸权重
  • INT8：7B × 1 byte ≈ 7 GB 裸权重，另有量化元数据
  • INT4：7B × 0.5 bytes ≈ 3.5 GB 裸权重，另有量化元数据

低位宽内核在受支持硬件和合适形状上可能提高吞吐，但权重解包、反量化、未量化算子及小 batch 都可能抵消收益，因此不能从位宽直接推导延迟倍率。

量化原理

量化的核心是用有限精度整数近似表示浮点权重，本质是一种有损压缩。

# INT8 对称量化（逐张量）
scale = max(abs(W)) / 127
W_q = round(W / scale).clamp(-128, 127)

# 反量化（推理时还原）
W_deq = W_q * scale

# INT8 非对称量化（逐张量）
scale = (max(W) - min(W)) / 255
zero_point = round(-min(W) / scale)
W_q = round(W / scale + zero_point).clamp(0, 255)
W_deq = (W_q - zero_point) * scale
量化误差 = W - W_deq，这个误差在权重分布不均匀时会很大。这就是为什么逐层、逐通道量化比逐张量量化精度更高。

PTQ vs QAT 对比

两种量化方法在成本、精度和适用场景上有显著差异：

  • PTQ（训练后量化）：
    • 时间：几分钟到几小时（需要校准集）
    • 精度损失：没有跨模型、量化方案和任务通用的百分比，需相对浮点基线评测
    • 适用场景：资源受限，快速部署，不需要重新训练
  • QAT（量化感知训练）：
    • 时间：与微调相当，需要完整训练循环
    • 精度：论文在其模型与任务上报告了较小退化，部署前仍需逐任务评估
    • 适用场景：对精度要求极高，有训练资源
权重 PTQ、动态/静态激活量化和 QAT 各有适用范围；选择取决于目标硬件内核、精度预算、训练资源与模型许可。

GPTQ 和 AWQ

GPTQ 与 AWQ 是常见的 LLM 权重训练后量化方法，两者优化目标和实现生态不同。

  • GPTQ：基于近似二阶信息逐层量化并补偿后续权重，目标是降低层输出重建误差；下游任务损失仍随模型、校准集和配置变化。
  • AWQ（Activation-Aware Weight Quantization）：观察到不是所有权重对精度的贡献相同——激活值（activation）大的通道对应的权重更重要。AWQ 对这些"显著权重"保持更高精度或放大 scale，其他权重正常量化。
# AWQ 核心思路：per-channel scaling
# 找激活值大的通道 → 这些权重更重要
channel_scale = act_percentile(calib_data)  # 每通道激活统计
# 对重要通道 scale up，量化后 scale down，等效提升这些通道精度
W_scaled = W / channel_scale  # 对称变换
W_q = quantize(W_scaled, bits=4)  # INT4 量化

量化粒度

量化粒度决定了 scale 参数的共享范围，粒度越细精度越高，但开销越大。

  • 逐张量（per-tensor）：整个权重矩阵共享一个 scale。最简单，精度最差。适合激活量化的快速实验。
  • 逐通道（per-channel/per-row）：每行或每列独立 scale，通常比逐张量更好地适应离群值，但元数据和内核开销取决于实现。
  • 逐组（group quantization）：每 G 个元素共享一个 scale；较小组通常更精细但元数据更多。组大小是格式与实现配置，不是 GPTQ/AWQ 算法的统一固定值。
实践中：权重用逐通道或逐组量化；激活用逐张量（静态校准）或动态量化（每次推理计算 scale）。

实践选择指南

根据场景选择合适的量化工具和精度：

  • 本地推理（llama.cpp）：支持 Q2_K 到 Q8_0 多种 INT4/INT8 格式，CPU 和 GPU 混合推理，是最易上手的本地部署方案。
  • Python 生态（bitsandbytes）：与 HuggingFace Transformers 深度集成，load_in_8bit=True 或 load_in_4bit=True 一行代码启用，支持与 LoRA 结合（QLoRA）。
  • 离线量化（AutoGPTQ / AutoAWQ）：预量化模型存成 GPTQ/AWQ 格式，上传 HuggingFace Hub 分发，用户下载即用，是推荐的生产分发方式。
  • 推理框架集成：vLLM 原生支持 AWQ/GPTQ；TensorRT-LLM 支持多种量化格式；Ollama 基于 llama.cpp，适合消费级硬件。
# bitsandbytes 4-bit 加载（最简单）
from transformers import AutoModelForCausalLM, BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",       # NormalFloat4
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,  # 二次量化 scale
)
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Meta-Llama-3-8B",
    quantization_config=bnb_config,
    device_map="auto"
)
