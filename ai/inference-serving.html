LLM 推理与服务

在线 LLM 服务本质上是显存、内存带宽、计算和调度的联合优化。架构设计要同时观察首 Token 延迟、逐 Token 延迟、吞吐、并发、成本与质量，而不是只比较模型参数量。

先拆 Prefill 与 Decode两阶段的计算特征不同，延迟瓶颈、批处理策略和扩缩容指标也不同。
优化必须匹配负载请求长度、输出长度、并发和硬件不同，PagedAttention、量化或投机解码的收益会变化。
模型结构不等于服务方案MoE 降低单 Token 激活计算量，但通信、路由与负载均衡仍会成为系统成本。
工程结论：先用真实流量建立 TTFT、TPOT、吞吐、显存和质量基线，再决定连续批处理、KV Cache 管理、量化、并行策略或投机解码；每项优化都应保留可回滚配置和质量回归测试。
