云原生

从 Docker 镜像分层到 Kubernetes 控制面，从 Pod 调度到网络包路径，从弹性伸缩到服务网格。云原生是构建和运行可扩展应用程序的方法论，容器、编排、微服务是其三大支柱。

Docker 镜像分层

Docker/OCI 镜像包含文件系统差异层和镜像配置；RUN、COPY、ADD 等可能改变文件系统，CMD、ENV 等主要记录配置。容器运行时通常叠加可写快照，具体机制由存储驱动决定。

OverlayFSCopy-on-WriteLayer

K8s 控制面

kubectl apply → API Server 认证鉴权和准入 → 对象持久化 → Controller/Scheduler 经 API Server 观察并更新对象 → kubelet 启动容器。etcd 通常只由 API Server 直接访问，部分操作仍存在 API Server 到 kubelet、Webhook 等直接通信。

etcdControllerScheduler

Pod 调度

Filter 阶段淘汰不满足条件的节点（资源/Taint/Affinity），Score 阶段为剩余节点打分加权，最高分节点绑定 Pod。

FilterScoreTaintAffinity

Service 网络包路径

以常见 Linux CNI 与 kube-proxy 数据平面为例观察 Service 转发；实际路径会随 CNI、iptables/IPVS/nftables 或 eBPF 实现而变化，不能把单一路径当成 Kubernetes API 保证。

弹性伸缩 HPA

HPA 周期性读取资源、自定义或外部指标并计算副本建议，再应用容差、稳定窗口和伸缩策略。默认扩容稳定窗口为 0，缩容稳定窗口为 300 秒，均可配置。

HPAmetrics-servercooldown

Serverless / FaaS

开发者只需编写函数，平台负责容器创建与销毁。无请求时实例归零（scale-to-zero），按实际执行时间计费。冷启动、并发扩容、事件驱动完整动画解析。

Lambda冷启动scale-to-zero事件驱动

GitOps / ArgoCD

以 Git 仓库为唯一事实来源，声明式定义集群期望状态。ArgoCD 持续检测 drift（漂移），检测到差异后自动将集群拉回 Git 声明的状态，实现可审计、可回溯的持续交付。

Service Mesh

Istio 可使用 Envoy sidecar，也可使用 ambient 模式的逐节点 ztunnel 与可选 waypoint。数据面覆盖范围和 L4/L7 能力取决于模式、流量捕获及策略配置，并非天然拦截所有流量。

Kubernetes Operator

通过 CRD 描述业务意图（如「MySQL 主从集群 3 副本」），自定义 Controller Reconcile 循环持续将实际状态拉向期望状态，让 K8s 能自动运维有状态应用。

CRDControllerReconcile有状态应用

K8s 存储 PV/PVC

StorageClass 定义存储类型，CSI Driver 动态创建 PersistentVolume，PVC 申请绑定后供 Pod 挂载。Pod 重调度后数据持久保留，支持在线扩容，解决容器无状态的存储困境。

PVPVCCSI动态Provision

Helm 包管理

将多个 K8s Manifest 打包为 Chart，values.yaml 参数化多环境差异，一条命令安装/升级/回滚，支持版本控制和 Hooks（数据库迁移等），大幅简化复杂应用部署。

ChartReleaseValuesHooks

学习路径建议

建议从 Docker 镜像分层（理解容器的基础机制）开始 → K8s 控制面（声明式 API 和 Watch 机制）→ Pod 调度（资源管理）→ Service 网络（流量路由）→ K8s 存储（有状态应用数据持久化）→ Helm（工程化打包部署）→ HPA 弹性伸缩（生产扩缩容）→ Operator（自动化运维有状态服务）→ Serverless（无服务器架构）→ GitOps（声明式持续交付）→ Service Mesh（流量治理与安全）。Linux 模块的容器原理页面是本模块的前置知识。
