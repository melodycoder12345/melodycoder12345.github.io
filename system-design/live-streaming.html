推流协议对比
📡 RTMP
主播端推流标准协议，延迟 1-3s，基于 TCP。OBS/FFmpeg 原生支持。推流稳定，但 Flash 依赖已淘汰，播放侧转 HLS/LLHLS。
⚡ LLHLS (Low-Latency HLS)
Apple 推出的低延迟 HLS，通过 Partial Segments（200ms）+ HTTP/2 Server Push 将延迟降到 2-5s，兼容 HLS 生态。
🔴 WebRTC
最低延迟（< 1s），基于 UDP，抗丢包。适合连麦、PK 场景。复杂度高，CDN 支持有限，不适合大规模分发。
转码与存储

自适应码率（ABR）

输出 1080p(4Mbps) / 720p(2Mbps) / 480p(1Mbps) / 360p(500Kbps) 四档，客户端根据网速自动切换，减少卡顿。

转码集群用 GPU 加速（NVENC），单路 1080p 直播转码 CPU 成本降低 80%。

切片存储

HLS 默认切片 2s，LLHLS 部分切片 200ms。切片存入对象存储，并实时推送到 CDN 边缘节点。

弹幕系统设计

WebSocket 长连接

每个观众持有一个 WebSocket 连接到弹幕服务器（按直播间分组到不同节点）。发送弹幕后广播给同房间所有连接。

时间戳对齐

弹幕附带直播流时间戳（PTS），播放器根据当前播放位置的 PTS 决定弹幕显示时机，保证弹幕与画面同步。
