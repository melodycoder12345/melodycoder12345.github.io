网络爬虫

爬虫以种子 URL 为圆心，BFS 向外扩展。每次访问新页面，提取其中的链接，检查 Bloom Filter（已爬过的 URL 对应位全为 1 则跳过），通过 robots.txt 过滤被禁止的路径，剩余链接进入下一轮 Frontier。

核心术语
  • Frontier待爬取的 URL 队列，BFS 每轮从中取出处理，新发现的 URL 加入下一轮。
  • Bloom Filter位数组去重，哈希命中则跳过。亿级 URL 只需 ~1GB 内存，有极低误判率。
  • robots.txt网站声明的爬虫协议，Disallow 路径不可爬取，合规爬虫必须遵守。
  • 礼貌策略对同一域名限制访问频率，避免被对方服务器封禁。

种子 URL 入队

爬虫从种子 URL 开始，BFS 向外扩展发现新页面。

系统组件
URL Frontier：优先级 + 礼貌调度（按域名分桶，限速）
Fetcher：并发下载 HTML，处理重定向、robots.txt
Parser：提取 href/src 链接，URL 规范化（去参数、统一协议）
Dedup：Bloom Filter 快速判断 + 精确 URL 数据库校验
Storage：内容存 HDFS/S3，索引写搜索引擎

Bloom Filter 的工程权衡

  • 10 亿 URL，误判率 0.1%：需要约 1.8GB 内存（位数组）
  • 误判（false positive）：已爬 URL 偶尔被当成新 URL 重爬，代价可接受
  • 漏判（false negative）：不存在，Bloom Filter 不会漏掉新 URL
  • 不可删除：标准 Bloom Filter 不支持删除（可用 Counting Bloom Filter）
  • 实践中：Bloom Filter 做快速初筛，精确 Set（Redis SET / HBase）做最终确认

URL 规范化

  • 统一大小写：HTTP://Example.com → http://example.com
  • 移除 fragment：#section1 不影响服务端内容
  • 移除无关参数：?utm_source=... 通常不影响内容
  • 处理相对路径：../about 相对当前页面解析为绝对 URL
  • 规范化后计算哈希，避免相同内容不同 URL 被重复爬取

分布式爬虫架构

  • URL 按域名哈希分配到不同爬虫节点，保证同一域名由同一节点处理（便于礼貌限速）
  • Consistent Hashing 支持节点增减时最小化 URL 重新分配
  • 中央 Coordinator 管理全局去重（或用分布式 Bloom Filter）
  • 深度和宽度限制：防止陷入无限循环（如分页参数 ?page=1&page=2&...）
  • 爬取深度通常 < 5 层，超出则优先级降低

爬虫陷阱

  • Spider Trap：无限生成 URL（如 /calendar/2024/01/01, /2024/01/02, ...），设置最大爬取深度和 URL 长度限制
  • 重复内容：不同 URL 相同内容（镜像站），用内容哈希（SimHash）检测近似重复
  • 动态内容：JavaScript 渲染的页面需要 Headless Browser（Puppeteer）才能爬取
  • 反爬机制：IP 封禁、CAPTCHA、User-Agent 检测——合规爬虫应遵守 robots.txt 并控制频率
