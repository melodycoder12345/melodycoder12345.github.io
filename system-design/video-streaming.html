视频流媒体

视频上传后，转码服务将其切分为固定长度的分片，每个分片并行转码为多个分辨率（360p/720p/1080p），输出段落按分辨率分行排列到 CDN。播放器通过 ABR 算法实时监测带宽，自动切换合适的分辨率层，保证流畅播放不卡顿。

HLSDASHABR 自适应码率分片转码CDNffmpeg
核心术语
  • 视频分片视频切成 2-10s 小块，播放器按需请求，不等整文件下载。
  • ABR 自适应码率带宽不足时自动降低分辨率，确保播放连续性。
  • HLS / M3U8Playlist 文件描述分片 URL 和多码率选项，基于 HTTP 传输。
  • CDN 边缘缓存分片存 CDN，用户就近拉取，降低源站负载和延迟。

分片长度的权衡

  • 短分片（2s）：ABR 切换更快，延迟低，适合直播；但分片数量多，Playlist 管理复杂
  • 长分片（10s）：HTTP 请求少，CDN 命中率高，适合 VOD；但切换延迟长
  • 典型值：点播 6-10s，低延迟直播 2-3s，超低延迟 HLS（LHLS/LL-DASH）< 1s
  • 分片太短的问题：每个分片都有 HTTP 请求头开销，带宽利用率下降

转码优化

  • 多分辨率并行转码：同一原始分片同时转 360p/720p/1080p，节省总时间
  • 分布式转码：按分片维度分发到多个 Worker，视频时长不影响总时间
  • 关键帧对齐：不同码率的分片在相同时间点切割，确保 ABR 切换无缝
  • 感知质量编码（CRF）：根据画面复杂度动态调整码率，复杂场景更高码率
  • AV1 > H.265 > H.264：更新的编码格式压缩率更好，但转码算力更高

CDN 分发策略

  • 分片上传到 S3/OSS 后，配置 CDN 缓存回源规则
  • 分片内容不变（URL 含 hash/segment 编号），TTL 设为较长（7天+）
  • Playlist（.m3u8）动态变化（直播时追加），TTL 短（1-5s）或不缓存
  • 预热（Cache Warming）：热门视频首次播放前提前推送到边缘节点
  • Range Request：大文件支持断点续传，客户端可只下载部分内容

直播与 VOD 差异

  • VOD（点播）：全量转码后入库，用户随时拉取；可以慢慢转高质量
  • 直播：实时切片，转码后立即推送到 CDN；延迟和质量二选一
  • RTMP → HLS：推流用低延迟的 RTMP，分发用 CDN 友好的 HLS
  • DVR 回看：直播分片持久化存储，用户可以拖动到过去的位置
  • WebRTC：P2P 传输实现真正毫秒级延迟，适合视频会议，不适合大规模分发
