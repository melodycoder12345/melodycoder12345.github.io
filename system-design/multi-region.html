核心概念

RPO（恢复点目标）

故障发生时能容忍丢失多少数据。RPO=0 意味着不允许丢任何数据（需要同步复制）；RPO=5min 意味着允许丢失最近 5 分钟的数据（异步复制可接受）。

RTO（恢复时间目标）

从故障发生到服务恢复的时间。RTO=30s 意味着故障后 30 秒内必须完成切换并恢复服务。RTO 越低，切换机制越复杂，成本越高。

同城双活 vs 异地多活

同城双活：延迟低（1-5ms），同步复制 RPO=0 可行，切换简单。
异地多活：跨区延迟 10-200ms，通常只能异步复制（RPO > 0），需要解决数据一致性问题。

流量调度

GSLB（全局负载均衡）

基于 DNS 或 Anycast 的全局流量调度。根据用户 IP 地理位置、延迟探测、健康检查结果，将用户路由到最近/最健康的 Region。故障时修改 DNS 解析实现流量切换（TTL 影响生效时间）。

DNS TTL 与切换速度：TTL=60s 时，DNS 变更最多需要 60s 才能全部生效。生产环境通常设置 TTL=30-60s，在故障前提前降低 TTL 是容灾演练的重要步骤。
数据一致性挑战

写入冲突处理

异地多活的最大挑战：两个 Region 同时接受写入，同一数据可能被并发修改。常见策略：单 Region 写（牺牲部分可用性）、CRDT（设计可合并的数据结构）、最后写入胜（牺牲一致性）。

简单地「两个 Region 都接受任意写入」会导致不可调和的冲突，必须在架构设计时就确定冲突解决策略。
