召回策略对比
🤝 协同过滤（CF）
基于用户行为矩阵，找相似用户或相似 Item。UserCF 适合社交场景，ItemCF 适合长尾内容。冷启动困难。
🗼 双塔模型（Two-Tower）
用户侧和物品侧各用 DNN 生成 Embedding，用 ANN（如 FAISS）做向量近邻检索。支持实时个性化，工业标配。
🔑 关键词/标签召回
基于用户历史行为提取关键词，在倒排索引中召回相关内容。简单高效，适合冷启动补充。

候选集规模

召回：~10,000 条候选
粗排：过滤到 ~1,000 条
精排：Top ~100 打分
Rerank：最终展示 20-50 条

示例延迟预算：整体链路、ANN 检索和模型推理分别设定可观测的分位数 SLO；具体数值需按产品体验、模型与硬件压测确定。

精排特征

用户特征（年龄/地域/历史行为）+ 物品特征（类别/标签/统计）+ 上下文特征（时间/位置/设备）三方联合建模。

实时性保障

实时特征流

用户行为 → Kafka → Flink 流计算 → 特征实时写入 Redis → 推荐服务实时读取。行为到生效延迟 < 1s。

Embedding 更新

离线全量训练（T+1）+ 在线增量更新（每小时）。Item Embedding 存入向量库，定期刷新 ANN 索引。
